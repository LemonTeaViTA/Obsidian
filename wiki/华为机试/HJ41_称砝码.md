# HJ41 称砝码

## 一、答案

```python
import sys


n = int(sys.stdin.readline())
weights = list(map(int, sys.stdin.readline().split()))
counts = list(map(int, sys.stdin.readline().split()))

# possible 保存目前能够称出的所有重量，0 表示不放砝码
possible = {0}

for weight, count in zip(weights, counts):
    new_possible = set()

    # 当前这种砝码可以放 0 个、1 个、...、count 个
    for old_weight in possible:
        for amount in range(count + 1):
            new_possible.add(old_weight + amount * weight)

    possible = new_possible

print(len(possible))
```

## 二、题目翻译成人话

有几种砝码，每种砝码有自己的重量和数量。

每种砝码不能无限使用，只能使用题目给出的数量。

问：把砝码放在同一侧时，一共能称出多少种不同的总重量。

不放任何砝码也算一种重量，所以重量 `0` 必须计入答案。

## 三、示例分析

输入：

```text
2
1 2
2 1
```

表示：

```text
重量 1 的砝码有 2 个
重量 2 的砝码有 1 个
```

可以放：

```text
0 个砝码              → 0
1 个重量 1 的砝码     → 1
2 个重量 1 的砝码     → 2
1 个重量 2 的砝码     → 2
1 + 2                 → 3
1 + 1 + 2             → 4
```

虽然 `2` 有两种放法，但我们只统计不同的重量，所以最终是：

```text
0、1、2、3、4
```

一共 `5` 种。

## 四、`possible` 集合是什么意思

```python
possible = {0}
```

`possible` 保存目前可以称出的重量。

一开始还没有处理任何砝码，只能称出 `0`：

```text
possible = {0}
```

使用集合 `set` 的原因是：集合会自动去重。

例如两种放法都得到重量 `2`，集合中仍然只保存一个 `2`。

## 五、处理一种砝码

```python
for weight, count in zip(weights, counts):
```

`zip` 会把重量和数量一一配对。

例如：

```python
weights = [1, 2]
counts = [2, 1]
```

配对后相当于：

```text
(1, 2)
(2, 1)
```

表示重量为 `1` 的砝码有 `2` 个，重量为 `2` 的砝码有 `1` 个。

## 六、为什么要创建 `new_possible`

```python
new_possible = set()
```

处理当前这种砝码时，需要根据处理之前的所有重量，生成处理之后的新重量。

如果直接修改 `possible`，同一种砝码可能在同一轮中被重复使用多次，逻辑会混乱。

因此每种砝码单独生成一个新的集合，处理结束后再替换：

```python
possible = new_possible
```

## 七、为什么 `amount` 要从 0 循环到 `count`

```python
for amount in range(count + 1):
```

当前这种砝码可以使用：

```text
0 个、1 个、2 个、……、count 个
```

所以要写 `range(count + 1)`。

例如 `count = 2`：

```python
range(3)  # 0、1、2
```

## 八、重量是如何计算的

```python
new_possible.add(old_weight + amount * weight)
```

其中：

- `old_weight`：之前已经称出的重量；
- `amount`：当前砝码使用的个数；
- `weight`：当前砝码的单个重量。

例如当前有一个旧重量 `1`，使用两个重量为 `2` 的砝码：

```text
1 + 2 × 2 = 5
```

就把 `5` 加入新集合。

## 九、完整执行示例

开始时：

```text
possible = {0}
```

### 处理重量 1、数量 2

当前可以使用 `0、1、2` 个：

```text
0 + 0×1 = 0
0 + 1×1 = 1
0 + 2×1 = 2
```

得到：

```text
possible = {0, 1, 2}
```

### 处理重量 2、数量 1

对之前的每个重量，都可以加 `0` 或 `2`：

```text
0 → 0、2
1 → 1、3
2 → 2、4
```

去重后：

```text
possible = {0, 1, 2, 3, 4}
```

最后：

```python
len(possible) == 5
```

## 十、为什么不直接用列表

当然可以使用列表保存所有结果，但同一个重量可能由多种方式得到。

例如重量 `2` 可以是：

```text
2 个重量 1 的砝码
1 个重量 2 的砝码
```

列表会保存两个 `2`，最后还要额外去重；集合可以自动处理这个问题，更适合本题。

## 十一、复杂度

设当前已经能得到 `S` 种重量，每种砝码最多使用 `x` 个：

- 这一种砝码最多产生 `S × (x + 1)` 次尝试；
- 题目中 `n <= 10`、`x_i <= 10`，所以这种集合动态规划可以轻松通过。

总空间主要用于保存所有可能重量，复杂度与可称出的重量种类数有关。

## 十二、另一种更直观的写法

也可以把每一种砝码逐个拿出来处理：

```python
possible = {0}

for weight, count in zip(weights, counts):
    for _ in range(count):
        possible |= {old_weight + weight for old_weight in list(possible)}
```

不过初学时更推荐上面的 `new_possible` 写法，因为它清楚地表示了：

```text
旧状态 → 新状态
```

## 十三、记忆方式

```text
集合里保存已经能称出的重量
每种砝码尝试使用 0 到数量上限个
旧重量 + 当前砝码重量 × 使用个数
集合自动去重
最后统计集合长度
```
