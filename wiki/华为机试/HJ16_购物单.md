# HJ16 购物单

## 一、答案

```python
import sys


# 普通文本输入即可，避免初学时混淆 buffer
input = sys.stdin.readline

budget, item_count = map(int, input().split())
budget //= 10

# mains[i] 保存第 i 件主件的（缩小后的价格，满意度）
# attachments[i] 保存属于第 i 件主件的附件
mains = [None] * (item_count + 1)
attachments = [[] for _ in range(item_count + 1)]

for item_id in range(1, item_count + 1):
    price, importance, main_id = map(int, input().split())
    satisfaction = price * importance
    price //= 10

    if main_id == 0:
        mains[item_id] = (price, satisfaction)
    else:
        attachments[main_id].append((price, satisfaction))

# dp[money] 表示预算不超过 money 时能够获得的最大满意度
dp = [0] * (budget + 1)

for main_id in range(1, item_count + 1):
    if mains[main_id] is None:
        continue

    main_price, main_value = mains[main_id]

    # 当前主件这一组中所有合法的购买方案
    options = [(main_price, main_value)]

    if len(attachments[main_id]) >= 1:
        first_price, first_value = attachments[main_id][0]
        options.append((
            main_price + first_price,
            main_value + first_value
        ))

    if len(attachments[main_id]) >= 2:
        second_price, second_value = attachments[main_id][1]
        options.append((
            main_price + second_price,
            main_value + second_value
        ))
        options.append((
            main_price + first_price + second_price,
            main_value + first_value + second_value
        ))

    # 每个主件组最多只能选择一种方案，所以预算倒序更新
    for money in range(budget, -1, -1):
        for option_price, option_value in options:
            if money >= option_price:
                dp[money] = max(
                    dp[money],
                    dp[money - option_price] + option_value
                )

print(dp[budget])
```

## 二、先把题目翻译成人话

你有一定预算，想买一些物品。每件物品都有：

```text
价格
重要度
满意度 = 价格 × 重要度
```

物品分为主件和附件：

```text
主件可以单独购买；
附件不能单独购买；
购买附件时，必须同时购买它所属的主件；
一个主件最多有两个附件。
```

目标是在不超过预算的情况下，让所有已购物品的满意度总和最大。

## 三、为什么不能把每件物品独立处理

普通的 `0/1` 背包中，每件物品都可以独立决定买或不买。

但本题中，附件不能独立购买。

例如：

```text
主件：电脑
附件 1：鼠标
附件 2：键盘
```

下面的选择是合法的：

```text
只买电脑；
买电脑和鼠标；
买电脑和键盘；
买电脑、鼠标和键盘。
```

下面的选择不合法：

```text
只买鼠标；
只买键盘；
买鼠标和键盘但不买电脑。
```

所以不能把主件、鼠标、键盘作为三件完全独立的物品放进背包。

## 四、把主件和附件看成一个组

一个主件最多有两个附件，因此每个主件组最多只有四种合法购买方案。

假设：

```text
主件价格为 M，满意度为 MV；
附件 1 价格为 A1，满意度为 A1V；
附件 2 价格为 A2，满意度为 A2V。
```

合法方案是：

| 方案            | 总价格          | 总满意度           |
| --------------- | --------------- | ------------------ |
| 只买主件        | `M`           | `MV`             |
| 主件 + 附件 1   | `M + A1`      | `MV + A1V`       |
| 主件 + 附件 2   | `M + A2`      | `MV + A2V`       |
| 主件 + 两个附件 | `M + A1 + A2` | `MV + A1V + A2V` |

处理这个组时，可以：

```text
整组不买；
或者选择四种合法方案中的一种。
```

这类问题叫做“分组背包”。

## 五、动态规划状态是什么意思

```python
dp[money]
```

表示：

```text
处理完目前这些主件组后，
预算不超过 money 时，
能够获得的最大满意度。
```

例如：

```python
dp[100]
```

表示预算不超过缩小后的 `100` 时，当前能够获得的最大满意度。

开始时还没有处理任何物品，所以：

```python
dp = [0] * (budget + 1)
```

所有预算下的最大满意度都是 `0`。

## 六、为什么价格可以除以 10

题目保证所有物品价格都是 `10` 的倍数。

例如：

```text
预算：1000
物品价格：200、300、400
```

全部除以 `10` 后：

```text
预算：100
物品价格：20、30、40
```

能够购买的组合完全没有变化，但动态规划数组长度从 `1001` 缩小到 `101`。

代码中：

```python
budget //= 10
price //= 10
```

只缩小了用于比较预算的价格。

满意度仍然使用原价格计算：

```python
satisfaction = price * importance
```

注意这行必须放在 `price //= 10` 之前，否则满意度也会被错误缩小十倍。

## 七、如何保存主件和附件

```python
mains = [None] * (item_count + 1)
attachments = [[] for _ in range(item_count + 1)]
```

物品编号从 `1` 开始，所以数组长度使用 `item_count + 1`，下标 `0` 不使用。

```python
mains[i]
```

保存编号为 `i` 的主件。

```python
attachments[i]
```

保存属于编号为 `i` 的主件的所有附件。

读取物品时：

```python
if main_id == 0:
    mains[item_id] = (price, satisfaction)
else:
    attachments[main_id].append((price, satisfaction))
```

其中：

```text
main_id == 0：当前物品是主件；
main_id != 0：当前物品是附件，main_id 是所属主件编号。
```

## 八、如何生成合法购买方案

每个主件至少可以单独购买：

```python
options = [(main_price, main_value)]
```

如果有第一个附件，加入“主件 + 附件 1”：

```python
options.append((
    main_price + first_price,
    main_value + first_value
))
```

如果有第二个附件，再加入：

```text
主件 + 附件 2；
主件 + 附件 1 + 附件 2。
```

代码从来不会生成“只买附件”的方案，所以自然满足附件必须跟随主件的规则。

## 九、动态规划如何更新

```python
for money in range(budget, -1, -1):
    for option_price, option_value in options:
        if money >= option_price:
            dp[money] = max(
                dp[money],
                dp[money - option_price] + option_value
            )
```

对于当前主件组的每一种合法方案，都比较：

```text
不买当前方案时的满意度：dp[money]

购买当前方案后的满意度：
dp[money - option_price] + option_value
```

取较大的值。

例如当前预算是 `100`，某个方案价格是 `30`，满意度是 `120`：

```text
先查看预算 70 时已有的最大满意度；
再加上当前方案的满意度 120；
与原来的 dp[100] 比较。
```

公式是：

```python
dp[100] = max(dp[100], dp[70] + 120)
```

## 十、为什么预算必须倒序更新

```python
for money in range(budget, -1, -1):
```

每个主件组最多只能选择一种方案。

如果预算从小到大更新，刚刚使用当前主件组得到的新状态，可能又被后面的预算读取，相当于重复购买同一个主件组。

倒序更新时：

```text
较大的预算先处理；
它读取的较小预算位置还没有被当前主件组修改；
所以当前主件组不会被重复购买。
```

这和普通 `0/1` 背包中物品只能选择一次时倒序更新的原因相同。

## 十一、一个小例子

假设预算为 `1000`，某个主件组是：

```text
主件：价格 500，重要度 3，满意度 1500
附件 1：价格 200，重要度 2，满意度 400
附件 2：价格 300，重要度 4，满意度 1200
```

这个组有四种购买方案：

| 方案            | 价格 | 满意度 |
| --------------- | ---: | -----: |
| 只买主件        |  500 |   1500 |
| 主件 + 附件 1   |  700 |   1900 |
| 主件 + 附件 2   |  800 |   2700 |
| 主件 + 两个附件 | 1000 |   3100 |

预算正好是 `1000` 时，这一组中最好的方案是第四种，满意度为 `3100`。

如果还有其他主件组，动态规划会继续比较：

```text
把钱全部花在这一组；
购买这一组的一部分方案，再用剩余预算购买其他组；
不购买这一组，把预算留给其他组。
```

最终留下全局最大满意度。

## 十二、为什么附件可能先读到也没有问题

输入中的 `q` 直接给出了附件所属的主件编号。

代码读取附件时直接执行：

```python
attachments[main_id].append(...)
```

它不要求主件已经读取完成。

所有物品读取完以后，才开始生成各个主件组的购买方案，因此即使附件在输入中出现在主件之前，也可以正确归组。

## 十三、和普通 0/1 背包的区别

普通 `0/1` 背包：

```text
每件物品独立决定买或不买。
```

本题的分组背包：

```text
每个主件和它的附件组成一组；
一个组中只能选择一种合法组合；
附件不能脱离主件出现。
```

可以记成：

```text
先将依赖关系变成合法组合，
再把每组合法组合放进背包。
```

## 十四、复杂度

设缩小后的预算为 `B = n / 10`，主件组数量为 `g`。

每个主件组最多有 `4` 种方案：

- 时间复杂度：`O(g × B × 4)`，可以简写为 `O(g × B)`；
- 空间复杂度：`O(B)`。

题目中：

```text
B 最大约为 3000；
物品总数最多为 60。
```

因此可以在限制内完成。

## 十五、记忆方式

```text
主件和附件先归成一组；
每组最多四种合法方案；
dp[money] 记录预算内最大满意度；
按组处理，预算倒序更新；
价格除以 10，满意度仍用原价格计算。
```

## 十六、从零开始理解：把商品看成套餐

这题最容易混淆的地方是附件不能单独购买。假设有一个主件、附件1、附件2，那么合法选择只有：不买这个组、只买主件、主件加附件1、主件加附件2、主件加两个附件。

因此不能把附件当成独立商品，而要先把一个主件和它的附件组成一个小组。每个小组最多有 4 种合法购买方案。

## 十七、dp[money] 到底表示什么

`dp[money]` 表示：处理完之前的主件组后，在预算不超过 `money` 的情况下，能够得到的最大满意度。

处理当前小组的某个套餐时，有两种选择：

```text
不选当前套餐：保留原来的 dp[money]
选择当前套餐：dp[money - 套餐价格] + 套餐满意度
```

所以更新为两者的较大值：

```text
dp[money] = max(dp[money], dp[money - option_price] + option_value)
```

## 十八、用一个小组举例

假设：

```text
主件：价格10，满意度30
附件1：价格5，满意度20
附件2：价格8，满意度16
```

合法套餐为：

```text
只买主件：价格10，满意度30
主件+附件1：价格15，满意度50
主件+附件2：价格18，满意度46
主件+附件1+附件2：价格23，满意度66
```

程序会把这 4 种套餐逐个和已有的 `dp` 比较，但同一个小组只能选其中一种。

## 十九、为什么预算要倒序

```python
for money in range(budget, -1, -1):
```

如果预算从小到大更新，当前小组刚更新出的结果可能又被当前小组读取，相当于同一个主件组买了两次。

从大到小更新时，读取的较小预算状态还是处理当前小组之前的旧结果，所以一个主件组最多只会被选择一次。这和普通 0/1 背包倒序更新的原因一样。

## 二十、样例1的主件5小组

主件5的价格是10、满意度是10；两个附件的价格都是20、满意度都是60。

该小组的方案：

```text
只买主件5：价格10，满意度10
主件5+附件1：价格30，满意度70
主件5+附件2：价格30，满意度70
主件5+两个附件：价格50，满意度130
```

预算正好是50时，选择最后一种方案，购买物品1、2、5，满意度为：

```text
20×3 + 20×3 + 10×1 = 130
```

## 二十一、整道题的解题流程

```text
读取预算和所有物品
计算每件物品的满意度
把附件放到对应主件下面
为每个主件列出合法套餐
把套餐放入分组背包
预算倒序更新 dp
输出 dp[预算]
```

## 二十二、最后记住

```text
先处理购买依赖，再做背包。
主件和附件是一个组，不是多件独立物品。
每个组最多选一种套餐。
dp[money] 是当前预算下的最大满意度。
预算倒序，防止同一组被重复购买。
```

## 十八、为什么不能把附件单独放进 `dp`

如果把物品 1、2、5 分别作为独立物品处理，程序可能选择：

```text
只买物品1和物品2，不买物品5
```

这在普通背包里是允许的，但在本题中不合法，因为附件 1、2 都属于主件 5，必须先买主件 5。

把它们合成一个组后，程序只能从合法方案中选择，就不会产生这种错误。

## 十九、预算倒序到底防止了什么

处理某个主件组时：

```python
for money in range(budget, -1, -1):
```

如果从小到大更新，可能出现这种错误：

```text
先用当前主件组更新 dp[30]
再用刚更新的 dp[30] 更新 dp[60]
```

这样相当于同一个主件组被买了两次。

从大到小更新时，当前组需要读取的较小预算位置还没有被当前组修改，因此每个主件组最多使用一次。
