# CC 怎么抓网页（WebFetch）

> **一句话定位**：CC 抓网页**不是把网页原文塞给你**，而是抓回来后**先用一个便宜的小模型，按你的问题把它浓缩成相关结论**，主模型只看到这份干净的浓缩。这是 token 经济学在"网页"这个场景的又一次体现。

---

---

## 零、参数与输出（Schema）

**输入参数**：

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `url` | string（URL） | ✅ | 目标网页地址，http 自动升级为 https |
| `prompt` | string | ✅ | 告诉小模型「你想从这页里提取什么信息」，如 "这个 API 的使用方法是什么"；**这是工具的核心入参**，驱动 AI 摘要 |

> **prompt 参数的设计意义**：WebFetch 不是「把网页塞给主模型」而是「让小模型帮你从网页里提炼答案」。prompt 就是你的问题，小模型拿着这个问题从网页正文里挑相关的来回答——所以 prompt 越具体，返回结果越准确。模糊问题（如"把这页概括一下"）会得到泛泛摘要，具体问题（如"这个函数的返回类型是什么"）才能得到精准片段。

**输出字段**（模型看到的工具结果）：

| 字段 | 含义 |
|---|---|
| `url` | 实际抓取的 URL（可能经过重定向） |
| `result` | 小模型生成的摘要/回答文本（这是主要内容） |
| `bytes` | 抓取的原始字节数 |
| `code` | HTTP 响应码（200/404/等） |
| `durationMs` | 抓取+摘要总耗时（毫秒） |

> **重定向时的输出**：跨域重定向时，`result` 字段不是摘要，而是一段「REDIRECT DETECTED」说明文本，告诉模型「原 URL 要跳到 XX，请用新地址再调一次 WebFetch」。这是安全设计——防跨域被钓鱼。

## 一、先记一张地图

| 环节 | 在做什么 | 关键点 |
|---|---|---|
| **① 抓 + 转** | 把网页抓回来、HTML 转成干净的 markdown | 自动把 http 升级成 https |
| **② AI 摘要（灵魂）** | 用小模型按"你想知道什么"把正文浓缩 | 主模型只看浓缩结果，不吞整页噪音 |
| **③ 缓存** | 15 分钟内重复抓同一页直接命中 | 省重复抓取 |
| **④ 安全** | 跨域重定向不自动跟、拒私有/认证 URL | 防被骗到恶意域、防泄漏 |

最值钱的是 ②，先讲它。

---

## 二、② AI 摘要：这个工具的灵魂

调用抓网页时，**必须同时给一个"你想从这页里知道什么"的问题**。流程是：

> 抓回网页 → HTML 转成 markdown → 把这份 markdown **连同你的问题，一起喂给一个便宜的小模型** → 小模型按你的问题把内容**浓缩成相关结论** → 返回的是**这份浓缩**，不是网页原文。

工具的自我介绍第一句就是"抓取内容**并用一个 AI 模型处理它**"——可见摘要不是附加功能，是它的核心定位。

**为什么要这样？还是 token 经济学**。一个网页正文动辄几万字，而且**大量是导航栏、页脚、广告、推荐位这些噪音**。如果把原文整个塞进主对话：

- 既占用大量 token（还会逐轮重发），
- 又可能**正好把你要的那一句埋在噪音里、或者截断时丢掉**。

所以 CC 用一个**便宜的小模型当"过滤器"**：让它读完整页、按你的问题把相关的东西拎出来，主模型只接这份干净浓缩。脏活（读长网页、去噪）交给便宜模型，贵的主模型只看结论。

> 这和[子 agent](03-Agent-子agent工具)是**同一个思想**：把"读一大堆原始材料、提炼出结论"这种脏活下放出去，主模型只接干净的结论，不被原始材料淹没。区别只是 web_fetch 下放给"一个小模型一次调用"，子 agent 下放给"一个独立 agent 多轮检索"。

摘要时给小模型的指令里还带有**版权护栏**（比如引用原文不能超过一定长度、不复现歌词等）。

**一个例外**：如果抓的是那种**本来就干净的官方文档站**（内容本身就是 markdown、又不太长），CC 会**直接返回原文、跳过摘要**——因为这种页面没什么噪音可去，浓缩反而可能丢细节。

## 三、① 抓取与转换

- **HTTP 自动升级成 HTTPS**：给个 http 链接，CC 自动改成 https 再抓，更安全。
- **HTML 转 markdown**：抓回来的网页会被转成干净的 markdown，去掉一堆标签噪音，再交给摘要。
- **有体积和超时上限**：URL 长度、抓取内容大小、抓取超时都有上限，防止一个巨大的页面或慢得要死的服务器拖垮工具。
- **二进制（比如 PDF）**：会落盘存一份，同时仍然尝试把它解出文字来交给小模型摘要（PDF 里有足够的文字结构能让小模型概括）。

---

## 四、③ 缓存：重复抓同一页直接命中

CC 给抓取结果配了一个**15 分钟的缓存**：15 分钟内再抓同一个 URL，直接返回上次的结果，不重新抓。这省的是"模型在一个任务里反复要看同一个页面"的重复抓取开销。还有一个独立的小缓存，用来避免对同一个域名反复做安全预检。

---

## 五、④ 安全：跨域重定向不自动跟

这是 CC 一个体现安全哲学的设计。

**问题**：网页重定向很常见。但"自动跟随重定向"有个安全风险——攻击者可以利用一个**你信任的域名上的开放重定向漏洞**，把你的请求**偷偷导向一个恶意域名**。

**CC 的做法**：
- 如果重定向是**跳到同一个域名**（或只是加减个 `www.`），那是安全的，**自动跟**。
- 如果重定向**跳到了一个不同的域名**，CC **不自动跟**——而是**把"这个页面想把你重定向到 XXX"这件事告诉模型，让模型自己决定要不要再发一次请求去抓那个新地址**。

这正是 CC 反复出现的安全哲学：**默认保守 + 把决定权交还**。跨域这种有风险的事，不替你做主，而是告诉你、让你（模型/用户）来定。

其他安全点：
- **拒绝带用户名密码的 URL**、**拒绝抓非公网能解析的地址**（防止被诱导去探测内网）。
- **每个域名要批准**：抓某个域名前要经过权限确认（信任的域名可预先放行）。
- prompt 里有一条**硬警告**：认证/私有的链接（公司内网文档、需要登录的服务）**抓不到**，遇到这种应该改用专门的、带认证的工具；GitHub 上的东西优先用 `gh` 命令行。

---

## 六、核心 takeaway

1. **抓网页 = 抓回来 + 小模型按需浓缩**，主模型只看浓缩结果——不是把原文塞给你。
2. **这是 token 经济学的又一面**：网页正文充满噪音，用便宜小模型当过滤器，比把原文整个塞进昂贵主对话划算得多。
3. **脏活下放、主模型接结论**——和子 agent 同一思想，只是下放的对象不同（一次小模型调用 vs 一个多轮子 agent）。
4. **跨域重定向不自动跟**：默认保守、把决定权交还给模型/用户，这是 CC 一以贯之的安全哲学。
