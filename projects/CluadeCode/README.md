# Claude Code 学习地图

> 这是理解 Claude Code 内部机制的知识索引。每篇聚焦一个主题，用**纯白话 + 地图式结构**讲透"CC 这里怎么做的"。

---

## 学习主线：一条贯穿全局的经济学

开始之前，记住这条贯穿 CC 几乎所有设计的主线：

> **工具返回的内容会进对话历史，而对话历史按 token 计费、逐轮重发。所以"读进来一段没用的"不是只浪费一次，是按剩余轮数倍增地浪费。**

理解了这条，下面所有"为什么要截断 / 为什么抛错不给内容 / 为什么用小模型先浓缩"就全顺了。

## 二、工具详解（理解 token 经济学的各种招式）

读完核心机制，再看具体工具——会发现每个工具都在用自己的方式回答"怎么不让没用的东西卡进昂贵的上下文"。

### 文件三件套

| 工具 | 核心要点 | 篇目 |
|---|---|---|
| **读文件** | 大文件抛错而不截断、重复读回桩不重发、读取台账是三件套的粘合剂 | [[01-FileRead-读文件]] |
| **写文件** | 写前三道闸（没读过/读后被改/临门再查），写比编辑更需要把关（没有 old_string 安全网） | [[06-FileWrite-写文件]] |

### 搜索与检索

| 工具 | 核心要点 | 篇目 |
|---|---|---|
| **Grep / Glob** | 三件套（Grep 找内容 / Glob 找文件名 / 子 agent 管开放式），同样有硬上限 + 分页，超时要和"无匹配"分开 | [[02-Grep-Glob-搜索工具]] |
| **子 agent** | 把开放式检索整包下放，只回传结论不回传过程——几十个文件的翻找垃圾全被挡在主对话之外 | [[03-Agent-子agent工具]] |

### 命令与网页

| 工具 | 核心要点 | 篇目 |
|---|---|---|
| **Bash** | 后台执行是灵魂（主对话不被一条命令劫持），截断保尾不保头，复合命令必须拆开匹配权限 | [[04-Bash-执行命令工具]] |
| **WebFetch** | 抓网页 = 抓回来 + 小模型按需浓缩，主模型只看浓缩结果——和子 agent 同一思想（脏活下放、只接结论） | [[07-WebFetch-网页抓取]] |

### 其他

| 工具 | 核心要点 | 篇目 |
|---|---|---|
| **TodoWrite** | 模型给自己管的草稿板（不是执行引擎），记"要做啥、做到哪了"，主要给自己看 | [[05-TodoWrite-vs-plan-DAG]] |
| **MCP 按需加载** | 接太多 MCP 工具时，平时只露名字，用时再展开——token 经济学做到了"工具定义"这一层 | [[08-MCP-延迟加载-ToolSearch]] |

## 三、几条贯穿的设计哲学

读完上面这些，会发现 CC 的设计反复出现同一些思路：

1. **扣留 + 偷偷救**：出错先别急着告诉用户，CC 在背后试着自救；救成了你无感，救不成才亮错。
2. **逐级升级、每级只试一次**：处理太长（排水→压缩→放弃）、处理截断（扩容→续写→放弃）都是先用最便宜的、不行再换更狠的，**每招只试一次**——绝不无限重试同一招。
3. **脏活下放、主模型接结论**：网页摘要（下放给小模型一次调用）、子 agent（下放给独立 agent 多轮检索）——都是"原始材料不进主对话、只让结论进"。
4. **守住格式底线**：工具调用必须配对结果，否则对话彻底卡死。无论怎么出错、中断，都要保证配对完整。
5. **处处防死亡螺旋**：在每个可能"越救越糟"的地方，都设"试过就不再试"或"这种情况直接退出"的硬闸。

## 使用建议

**入门路径**（建立整体认知）：
1. 先读 [[09-核心引擎-主循环与工具契约]] + [[CC-健壮性外壳]]，理解"骨架 + 外壳"。
2. 挑 1-2 个你最关心的工具细读（比如读文件、执行命令），体会 token 经济学怎么落地。
3. 读子 agent 或网页摘要，理解"脏活下放"思想。

**深入路径**（理解每个设计细节的动机）：
- 按上面"工具详解"的顺序逐篇读，每篇都有地图 + 关键细节。
- 读的时候记住那条主线——"别让没用的东西卡进昂贵的、逐轮重发的上下文"，所有设计都在回答这个。
