## 四、实际数据流

### 4.1 任务初始化流程

```
1. 用户发起任务 (POST /task/perform)
   ↓
2. main.py: init_task_project()
   - 克隆代码
   - 初始化OpenSpec
   - 创建TaskMetadata对象
   ↓
3. MetaContainer.report_task()
   - save_or_update(TASK_METADATA)  → 保存任务元数据
   - save_or_update(TASK_VERSION)   → 保存版本号
   ↓
4. 数据写入 AI24 管理平台数据服务
   ↓
5. 其他机器可以通过 get_data_content() 读取
```

### 4.2 多轮对话流程

```
第一次查询:
1. 用户发送查询 (task_id="task_123", input="...")
   ↓
2. ClaudeAgentSDKService.query()
   - 创建新session: session_id="sess_abc"
   ↓
3. TaskSessionMapper.set_mapping()
   - save_or_update(SESSION_MAPPING)  → task_123 → sess_abc
   - save_or_update(SESSION_CONFIG)   → sess_abc → task_123
   ↓
4. 数据存储到云端

第二次查询:
1. 用户发送查询 (task_id="task_123", input="...")
   ↓
2. TaskSessionMapper.get_session_by_task("task_123")
   - get_data_content(SESSION_MAPPING) → 返回 "sess_abc"
   ↓
3. ClaudeAgentSDKService.query(session_id="sess_abc")
   - 复用之前的会话，实现多轮对话
```

### 4.3 任务中断与恢复流程

```
中断阶段:
1. 进程收到 SIGTERM 信号
   ↓
2. TaskRecoveryManager.save_interrupted_task()
   - save_or_update(INTERRUPTED_TASKS)
   ↓
3. 数据存储到云端
   ↓
4. 进程退出

恢复阶段:
1. 重新启动进程
   ↓
2. TaskRecoveryManager.list_interrupted_tasks()
   - list_by_type(INTERRUPTED_TASKS) → 查询所有中断任务
   ↓
3. 提示用户选择恢复
   ↓
4. 用户确认后，继续执行任务
   ↓
5. 任务完成后，delete(INTERRUPTED_TASKS)
```

## 五、内存缓存机制

所有使用云存储的模块都实现了**两级缓存**：

### 5.1 MetaContainer的缓存

```python
class MetaContainer:
    def __init__(self):
        self._metadata: Dict[str, TaskMetadata] = {}  # 内存缓存
    
    def get(self, task_id: str):
        # 1. 先查内存缓存
        if task_id in self._metadata:
            return self._metadata[task_id]
        
        # 2. 再查云端
        metadata_dict = get_data_content(task_id, TaskDataType.TASK_METADATA)
        if metadata_dict:
            metadata = TaskMetadata.from_dict(metadata_dict)
            self._metadata[task_id] = metadata  # 缓存到内存
            return metadata
        
        return None
```

### 5.2 TaskSessionMapper的缓存

```python
class TaskSessionMapper:
    _task_to_session_cache: Dict[str, str] = {}
    _session_to_task_cache: Dict[str, str] = {}
    
    @classmethod
    def get_session_by_task(cls, task_id: str):
        # 1. 先查内存缓存
        if task_id in cls._task_to_session_cache:
            return cls._task_to_session_cache[task_id]
        
        # 2. 再查云端
        session_id = get_data_content(task_id, TaskDataType.SESSION_MAPPING)
        if session_id:
            cls._task_to_session_cache[task_id] = session_id
        
        return session_id
```

### 5.3 缓存策略总结

```
读取流程:
内存缓存 → 命中 → 直接返回（最快）
         ↓ 未命中
      云端查询 → 命中 → 写入内存缓存 → 返回
              ↓ 未命中
            返回None

写入流程:
数据 → 写入内存缓存
    ↓
    写入云端（异步，保证持久化）
```

**优点：**
- ✅ 减少HTTP请求，提升性能
- ✅ 降低延迟（内存访问 < 1ms，云端查询 ~ 100ms）
- ✅ 减轻云端服务压力

**注意事项：**
- ⚠️ 多机环境下，缓存可能不同步
- ⚠️ 需要明确缓存失效策略

## 七、最佳实践（基于实际使用）

### 7.1 读取数据时先查缓存

```python
# ✅ 推荐：先查内存缓存，再查云端
def get_metadata(task_id: str):
    if task_id in memory_cache:
        return memory_cache[task_id]
    
    data = get_data_content(task_id, TaskDataType.TASK_METADATA)
    if data:
        memory_cache[task_id] = data
    return data

# ❌ 不推荐：每次都查云端
def get_metadata(task_id: str):
    return get_data_content(task_id, TaskDataType.TASK_METADATA)
```

### 7.2 写入数据时同步更新缓存

```python
# ✅ 推荐：同时更新内存和云端
def save_metadata(task_id: str, data: dict):
    memory_cache[task_id] = data
    save_or_update(task_id, TaskDataType.TASK_METADATA, data)

# ❌ 不推荐：只更新云端，不更新缓存
def save_metadata(task_id: str, data: dict):
    save_or_update(task_id, TaskDataType.TASK_METADATA, data)
```

### 7.3 异常处理

```python
# ✅ 推荐：云端查询失败时降级到内存缓存
def get_metadata(task_id: str):
    if task_id in memory_cache:
        return memory_cache[task_id]
    
    try:
        data = get_data_content(task_id, TaskDataType.TASK_METADATA)
        if data:
            memory_cache[task_id] = data
            return data
    except Exception as e:
        logger.error(f"云端查询失败: {e}")
        # 降级：返回内存中的旧数据（如果有）
        return memory_cache.get(task_id)
    
    return None
```

## 八、总结

### 核心发现

1. **StepPlanner未实际使用**
   - 代码完整但MCP服务被注释
   - 云存储代码存在但未被调用
   
2. **真正使用云存储的模块（5个）**
   - MetaContainer（任务元数据）⭐⭐⭐
   - TaskSessionMapper（会话映射）⭐⭐⭐
   - StopWatch（时间追踪）⭐⭐
   - TaskRecoveryManager（中断恢复）⭐⭐
   - OSSProxy/ContextExportService（文件地址）⭐

3. **都使用了两级缓存**
   - 内存缓存（快速访问）
   - 云端存储（持久化、多机共享）

4. **多机共享的关键数据**
   - TASK_METADATA - 机器B需要知道机器A初始化的任务信息
   - SESSION_MAPPING - 保证任务可以在任意机器上继续对话
   - TASK_VERSION - 检测数据版本，防止脏读

### 数据重要性排序

1. **TASK_METADATA** - 最核心，没有它任务无法执行
2. **SESSION_MAPPING** - 多轮对话必需
3. **TASK_VERSION** - 多机环境下数据一致性保证
4. **STOPWATCH** - 性能监控和分析
5. **INTERRUPTED_TASKS** - 容错和恢复能力

这才是code-agent**真正的云存储使用情况**！
