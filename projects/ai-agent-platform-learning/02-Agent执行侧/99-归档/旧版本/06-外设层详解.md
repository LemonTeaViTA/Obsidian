> 对应 [03-启动流程走读.md](./03-启动流程走读.md) 分层时序图里的 **外设层**。
> 外设层 = 初始化外部服务（COS 云存储、Langfuse LLM 追踪），为后续的数据备份和监控打好基础。
> 入口：[main.py:3814-3817](../main.py#L3814-L3817)

## 二、为什么需要外设层？

### 问题场景

```
场景1：任务元数据需要持久化
  - MetaContainer 保存任务信息到本地 tmp/data/task_metadata.json
  - 但本地磁盘可能损坏、机器可能重装
  - 需要云端备份 → 使用 COS 对象存储

场景2：需要监控 Claude API 的使用情况
  - 每次调用花费多少 token？
  - 哪个任务最耗时？
  - 是否有异常调用？
  - 需要追踪和监控 → 使用 Langfuse
```

## 三、COS 配置 — init_coscmd_config()

### 3.1 什么是 COS？

**COS = 腾讯云对象存储（Cloud Object Storage）**

类似于：
- AWS S3
- 阿里云 OSS
- 七牛云存储

**在 code-agent 中的作用**：
- 备份任务元数据（`task_metadata.json`）
- 备份 `.claude` 目录（会话历史）
- 分环境隔离：`/code-agent/daily`、`/code-agent/pre`、`/code-agent/prod`

### 3.2 代码位置

[main.py:2893-2920](../main.py#L2893-L2920)

### 3.3 完整代码走读

```python
def init_coscmd_config():
    """
    初始化腾讯云 COS 命令行工具配置

    该方法会在服务启动时调用，将项目内的 config/.cos.conf 复制到 ~/.cos.conf。
    coscmd 工具运行时会从 ~/.cos.conf 读取访问密钥和存储桶信息。

    之所以不通过 `coscmd config` 子命令来配置：该子命令本质上只是往 ~/.cos.conf
    写一个本地 INI 文件，不涉及网络请求。但每次调用都要冷启动一个新的 Python 解释器
    并 import coscmd/qcloud_cos/requests 等大量依赖，在磁盘慢或依赖未缓存的机器上很容易
    超过超时时间。直接复制配置文件可彻底绕开子进程启动开销，更快也更稳定。

    - 如果目标文件已存在，会被覆盖
    - 配置失败不会影响服务启动，但会记录警告日志

    Returns:
        bool: 配置成功返回 True，否则返回 False
    """
    logger.info("正在配置 coscmd (腾讯云 COS)...")
    try:
        # 获取 main.py 所在的目录
        current_dir = os.path.dirname(os.path.abspath(__file__))
        source_cos_conf = os.path.join(current_dir, 'config', '.cos.conf')
        target_cos_conf = os.path.join(Path.home(), '.cos.conf')

        if not os.path.exists(source_cos_conf):
            logger.warning(f"源 .cos.conf 文件不存在: {source_cos_conf}")
            return False

        # 直接复制配置文件（比调用 coscmd config 快很多）
        shutil.copy2(source_cos_conf, target_cos_conf)
        logger.info(f"coscmd 配置已复制: {source_cos_conf} -> {target_cos_conf}")
        return True

    except Exception as e:
        logger.error(f"配置 coscmd 失败: {str(e)}", exc_info=True)
        return False
```

### 3.4 为什么直接复制而不用 `coscmd config`？

注释说得很清楚：

**`coscmd config` 的问题**：
```python
# 执行 coscmd config 相当于：
subprocess.run(['coscmd', 'config', '-a', secret_id, '-s', secret_key, ...])

# 这会：
# 1. 冷启动一个新的 Python 解释器
# 2. import coscmd 及其依赖（qcloud_cos, requests, ...）
# 3. 执行配置逻辑（其实就是写 INI 文件）
# 4. 退出进程

# 在慢磁盘或依赖未缓存的机器上，可能超时
```

**直接复制的优势**：
```python
# 绕开子进程启动开销
shutil.copy2(source, target)

# 更快（毫秒级 vs 秒级）
# 更稳定（不依赖外部命令）
```

### 3.5 .cos.conf 文件格式

```ini
[common]
secret_id = AKIDxxxxxxxxxxxxxxxxxxxxxx
secret_key = xxxxxxxxxxxxxxxxxxxxxxxxxx
bucket = code-agent-backup-1234567890
region = ap-guangzhou
max_thread = 5
part_size = 10
schema = https
```

**配置项说明**：
- `secret_id` / `secret_key`：腾讯云访问密钥
- `bucket`：存储桶名称
- `region`：存储桶所在地域
- `max_thread`：上传下载的最大并发数
- `part_size`：分片上传的大小（MB）

### 3.6 COS 在项目中的使用

**使用位置**：`meta_container.py`

```python
# 上传任务元数据到云端
def upload_to_cloud(task_id):
    local_file = f"tmp/data/task_metadata.json"
    remote_path = f"{COS_PATH_PREFIX}/{task_id}/task_metadata.json"
    
    # 调用 coscmd 命令（读取 ~/.cos.conf）
    subprocess.run(['coscmd', 'upload', local_file, remote_path])
```

**云端路径结构**：
```

  │   ├── task_metadata.json
  │   └── .claude/
  │       └── projects/
  ├── task_12346/
  └── ...
```

## 四、Langfuse 初始化 — init_langfuse()

### 4.1 什么是 Langfuse？

**Langfuse = LLM 应用的可观测性平台**

功能：
- **追踪 LLM 调用**：记录每次 API 请求/响应
- **Token 统计**：输入/输出 token 数量、成本
- **性能监控**：延迟、错误率
- **对话历史**：完整的会话记录
- **评估和调试**：标注、回放、分析

类似工具：
- LangSmith（LangChain 官方）
- Helicone
- Weights & Biases

### 4.2 代码位置

[main.py:2871-2890](../main.py#L2871-L2890)

### 4.3 完整代码走读

```python
def init_langfuse():
    """
    初始化 langfuse
    """
    try:
        from langfuse import get_client

        # 1. 获取 Langfuse 客户端（自动读取环境变量）
        langfuse = get_client()

        # 2. 验证连接
        if langfuse.auth_check():
            print("Langfuse client is authenticated and ready!")
        else:
            print("Authentication failed. Please check your credentials and host.")

        # 3. 配置 Claude Agent SDK 的 OpenTelemetry 追踪
        from langsmith.integrations.claude_agent_sdk import configure_claude_agent_sdk
        configure_claude_agent_sdk()
        
    except Exception as e:
        logger.error(f"初始化 langfuse 失败: {str(e)}", exc_info=True)
```

### 4.4 配置来源

Langfuse 客户端从环境变量读取配置（由 [04-环境层详解.md](./04-环境层详解.md) 的 `apply_env_config()` 设置）：

```python

"LANGFUSE_PUBLIC_KEY": "pk-lf-f1fb700d-30c0-492e-afff-c8ac09c12728"
"LANGFUSE_SECRET_KEY": "sk-lf-d36645f2-218d-464c-9c85-7b58dc23fd47"
"LANGFUSE_BASE_URL": "http://langfuse.daily.vdian.net"
```

**三环境配置**：
- daily：`langfuse.daily.vdian.net`
- pre/prod：`langfuse.vdian.net`

### 4.5 OpenTelemetry 集成

```python
from langsmith.integrations.claude_agent_sdk import configure_claude_agent_sdk
configure_claude_agent_sdk()
```

**作用**：
- 自动在 Claude Agent SDK 中注入 OpenTelemetry instrumentation
- 无需修改业务代码，自动追踪所有 `service.query()` 调用
- 数据自动上报到 Langfuse

**追踪内容**：
```json
{
  "trace_id": "trace_abc123",
  "span_id": "span_def456",
  "name": "claude.query",
  "start_time": "2026-07-07T10:30:00Z",
  "end_time": "2026-07-07T10:30:15Z",
  "attributes": {
    "task_id": "task_12345",
    "model": "claude-opus-4",
    "input_tokens": 1500,
    "output_tokens": 800,
    "cost_usd": 0.025
  }
}
```

## 五、外设层的执行顺序

### 代码位置
[main.py:3814-3817](../main.py#L3814-L3817)

```python
# 配置 coscmd (腾讯云 COS)
init_coscmd_config()

# 初始化 langfuse
init_langfuse()
```

### 为什么 COS 在前，Langfuse 在后？

**没有强依赖关系**，顺序可以交换。

当前顺序的考虑：
1. **COS 更基础**：后续很多模块可能需要云端备份
2. **Langfuse 更轻**：即使失败也不影响主流程

**都不是阻塞的**：
- 两者初始化失败都只记录警告日志
- 不会 `sys.exit(1)` 退出服务
- 服务可以在没有 COS 或 Langfuse 的情况下运行

## 六、外设层的错误处理

### COS 配置失败

```python
if not os.path.exists(source_cos_conf):
    logger.warning(f"源 .cos.conf 文件不存在: {source_cos_conf}")
    return False
```

**影响**：
- MetaContainer 无法上传元数据到云端
- 只能本地保存
- 机器重装会丢失数据

**不影响**：
- 服务启动
- 任务执行
- 本地功能

### Langfuse 初始化失败

```python
except Exception as e:
    logger.error(f"初始化 langfuse 失败: {str(e)}", exc_info=True)
    # 不抛异常，继续启动
```

**影响**：
- 无法追踪 Claude API 调用
- 无法统计 token 使用量
- 无法查看对话历史

**不影响**：
- 服务启动
- 任务执行
- Claude 调用（只是不记录）

## 十、小结：外设层做了什么

| 服务 | 输入 | 输出 | 作用 |
|------|------|------|------|
| **COS 配置** | config/.cos.conf | ~/.cos.conf | 云端备份能力 |
| **Langfuse 初始化** | 环境变量 | OpenTelemetry instrumentation | LLM 调用追踪 |

**外设层的本质**：它是服务可观测性和数据持久化的"基础设施层"——配置云存储用于备份，配置追踪工具用于监控，为后续的核心业务提供数据保障和可见性。

**特点**：
- **非阻塞**：初始化失败不影响服务启动
- **被动使用**：一次配置，自动工作，无需业务代码修改
- **环境隔离**：COS 路径和 Langfuse 地址按环境（daily/pre/prod）区分
