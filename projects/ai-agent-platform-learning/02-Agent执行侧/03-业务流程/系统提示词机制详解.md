## 🎯 核心认知

### 什么是系统提示词？

**系统提示词 (System Prompt)**: 在用户提示词之前，由系统自动注入的指令，用于引导 Claude 的行为。

**类比理解**:
- 用户提示词 = 具体任务描述 ("帮我实现登录功能")
- 系统提示词 = 工作规范和上下文 ("你是前端工程师，当前项目使用 React...")

**code-agent 的系统提示词层次**:
```
1. 全局系统提示词 (Claude SDK 内置)
   - Claude 的基础行为规范
   - 工具使用指南
   
2. 领域系统提示词 (domain_prompt)
   - 特定领域的技术栈和规范
   - 例如: 前端领域的 React/Vue 规范
   
3. 精简系统提示词 (concise_system_prompt)
   - 任务级别的关键信息
   - 任务ID、PRD路径、文件引用处理规则
```

## 二、精简系统提示词详解

### 2.1 基础结构 (更新前)

```python
def get_concise_system_prompt(task_id: str) -> str:
    prd = PathManager.get_prd_file_path(task_id)
    
    return f"""
    1. **当前任务task_id = {task_id}**
    2. 如果你在这个过程中，需要读取需求文档（PRD），那么请读取 {prd} 文件
    """
```

**作用**:
- 告诉 Claude 当前任务的 ID
- 提供 PRD 文件的准确路径

**局限性**:
- ❌ 没有处理文件引用格式 (`@/openspec/design.md`)
- ❌ Claude 可能猜测文件内容而不调用 MCP

### 2.2 增强后的结构 (2026-07-21 更新)

**提交**: 29076014c  
**作者**: 御 (chenyu01@weidian.com)  
**标题**: feat: 精简系统提示词增加文件引用格式提示

**完整代码**:
```python
def get_concise_system_prompt(task_id: str) -> str:
    """
    获取精简的系统提示词
    """
    from config import get_ai24_mcp_name

    prd = PathManager.get_prd_file_path(task_id)
    ai24_mcp_name = get_ai24_mcp_name()

    return f"""
        1. **当前任务task_id = {task_id}**
        2. 如果你在这个过程中，需要读取需求文档（PRD），那么请读取 {prd} 文件
        3. 注意(FATAL): **当你在执行任务时,如果用户的提示词中包含文件引用格式(如 @/openspec/design.md、@/openspec/local_design.md、@/command 等以 @ 开头的路径),你必须先使用 MCP 工具获取这些文件的内容:**
            - **必须先调用 `mcp__{ai24_mcp_name}__getTemplateUsingPOST` 来获取模板内容**
            - **调用参数格式:**
              - templateId: "" (固定传空字符串)
              - promptType: 2 (固定值,表示获取文件引用)
              - promptDetail: 文件引用路径 (例如 "/openspec/AGENTS.md" 或 "/command",去掉开头的@符号)
              - taskId: "{task_id}" (当前任务ID)
            - **示例:** 如果用户提示词包含 "@/openspec/design.md",你必须先调用:
              ```
              mcp__{ai24_mcp_name}__getTemplateUsingPOST(templateId="", promptType=2, promptDetail="/openspec/AGENTS.md", taskId="{task_id}")
              ```
            - **获取到文件内容后,再继续执行后续操作**
            - **禁止跳过这个步骤,禁止假设文件内容**
    """
```

### 2.3 新增内容解析

**关键点1: 强制性标注**
```
注意(FATAL): ...你必须...
```
- 使用 `FATAL` 级别标注，增强 Claude 的重视度
- 使用 "必须"、"禁止" 等强制性语言

**关键点2: 明确的触发条件**
```
如果用户的提示词中包含文件引用格式(如 @/openspec/design.md...)
```
- 明确定义触发条件：`@` 开头的路径
- 列举常见示例：`@/openspec/*`、`@/command`

**关键点3: 完整的调用示例**
```python
mcp__{ai24_mcp_name}__getTemplateUsingPOST(
    templateId="", 
    promptType=2, 
    promptDetail="/openspec/AGENTS.md", 
    taskId="{task_id}"
)
```
- 提供可执行的代码示例
- 明确每个参数的值和含义

**关键点4: 路径处理规则**
```
promptDetail: 文件引用路径 (例如 "/openspec/AGENTS.md" 或 "/command",去掉开头的@符号)
```
- 明确需要去掉 `@` 符号
- 提供正确示例

**关键点5: 禁止绕过**
```
- **获取到文件内容后,再继续执行后续操作**
- **禁止跳过这个步骤,禁止假设文件内容**
```
- 强调必须先获取内容
- 禁止 Claude 自行推测或假设

## 三、文件引用格式处理机制

### 3.1 为什么需要文件引用格式？

**背景**: 用户在创建任务时，可能引用平台上的其他文档

**常见场景**:
```
用户提示词:
"请根据 @/openspec/design.md 中的设计实现登录页面"

期望行为:
1. Claude 识别 @/openspec/design.md
2. 调用 MCP 工具获取该文件内容
3. 基于文件内容实现登录页面

错误行为 (如果没有系统提示词引导):
1. Claude 假设文件内容
2. 生成不符合设计规范的代码
```

### 3.2 文件引用的标准格式

**格式**: `@<路径>`

**常见路径前缀**:

| 路径前缀 | 含义 | 示例 |
|---------|------|------|
| `/openspec/` | 开放规范文档 | `@/openspec/design.md` |
| `/openspec/local_design.md` | 本地设计文档 | `@/openspec/local_design.md` |
| `/command` | 命令说明 | `@/command` |
| `/template/` | 模板文件 | `@/template/react_component.tsx` |

### 3.3 处理流程

```
用户提示词包含 @/openspec/design.md
    ↓
Claude 收到系统提示词 (包含文件引用处理规则)
    ↓
识别: 提示词中有 @ 开头的路径
    ↓
解析: 去掉 @ 符号 → "/openspec/design.md"
    ↓
调用 MCP 工具:
  mcp__ai24__getTemplateUsingPOST(
    templateId="",
    promptType=2,
    promptDetail="/openspec/design.md",
    taskId="task_12345"
  )
    ↓
AI24 MCP 服务器:
  - 验证权限 (taskId)
  - 查询数据库或文件系统
  - 返回文件内容
    ↓
Claude 收到文件内容
    ↓
基于真实内容继续执行任务
```

### 3.4 promptType 参数说明

**AI24 MCP 的 getTemplateUsingPOST 接口支持多种 promptType**:

```python
class PromptType:
    TEMPLATE = 0        # 获取预定义模板
    PRD = 1             # 获取 PRD 文档
    FILE_REFERENCE = 2  # 获取文件引用 (@ 路径) ⭐ 新增
```

**promptType=2 的特殊规则**:
- `templateId` 固定传空字符串 `""`
- `promptDetail` 存放去掉 `@` 后的路径
- 必须传递 `taskId` 用于权限校验

**示例对比**:

| promptType | 用途 | templateId | promptDetail | taskId |
|-----------|------|------------|--------------|--------|
| 0 | 获取模板 | "template_001" | "" | 可选 |
| 1 | 获取PRD | "" | "" | 必须 |
| 2 | 获取文件引用 | "" | "/openspec/design.md" | 必须 |

### 4.1 场景1: 根据设计文档实现页面

**用户提示词**:
```
请根据 @/openspec/design.md 实现用户个人中心页面，
包含头像、昵称、设置按钮等组件。
```

**Claude 执行过程**:

**步骤1: 识别文件引用**
```
系统提示词中的规则: 如果包含 @/openspec/...
识别到: @/openspec/design.md
```

**步骤2: 调用 MCP 工具**
```python

# 用户提示词包含 @/openspec/design.md
```

## 五、对比：有无系统提示词的差异

### 5.1 没有系统提示词引导

**用户提示词**:
```
请根据 @/openspec/design.md 实现登录页面
```

**Claude 的可能行为**:
```
我看到你提到了 @/openspec/design.md，但我没有这个文件的内容。
让我根据常见的登录页面设计来实现：

[生成一个通用的登录页面代码，可能不符合实际设计规范]
```

**问题**:
- ❌ Claude 猜测文件内容
- ❌ 生成的代码可能不符合规范
- ❌ 需要人工干预和修正

### 5.2 有系统提示词引导

**系统提示词** (自动注入):
```
注意(FATAL): 如果用户提示词包含 @/openspec/...，
你必须先调用 mcp__ai24__getTemplateUsingPOST 获取文件内容，
禁止假设内容。
```

**Claude 的行为**:
```
识别到用户提示词包含 @/openspec/design.md，
根据系统提示词要求，我需要先获取该文件。

[调用 MCP 工具获取真实内容]

已获取设计文档，现在开始实现登录页面：
[基于真实设计规范生成代码]
```

**优势**:
- ✅ 自动识别并处理文件引用
- ✅ 使用真实内容而非猜测
- ✅ 无需人工干预

## 六、错误处理与边界情况

### 6.1 文件不存在

**场景**: 用户引用了不存在的文件

```python
# Claude 调用 MCP
mcp__ai24__getTemplateUsingPOST(
    templateId="", promptType=2, 
    promptDetail="/openspec/nonexistent.md", 
    taskId="task_12345"
)

# MCP 返回错误
{
  "error": "File not found: /openspec/nonexistent.md"
}

# Claude 的响应
"""
无法找到文件 @/openspec/nonexistent.md，请检查路径是否正确。
可用的文件列表：
- /openspec/design.md
- /openspec/api_spec.md
"""
```

### 6.2 权限不足

**场景**: 当前任务无权访问某个文件

```python
# MCP 返回错误
{
  "error": "Permission denied: User does not have access to this file"
}

# Claude 的响应
"""
您没有权限访问 @/openspec/design.md，
请联系任务创建者或管理员授予权限。
"""
```

### 6.3 路径格式错误

**错误示例**:
```
用户提示词: "请根据 /openspec/design.md 实现..."
          ↑ 缺少 @ 符号
```

**Claude 的行为**:
```
系统提示词规则: 必须是 @ 开头的路径
当前路径: /openspec/design.md (没有 @ 符号)
不触发 MCP 调用，按普通路径处理
```

**建议**: 用户教育，明确文件引用必须以 `@` 开头

## 七、最佳实践

### 7.1 系统提示词编写原则

1. **明确性**: 使用清晰的条件和指令
   ```
   ✅ "如果用户提示词包含 @/openspec/..."
   ❌ "你可能需要..."
   ```

2. **强制性**: 使用强制性语言
   ```
   ✅ "你必须先调用...，禁止跳过..."
   ❌ "建议你调用..."
   ```

3. **可执行性**: 提供完整的调用示例
   ```
   ✅ 提供完整代码示例 (参数、值)
   ❌ 只说明概念
   ```

4. **层次分明**: 使用标注区分重要程度
   ```
   ✅ "注意(FATAL): ..."
   ✅ "提示: ..."
   ```

### 7.2 文件引用规范

**DO**:
- ✅ 使用标准前缀: `@/openspec/`, `@/template/`
- ✅ 使用清晰的文件名: `design.md`, `api_spec.md`
- ✅ 在任务描述中说明文件用途

**DON'T**:
- ❌ 使用相对路径: `../design.md`
- ❌ 使用模糊名称: `doc1.md`, `file.txt`
- ❌ 假设 Claude 知道文件内容

### 7.3 调试技巧

**查看 Claude 是否调用了 MCP**:
```bash
# code-agent 日志
tail -f logs/main.log | grep "mcp__ai24__getTemplateUsingPOST"
```

**测试文件引用是否生效**:
