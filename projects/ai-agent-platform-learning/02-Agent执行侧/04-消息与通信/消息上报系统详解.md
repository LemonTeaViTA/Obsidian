# 消息上报系统详解

## ⚡ 核心结论（先看这里）

**不是长连接/WebSocket，是逐条 HTTP POST 短连接。**

Claude 每生成一条消息 → 消息循环收到 → 渲染 → 立刻 POST 到 AI24 → 平台展示给用户。
Claude 持续生成，就持续 POST。每次 POST 独立，发完即断，下次再发新连接。

```
Claude 生成文字/调用工具
    ↓  （SDK 流式吐出一条 message）
async for message in client.receive_response():   ← 消息循环
    ↓
_should_report_message() 过滤
    ↓  （通过）
渲染成可读文本
    ↓
HTTP POST /api/task/notify → AI24 平台           ← 独立短连接，发完断开
    ↓
平台追加展示给用户

Claude 继续生成下一条...  → 又一个 HTTP POST   ← 再来一次
```

**为什么不用长连接？**
整个系统的核心设计思想是"无状态"——任务可以在任意机器执行。
长连接会把连接绑死在某台机器上，破坏多机协作能力。
逐条 POST 无状态、任何机器都能发、一条失败不影响其他条。

消息上报系统负责将Code-agent的执行过程实时推送到AI24管理平台，让用户在Web界面看到任务进度。

## 三、消息类型

### 3.1 五大消息类型

MessageReporter提供5种消息上报方法：

| 方法 | report_type | 用途 | 使用场景 |
|------|-------------|------|---------|
| `report_initialization()` | 1 | 初始化信息 | 任务初始化成功/失败 |
| `report_user_message()` | 2 | 用户消息 | 用户的输入内容 |
| `report_system_message()` | 3 | 系统消息 | Claude的回复、系统提示 |
| `report_completion_metrics()` | 4 | 完成量化报告 | 任务完成后的统计信息 |
| `report_session_status()` | sessionStatus | 会话状态 | IDLE/IN_PROGRESS |

### 3.2 特殊状态上报

| 方法 | 用途 | 使用场景 |
|------|------|---------|
| `report_task_status_with_retry()` | 任务状态码 | 100-初始化, 200-技术方案, 310-开发, 500-完成, 999-失败 |
| `report_frontend_preview_status()` | 前端预览状态 | STARTING/STARTED/FAILED/STOPPED |

### 4.4 report_completion_metrics() - 完成量化报告

```python
    task_id="task_123",
    report_content=json.dumps({

        "execution_time": "5m 30s",
        "files_modified": 8,
        "tests_created": 12
    })
)
```

**实际调用位置：**
- 旧路径：`code-agent-report-tools` MCP 调用 `MessageReporter.report_completion_metrics()`。
- 新路径：`report-completion-metrics` Skill 的 `report_metrics.py` 直接 POST `/api/task/notify`，同样使用 `reportType=4`。

### 两条完成指标上报路径

```text
旧路径（当前 Apply 仍使用）
Claude → code-agent-report-tools MCP
       → MessageReporter.report_completion_metrics
       → ManagementApiTool → AI24

新路径（新增 Skill）
Claude → report-completion-metrics Skill
       → report_metrics.py → requests.post
       → AI24 /api/task/notify
```

新 Skill 要求指标包含 `total_code_lines`、`total_token`、`cost_estimate`、`execution_time`、`files_modified`，并可附带测试代码行数和开发代码行数。它会尝试读取 StopWatch，但当前脚本先校验 `execution_time` 必填再做补全，因此不能依赖 StopWatch 自动补齐缺失的必填时间。

> README 使用了“替代旧 MCP”的说法，但当前源码并未完成切换：旧 MCP、权限和 Apply 中的调用都还存在。学习文档应按“迁移并存期”理解。

### 4.5 report_session_status() - 会话状态 ⭐⭐⭐

**方法签名：**
```python
@staticmethod
async def report_session_status(
    task_id: int | str,
```

**SessionStatus枚举：**
```python
class SessionStatus(Enum):
```

**使用示例：**
```python

    task_id="task_123",
    session_status=SessionStatus.IDLE,
    idle_reason="success"
)
```

**实际调用位置（高频使用）：**
- `main.py:execute_query_task()` - 开始时上报IN_PROGRESS，结束时上报IDLE
- 每次查询都会调用2次

**用途：**
- 前端根据状态显示"执行中"或"空闲"
- 防止用户在执行中重复发送请求

## 六、实际使用流程

### 6.1 任务初始化流程

```
1. 用户发起任务 (POST /task/perform)
   ↓
2. main.py:run_init_task_via_claude()
   ↓
3. 开始初始化
   await MessageReporter.report_system_message(
       task_id, "开始初始化项目..."
   )
   ↓
4. 执行初始化（克隆代码、初始化OpenSpec）
   ↓
5. 初始化成功
   await MessageReporter.report_initialization(
       task_id, {"code": 0, "message": "初始化成功"}
   )
   ↓
6. 上报会话状态为空闲
   await MessageReporter.report_session_status(
       task_id, SessionStatus.IDLE, idle_reason="success"
   )
```

### 6.2 任务查询流程

```
1. 用户发送查询 (POST /task/query)
   ↓
2. main.py:execute_query_task()
   ↓
3. 上报会话状态：进行中
   await MessageReporter.report_session_status(
       task_id, SessionStatus.IN_PROGRESS
   )
   ↓
4. 提示用户
   await MessageReporter.report_system_message(
       task_id, "收到请求，正在为您生成..."
   )
   ↓
5. ClaudeAgentSDKService.query() 执行任务
   ├─ Claude生成消息
   ├─ claude_message_renderer渲染消息
   └─ report_system_message() 上报Claude的回复
   ↓
6. 任务完成，上报会话状态：空闲
   await MessageReporter.report_session_status(
       task_id, SessionStatus.IDLE
   )
```

### 6.3 OpenSpec工作流流程

```
用户: /openspec:proposal
   ↓
1. 上报会话状态：IN_PROGRESS
   ↓
2. 上报系统消息："开始需求分析..."
   ↓
3. Claude执行proposal阶段
   ├─ 需求分析 → report_system_message()
   ├─ 技术设计 → report_system_message()
   ├─ 测试设计 → report_system_message()
   └─ 任务拆解 → report_system_message()
   ↓
4. 上报任务状态码：200（技术方案完成）
   await MessageReporter.report_task_status_with_retry(

   ↓

```

## 八、关键设计特点

### 8.1 异步非阻塞

所有上报方法都是异步的：
```python
@staticmethod
async def report_system_message(...) -> bool
```

**优点：**
- ✅ 不阻塞主流程
- ✅ 上报失败不影响任务执行
- ✅ 提升性能

### 8.2 失败容错

```python
try:
    result = await ManagementApiTool.report_task_status(...)
    if result:
        logger.info("上报成功")
    else:
        logger.warning("上报失败")
    return result
except Exception as e:
    logger.error(f"上报异常: {str(e)}", exc_info=True)
    return False  # 返回False而不是抛出异常
```

**特点：**
- ✅ 上报失败只记录日志
- ✅ 不抛出异常
- ✅ 不中断任务执行

### 8.3 重试机制

`report_task_status_with_retry()` 实现了重试逻辑：
```python
total_attempts = 1 + max_retries  # 默认最多3次

for attempt in range(1, total_attempts + 1):
    try:
        result = await ai24_client.notify_task_status(...)
        return True
    except Exception as e:
        if attempt < total_attempts:
            logger.warning("上报失败，将在1秒后重试")
            await asyncio.sleep(1)
        else:
            logger.error("上报失败（已达最大重试次数）")
return False
```

**特点：**
- ✅ 默认重试2次（总共3次尝试）
- ✅ 失败间隔1秒
- ✅ 最终失败不抛异常

### 8.4 UUID生成

每条消息都有唯一的report_id：
```python
report_id=str(uuid.uuid4())
```

**用途：**
- 消息去重
- 消息追踪
- 幂等性保证

| `report_system_message()` | ⭐⭐⭐ 非常高频 | 各处（Claude回复、错误提示、进度提示） |
| `report_session_status()` | ⭐⭐⭐ 高频 | 每次查询2次（开始+结束） |
| `report_initialization()` | ⭐ 低频 | 仅任务初始化时 |
| `report_task_status_with_retry()` | ⭐⭐ 中频 | OpenSpec各阶段完成时 |
| `report_frontend_preview_status()` | ⭐ 低频 | 前端任务预览启动/停止时 |
| `report_completion_metrics()` | ⭐ 低频 | 旧 MCP 完成指标路径；新增 Skill 提供并行 HTTP 路径 |
| `report_user_message()` | ⭐ 低频 | 记录用户输入 |

### 9.2 典型任务的上报次数

**一次OpenSpec Proposal任务：**
```
1. report_session_status(IN_PROGRESS)      - 1次
2. report_system_message("收到请求...")     - 1次
3. report_system_message(Claude回复)       - 10-20次（分多次返回）
4. report_task_status_with_retry(200)      - 1次
5. report_session_status(IDLE)             - 1次

总计：约 15-25 次上报
```

## 十、错误处理实践

### 10.1 上报失败的处理

```python
# ✅ 推荐：捕获异常，记录日志，不阻塞
try:
    await MessageReporter.report_system_message(
        task_id=task_id,
        report_content=message
    )
except Exception as e:
    logger.error(f"上报消息失败: {str(e)}")
    # 不影响主流程继续执行

# ❌ 不推荐：让异常传播
await MessageReporter.report_system_message(...)  # 可能抛异常
```

### 10.2 关键节点必须上报

```python
# 会话状态必须上报（即使失败也要记录）
try:
    await MessageReporter.report_session_status(
        task_id=task_id,
        session_status=SessionStatus.IDLE
    )
except Exception as e:
    logger.error(f"上报会话状态失败: {str(e)}", exc_info=True)
    # 即使上报失败，也要记录到本地日志
```

## 十一、总结

### 核心要点

1. **消息类型丰富**
   - 7种上报方法
   - 覆盖初始化、执行、完成、状态等全流程

2. **异步非阻塞设计**
   - 所有方法都是async
   - 上报失败不影响任务执行

3. **容错性强**
   - 异常捕获
   - 重试机制
   - 日志记录

4. **实时性好**
   - Claude每生成一条消息就上报
   - 用户可以实时看到进度

5. **两个API客户端**
   - ManagementApiTool - 通用上报（大部分场景）
   - AI24Client - 任务状态码上报（OpenSpec流程）

### 消息上报流程总结

```
任务执行 → 生成消息 → MessageReporter分类 → 
HTTP API → AI24平台 → 存储到数据库 → 
Web界面实时展示 → 用户看到进度
```

这个消息上报系统是用户体验的关键，没有它用户就看不到任务执行进度，只能干等！
