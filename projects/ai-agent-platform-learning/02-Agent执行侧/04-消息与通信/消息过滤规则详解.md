## 二、为什么跳过 SystemMessage？

### 2.1 SystemMessage 是什么？

**SystemMessage 是 SDK 发给 code-agent 的"控制信令"，不是 Claude 生成的内容。**

它的内容类似这样：

```json
{
  "type": "SystemMessage",
  "data": {
    "session_id": "sess_abc123",
    "status": "started",
    "timestamp": 1234567890
  }
}
```

### 2.2 为什么不展示给用户？

**原因1：用户看不懂**

用户想看的是：
- ✅ "正在读取文件"
- ✅ "我已经理解了需求"
- ✅ "开始修改代码"

用户**不想看**：
- ❌ `{"session_id": "sess_abc123", "status": "started"}`
- ❌ 这是技术细节，没有业务意义

**原因2：code-agent 内部使用**

SystemMessage 的真正用途是：
```python
# 从 SystemMessage 里提取 session_id，建立映射
if isinstance(message, SystemMessage):
    msg_session_id = message.data.get('session_id')
    TaskSessionMapper.set_mapping(task_id, msg_session_id)  # 这是给系统用的
```

这是"管道信号"，不是"给用户的内容"。

### 2.3 类比：HTTP 协议的 Header

就像浏览器访问网站：
- **HTTP Header**（Connection: keep-alive, Content-Type: ...）→ 浏览器内部用，不展示给用户
- **HTTP Body**（网页内容）→ 展示给用户

SystemMessage 就是 "SDK 协议的 Header"，AssistantMessage 是 "Body"。

## 三、为什么跳过空的 AssistantMessage？

### 3.1 什么是"空的" AssistantMessage？

```python
# 空的 AssistantMessage
{
  "type": "AssistantMessage",
  "content": []        # ← 没有任何 Block
}

# 或者
{
  "type": "AssistantMessage",
  "content": [
    TextBlock(text=""),   # ← 空字符串
    TextBlock(text="  ")  # ← 只有空格
  ]
}
```

### 3.2 为什么会有空的 AssistantMessage？

**Claude 在"思考"的时候，可能会发出这种消息。**

真实场景：
```
Claude 收到你的请求
    ↓
Claude: "嗯...让我想想..."  ← 内部思考阶段
    ↓
SDK 发出一条 AssistantMessage，但 content=[]  ← 思考中，还没写出来
    ↓
Claude: "好的，我明白了，开始写代码"
    ↓
SDK 发出一条有内容的 AssistantMessage  ← 有实际输出了
```

如果把空的也发给用户，用户会看到：
```
[系统消息] （空白）  ← 莫名其妙的空行
[系统消息] 好的，我明白了，开始写代码
```

过滤后，用户只看到：
```
[系统消息] 好的，我明白了，开始写代码  ← 干净
```

### 3.3 代码里的检查逻辑

```python
# 检查 content 是否为空列表
if not message.content:
    return False  # 跳过

# 检查是否所有 TextBlock 都是空字符串
text_blocks = [block for block in message.content if isinstance(block, TextBlock)]
if text_blocks and all(not block.text.strip() for block in text_blocks):
    return False  # 跳过
```

## 四、为什么跳过评分用的临时 Session？

### 4.1 什么是"评分 Session"？

code-agent 有个功能：**自动评估 UI 设计稿和实现的相似度**。

流程：
```
1. Claude 实现完前端页面
2. code-agent 截图 + 读取设计稿
3. 创建一个临时 Session 让 Claude 打分："这两个图像有多像？0-100 分"
4. Claude 返回评分（如 85 分）
5. 评分完，这个临时 Session 就丢弃了
```

### 4.2 临时 Session 的命名规则

```python
# 评分专用的 Session，名字里有特殊标记
session_id = f"{task_id}_scoring_{uuid.uuid4()}"
#                    ↑ 标记：这是临时评分用的
```

### 4.3 为什么不展示评分对话？

**用户关心的是"分数"，不关心"Claude 怎么打分的"。**

如果不过滤，用户会看到：
```
[系统消息] 正在编辑 index.html...
[系统消息] 文件已保存
[系统消息] 让我评估这两张图的相似度   ← 评分 Session 开始
[系统消息] 布局一致，颜色略有差异
[系统消息] 综合评分 85 分             ← 评分 Session 的对话
[系统消息] 继续实现下一个功能...      ← 回到主 Session
```

这些"打分过程"的对话会干扰用户，他们只想看主任务的进度。

过滤后：
```
[系统消息] 正在编辑 index.html...
[系统消息] 文件已保存
[评分结果] UI 相似度：85 分           ← 只上报结果，不上报打分过程
[系统消息] 继续实现下一个功能...
```

### 4.4 代码里的检查逻辑

```python
# 跳过评分 Session 的消息
if session_id and "_scoring_" in session_id:
    logger.info(f"[Session {session_id}] 跳过评分 Session 消息上报")
    return False
```

## 五、总结：过滤的核心原则

| 过滤类型 | 本质 | 类比 |
|---------|------|------|
| SystemMessage | 控制信令 | HTTP Header（不给用户看） |
| 空 AssistantMessage | 思考中间态 | 打字时的"正在输入..."（不必每次都发） |
| 评分 Session | 内部辅助任务 | 后台计算（用户只要结果） |

**核心原则：只展示对用户有意义的内容，过滤掉技术细节和中间态。**

## 六、如果不过滤会怎样？

### 不过滤 SystemMessage：

```
用户看到：
[系统消息] {"session_id": "sess_abc", "status": "started"}  ← ???
[系统消息] 好的，我来帮你实现登录功能
```

用户：什么是 session_id？status 是什么？我看不懂！😵

### 不过滤空 AssistantMessage：

```
用户看到：
[系统消息] 
[系统消息] 
[系统消息] 好的，我来帮你实现登录功能
```

用户：前面两条空白是什么？bug 吗？😕

### 不过滤评分 Session：

```
用户看到：
[系统消息] 正在实现登录...
[系统消息] 请评估这两张图的相似度   ← 评分对话开始
[系统消息] 图A 是登录页面
[系统消息] 图B 是设计稿
[系统消息] 它们的布局相似度 90%
[系统消息] 颜色相似度 85%
[系统消息] 综合评分 87 分           ← 评分对话结束
[系统消息] 继续实现注册功能...      ← 回到主任务
```

用户：中间这一大段评分对话是什么？我只想知道最后的分数啊！🤔

## 八、过滤是"用户体验优化"，不是"隐藏信息"

**重要**：所有消息仍然会记录到日志文件（`claude_message_renderer.py` 渲染的本地日志），方便调试。

过滤只影响"实时推送到 AI24 平台展示给用户"的内容。

```
完整日志（本地文件，开发者看）：
  ✅ SystemMessage
  ✅ 空 AssistantMessage
  ✅ 评分 Session
  ✅ 所有细节

用户界面（AI24 平台，用户看）：
  ❌ SystemMessage（过滤）
  ❌ 空 AssistantMessage（过滤）
  ❌ 评分 Session（过滤）
  ✅ 只有有意义的内容
```

这样既保证了**调试时有完整信息**，又保证了**用户看到的简洁清晰**。
