# 环境恢复机制详解

> 任务从机器 A 切换到机器 B 时，代码、文件如何被重新拉取？多机协作的最后一块拼图。

---

## ⚡ 核心问题

```
机器 A (10.0.1.100):
  - 用户初始化任务 task_123
  - 代码克隆到 /tmp/projects/task_123/
  - Claude 开始工作...

机器 B (10.0.1.200):
  - 用户继续查询任务 task_123
  - 问题：机器 B 没有代码！
  - 解决：自动恢复环境 ✅
```

**环境恢复机制就是解决这个问题的。**

---

## 一、何时触发恢复？

### 调用位置

在 `run_query_task_in_thread()` 的最开头（[main.py:2400-2407](../../code-agent/main.py#L2400-L2407)）：

```python
def run_query_task_in_thread(query_message: TaskQueryMessage, skip_check: bool = False):
    task_id = query_message.task_id
    
    # 检查并恢复任务环境（在后台线程中执行，不阻塞）
    if query_message.message_type != "interrupt":
        try:
            logger.info(f"[Task {task_id}] 开始检查任务环境...")
            asyncio.run(check_and_restore_task_environment(task_id))  # ⭐ 这里
            logger.info(f"[Task {task_id}] 任务环境检查完成")
        except Exception as env_err:
            logger.error(f"[Task {task_id}] 任务环境检查失败: {str(env_err)}")
            # 环境检查失败不阻断任务（容错设计）
```

**关键点**：
- ✅ **每次查询前都检查**：确保环境完整
- ✅ **异步执行**：不阻塞 HTTP 响应
- ✅ **容错设计**：失败不影响任务继续执行（可能用旧代码运行）

## 二、恢复什么？（三种资源）

```
任务环境 = 任务目录 + PRD 文件 + Claude 会话
```

| 资源类型 | 内容 | 示例 | 优先级 |
|---------|------|------|--------|
| 任务目录 | 项目代码（Git 仓库） | `/tmp/projects/task_123/project/` | ⭐⭐⭐ |
| PRD 文件 | 产品需求文档 | `/tmp/projects/task_123/prd.md` | ⭐⭐ |
| Claude 会话 | Claude Code 对话历史 | session JSONL/目录 | ⭐ |

**注意**：`TaskSessionMapper + Claude SDK resume` 负责定位和续接会话；跨机器时，当前代码仍会通过 `ClaudeSessionRestoreStrategy` 恢复本地会话文件。两者是配合关系，不是替代关系。

## 三、从哪里恢复？（责任链模式）

### 3.1 数据源与实际适用范围

```
1️⃣ COS（腾讯云对象存储）← 优先级最高
    机器 A 实时备份 → COS
    机器 B 从 COS 下载
    
2️⃣ OSS（阿里云对象存储）← 次优先级
    历史遗留，部分老任务在 OSS
    
3️⃣ Git（代码仓库）或 DEP ← 兜底/专项来源
    任务目录可从 Git 克隆，PRD 可从 DEP 恢复
```

不同资源不会机械地使用同一条三段链路：

| 资源 | 当前有效恢复顺序 |
|------|------------------|
| 任务目录 | COS → Git（默认链中会经过 OSS，但 OSS 不负责项目目录） |
| PRD 文件 | COS → DEP |
| Claude 会话 | COS → OSS |

### 3.2 责任链尝试顺序

```python
# base.py 初始化数据源列表
self.backup_sources = [
    COSBackupSource(),      # 优先级 1
    OSSBackupSource(),      # 优先级 2
    GitBackupSource()       # 优先级 3
]

# 按优先级排序（数字越小优先级越高）
self.backup_sources.sort(key=lambda s: s.get_priority())
```

**基类默认恢复流程**：
```
尝试从 COS 恢复
    ├─ 成功 → 返回
    └─ 失败 → 继续
            ↓
尝试从 OSS 恢复
    ├─ 成功 → 返回
    └─ 失败 → 继续
            ↓
尝试从 Git 恢复
    ├─ 成功 → 返回
    └─ 失败 → 恢复失败
```

## 五、三个恢复策略详解

### 5.1 任务目录恢复（TaskDirectoryRestoreStrategy）⭐ 最重要

**检查**：
```python
async def check(self, task_id: str, metadata) -> bool:
    project_path = metadata.project_path
    if not project_path:
        return False  # 元数据里没有 project_path
    
    project_dir = PathManager.get_task_project_dir_by_task_id(task_id)
    return os.path.exists(project_dir)  # 目录存在吗？
```

**恢复**：
```python
async def restore(self, task_id: str, metadata) -> bool:
    git_url = metadata.git_url
    branch = metadata.branch
    project_dir = PathManager.get_task_project_dir_by_task_id(task_id)
    
    # 使用 COS 路径
    cos_path = PathManager.get_cos_task_dir_path(task_id)
    
    # 责任链尝试恢复（COS → OSS → Git）
    success = await self.try_restore_from_sources(
        task_id=task_id,
        target_path=project_dir,
        is_directory=True,      # ⭐ 目录需要递归下载
        cos_path=cos_path,
        git_url=git_url,
        branch=branch
    )
    
    return success
```

**COS 路径示例**：
```
task_123 → /code-agent/task_env/task_123/project/
```

---

### 5.2 PRD 文件恢复（PRDFileRestoreStrategy）

**检查**：
```python
async def check(self, task_id: str, metadata) -> bool:
    prd_path = metadata.prd_path
    if not prd_path:
        return False
    
    prd_file_path = PathManager.get_prd_file_path(task_id)
    return os.path.exists(prd_file_path)  # PRD 文件存在吗？
```

**恢复**：
```python
async def restore(self, task_id: str, metadata) -> bool:
    prd_file_path = PathManager.get_prd_file_path(task_id)
    
    # COS 路径
    cos_path = PathManager.get_cos_prd_file_path(task_id)
    
    # 责任链尝试恢复
    success = await self.try_restore_from_sources(
        task_id=task_id,
        target_path=prd_file_path,
        is_directory=False,     # ⭐ 单个文件
        cos_path=cos_path
    )
    
    return success
```

---

### 5.3 Claude 会话恢复（ClaudeSessionRestoreStrategy）

**原理**：根据 `TaskSessionMapper` 找到任务对应的 `session_id`，检查本地 Claude 会话目录；跨机器或本地文件缺失时，依次尝试从 COS、OSS 恢复会话文件。

**现状**：当前仍由 `BackupRestoreManager` 注册并执行。文件恢复完成后，Claude SDK 再通过 `resume=session_id` 续接历史会话。

## 六、三个数据源详解

### 6.1 COSBackupSource（腾讯云 COS）⭐ 主力

**优先级**：10（最高）

**恢复方法**：
```python
async def restore(self, cos_path: str, target_path: str, is_directory: bool) -> bool:
    if is_directory:
        # 目录：使用 coscmd download 递归下载
        cmd = f"coscmd download -r {cos_path} {target_path}"
    else:
        # 文件：直接下载
        cmd = f"coscmd download {cos_path} {target_path}"
    
    result = subprocess.run(cmd, shell=True, ...)
    return result.returncode == 0
```

**备份触发**：
```python
# execute_query_task() 开头
start_file_backup_listener(task_id, project_path)
    ↓
监听文件变化 → 实时上传到 COS
```

**COS 路径结构**：
```
/code-agent/task_env/
    ├─ task_123/
    │   ├─ project/          ← 任务目录
    │   │   ├─ src/
    │   │   ├─ package.json
    │   │   └─ ...
    │   └─ prd.md            ← PRD 文件
    ├─ task_456/
    └─ ...
```

### 6.2 OSSBackupSource（阿里云 OSS）

**优先级**：20（次优先级）

**用途**：历史遗留，部分老任务的备份在 OSS。

**恢复方法**：

```python
async def restore(self, oss_path: str, target_path: str, is_directory: bool) -> bool:
    if is_directory:
        # 目录：使用 OSS API 递归下载
        ...
    else:
        # 文件：直接下载
        ...
```

---

### 6.3 GitBackupSource（Git 仓库）⭐ 兜底

**优先级**：30（最低，但最可靠）

**用途**：COS/OSS 都失败时，直接从 Git 克隆代码。

**恢复方法**：
```python
async def restore(self, git_url: str, branch: str, target_path: str) -> bool:
    # 克隆代码
    cmd = f"git clone --depth 1 --branch {branch} {git_url} {target_path}"
    result = subprocess.run(cmd, shell=True, ...)
    
    # 如果有依赖仓库，也克隆
    if dependent_git_urls:
        for dep_url in dependent_git_urls:
            ...
    
    return result.returncode == 0
```

**关键点**：
- ✅ `--depth 1`：浅克隆，只下载最新版本（快）
- ✅ `--branch`：指定分支
- ✅ 支持多仓库（dependent_git_urls）

## 七、多机协作完整示例

### 场景：任务从机器 A 切换到机器 B

```
时间线：

T1: 机器 A (10.0.1.100) - 初始化任务
    POST /task/perform {"taskId": "task_123", ...}
    ↓
    1. init_task_project() - 克隆代码到 /tmp/projects/task_123/
    2. MetaContainer.update(project_path="/tmp/projects/task_123/project")
    3. MetaContainer.report_task() - 上报 IP: 10.0.1.100
    4. start_file_backup_listener() - 启动 COS 实时备份
    ↓
    代码实时同步到 COS: /code-agent/task_env/task_123/

T2: 机器 A - 第一次查询
    POST /task/query {"taskId": "task_123", "input": "实现登录"}
    ↓
    1. check_and_restore_task_environment()
       - 检查：project_dir 存在 ✅
       - 跳过恢复
    2. service.query() - 正常执行

T3: 机器 B (10.0.1.200) - 第二次查询（负载均衡切换）
    POST /task/query {"taskId": "task_123", "input": "继续实现"}
    ↓
    1. check_and_restore_task_environment()
       - 检查：project_dir 不存在 ❌
       - 开始恢复：
         ↓
         a. 从 MetaContainer 读取：
            - project_path="/tmp/projects/task_123/project"
            - git_url="ssh://git@gitlab..."
            - branch="feature/task_123"
         ↓
         b. 尝试从 COS 恢复：
            coscmd download -r /code-agent/task_env/task_123/project/ \
                               /tmp/projects/task_123/project/
            成功 ✅
         ↓
         c. 上报："✅ 任务目录恢复成功"
    
    2. TaskSessionMapper.get_session_id("task_123")
       → 返回 "sess_abc123"（从云端读取映射）
    
    3. service.query(session_id="sess_abc123")
       - Claude 恢复对话历史 ✅
       - 继续执行任务
    
    4. MetaContainer.report_task()
       - 更新 IP: 10.0.1.200（任务切换到机器 B）
```

**关键点**：
- ✅ 机器 B 从 COS 下载代码（秒级）
- ✅ 机器 B 从 TaskSessionMapper 获取 session_id（秒级）
- ✅ 用户无感知切换（体验连贯）

## 八、设计亮点

### 8.1 责任链模式（容错）

```
COS 失败 → OSS 失败 → Git 兜底

优点：
  - COS 挂了，还有 OSS
  - OSS 也挂了，还能从 Git 克隆
  - 多层保障，极大提升可靠性
```

### 8.2 实时备份 + 按需恢复

```
备份：后台实时同步（不阻塞任务）
恢复：查询前按需检查（只在必要时下载）

优点：
  - 不浪费资源（不是每次都下载）
  - 数据始终最新（实时同步）
```

### 8.3 容错设计

```python
try:
    asyncio.run(check_and_restore_task_environment(task_id))
except Exception as env_err:
    logger.error(f"环境检查失败: {str(env_err)}")
    # 不阻断任务执行 ← 容错
```

**原因**：
- 环境恢复失败，可能用旧代码也能跑
- 总比直接中断任务好
- 会发管理员通知，人工介入

### 8.4 用户体验优化

```python
# 恢复开始
await MessageReporter.report_system_message(
    task_id, "🔄 正在恢复任务目录，请稍候..."
)

# 恢复成功
await MessageReporter.report_system_message(
    task_id, "✅ 任务目录恢复成功"
)
```

**用户看到**：
```
[系统消息] 🔄 正在恢复任务目录，请稍候...
（等待 3 秒）
[系统消息] ✅ 任务目录恢复成功
[系统消息] 好的，我继续实现登录功能...
```

用户知道发生了什么，不会觉得"卡住了"。

## 十一、总结

### 核心价值

**环境恢复机制是多机协作的基石。没有它，任务就被"绑死"在某台机器上了。**

### 关键设计

1. **三种资源**：任务目录 + PRD 文件 + Claude 会话文件
2. **按资源选择责任链**：任务目录 COS→Git、PRD COS→DEP、会话 COS→OSS
3. **实时备份 + 按需恢复**：不浪费资源
4. **容错设计**：恢复失败不阻塞任务
5. **用户体验**：实时通知恢复进度

### 与整体架构的契合

```
多机协作的三大支柱：

1. MetaContainer           → 元数据共享（云端）
2. TaskSessionMapper       → 会话共享（云端）
3. BackupRestoreManager    → 文件共享（COS/Git）← 你刚学完 ✅

三者配合，任务可以在任意机器无缝切换！
```
