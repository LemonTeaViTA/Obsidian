# 云存储系统详解

## 一、整体架构

Code-agent 同时使用两类“云端”能力：结构化状态通过 AI24 管理平台的 `agentTaskData` / `agentClaudeData` HTTP API 保存；任务目录和会话文件主要通过腾讯云 COS 备份，部分文件还会使用 OSS、DEP 或 Git 恢复。仅凭客户端代码不能断言管理平台 API 的服务端数据一定落在 COS。

### 架构图

```
┌─────────────────────────────────────────────────────────────┐
│                     Code-agent 进程                          │
│                                                              │
│  ┌──────────────────┐        ┌──────────────────┐          │
│  │  StepPlanner     │        │  MetaContainer   │          │
│  │  (步骤管理)      │        │  (任务元数据)    │          │
│  └────────┬─────────┘        └────────┬─────────┘          │
│           │                           │                     │
│           │ 调用                      │ 调用                │
│           ↓                           ↓                     │
│  ┌──────────────────┐        ┌──────────────────┐          │
│  │ task_data_api.py │        │ claude_data_api  │          │
│  │ (任务数据API)    │        │ (会话数据API)    │          │
│  └────────┬─────────┘        └────────┬─────────┘          │
│           │                           │                     │
│           └───────────┬───────────────┘                     │
│                       │ HTTP请求                            │
└───────────────────────┼─────────────────────────────────────┘

            ┌───────────────────────┐
            │   腾讯云 COS          │
            │ (对象存储)            │
            └───────────────────────┘
```

## 二、两个核心API客户端

### 2.1 claude_data_api.py - 会话数据管理

**职责：** 管理Claude会话相关的配置数据

**文件位置：** `claude_data_api.py`

**数据类型：**
```python
class ClaudeDataType(str, Enum):
    SESSION_CONFIG = "session_config"  # 会话配置
```

**核心方法：**
```python
# 1. 保存或更新数据
save_or_update(session_id: str, data_type: ClaudeDataType, data: Any)

# 2. 删除数据
delete(session_id: str, data_type: ClaudeDataType)

# 3. 查询数据
get(session_id: str, data_type: ClaudeDataType)

# 4. 获取实际内容（自动解析JSON）
get_data_content(session_id: str, data_type: ClaudeDataType)
```

**API端点：**
```
POST   /api/agentClaudeData/saveOrUpdate
DELETE /api/agentClaudeData/delete
GET    /api/agentClaudeData/get
```

### 2.2 task_data_api.py - 任务数据管理

**职责：** 管理任务相关的所有数据

**文件位置：** `task_data_api.py`

**数据类型（重要）：**
```python
class TaskDataType(str, Enum):
    # 文档相关
    TECHNICAL_DESIGN = "technical_design"      # 技术方案
    PRD_OSS_URL = "prd_oss_url"               # PRD文档的OSS存储URL
    SESSION_OSS_URL = "session_oss_url"       # ClaudeCode会话文件的OSS存储URL
    GIT_BACKUP_BRANCH = "git_backup_branch"   # Git备份分支信息
    
    # 本地文件迁移相关
    TASK_METADATA = "task_metadata"           # 任务元信息（task_metadata.json）
    INTERRUPTED_TASKS = "interrupted_tasks"   # 中断任务（interrupted_tasks.json）
    STOPWATCH = "stopwatch"                   # 任务执行时间追踪
    STEP_PLANNER = "step_planner"             # 任务步骤规划
    SESSION_MAPPING = "session_mapping"       # 会话映射关系
    
    # 任务机器映射
    CONTAINER_IP = "container_ip"             # 任务所在容器IP地址
    AGENT_IP = "agent_ip"                     # 任务所在机器IP
    TASK_VERSION = "task_version"             # 任务版本号
    
    CUSTOM = "custom"                         # 自定义类型
```

**核心方法：**
```python
# 1. 保存或更新数据
save_or_update(task_id: str, data_type: TaskDataType, data: Any)

# 2. 删除数据
delete(task_id: str, data_type: TaskDataType)

# 3. 查询单个任务数据
get(task_id: str, data_type: TaskDataType)

# 4. 获取实际内容（自动解析JSON）
get_data_content(task_id: str, data_type: TaskDataType)

# 5. 按类型列出所有任务
list_by_type(data_type: TaskDataType) -> List[TaskDataRecord]

# 6. 按类型和数据内容筛选
list_by_type_and_data(data_type: TaskDataType, data: str)
```

**API端点：**
```
POST   /api/agentTaskData/saveOrUpdate
DELETE /api/agentTaskData/delete
GET    /api/agentTaskData/get
GET    /api/agentTaskData/listByType
GET    /api/agentTaskData/list
```

## 三、实际使用案例

### 3.1 StepPlanner的云存储

**文件：** `step_planner.py`

**存储机制：**
```python
class StepPlanner:
    def _save_task_data(self, task_id: str, steps: List[Step], current_index: int):
        """保存任务数据到云端"""
        data = StepPlannerData(
            task_id=task_id,
            steps=steps,
            current_index=current_index
        )
        
        # 调用task_data_api保存
        save_or_update(
            task_id=task_id,
            data_type=TaskDataType.STEP_PLANNER,  # 数据类型
            data=data.to_dict()                    # 转为字典
        )
    
    def _load_task_data(self, task_id: str):
        """从云端加载任务数据"""
        data_dict = get_data_content(task_id, TaskDataType.STEP_PLANNER)
        if data_dict:
            return StepPlannerData.from_dict(data_dict)
        return None
```

**数据结构：**
```json
{
  "task_id": "task_123",
  "steps": [
    {
      "name": "需求分析",
      "description": "阅读PRD文档，理解需求",
      "condition": "完成需求分析报告"
    },
    {
      "name": "技术设计",
      "description": "设计数据库和API",
      "condition": "完成技术设计文档"
    }
  ],
  "current_index": 0
}
```

## 四、数据流转过程

### 4.1 数据保存流程

```
应用层代码（如StepPlanner）
    ↓ 调用
task_data_api.save_or_update(task_id, data_type, data)
    ↓ 
TaskDataAPIClient实例化
    ↓ 
1. 将data转换为JSON字符串（如果是dict/list）
2. 构造HTTP请求体：
   {
     "taskId": "task_123",
     "type": "step_planner",
     "data": "{...json...}"
   }
    ↓ 
发送POST请求到AI24平台
    ↓ 
POST http://ai24.daily.vdian.net/api/agentTaskData/saveOrUpdate
    ↓ 
AI24 管理平台保存结构化任务数据（客户端代码无法确认服务端底层介质）
    ↓ 
返回结果：{"code": 200, "message": "success", "data": true}
```

### 4.2 数据读取流程

```
应用层代码（如StepPlanner）
    ↓ 调用
task_data_api.get_data_content(task_id, data_type)
    ↓ 
内部调用get()方法
    ↓ 
发送GET请求到AI24平台
    ↓ 
GET http://ai24.daily.vdian.net/api/agentTaskData/get?taskId=xxx&type=yyy
    ↓ 
AI24 管理平台读取结构化任务数据
    ↓ 
返回结果：
{
  "code": 200,
  "data": {
    "id": 123,
    "taskId": "task_123",
    "type": "step_planner",
    "data": "{...json字符串...}",
    "gmtCreate": "2026-07-08 10:00:00",
    "gmtUpdate": "2026-07-08 10:00:00"
  }
}
    ↓ 
get_data_content()自动解析data字段的JSON
    ↓ 
返回解析后的Python对象（dict/list）
```

## 五、关键设计特点

### 5.1 单例模式

两个API客户端都使用单例模式：
```python
_default_client = None

def get_default_client():
    global _default_client
    if _default_client is None:
        _default_client = TaskDataAPIClient()
    return _default_client
```

**优点：**
- 复用HTTP连接
- 统一配置管理
- 避免重复初始化

### 5.2 自动JSON转换

```python
# 保存时：自动将dict/list转为JSON字符串
if isinstance(data, dict) or isinstance(data, list):
    data_str = json.dumps(data, ensure_ascii=False)

# 读取时：自动将JSON字符串解析为dict/list
try:
    return json.loads(data_str)
except json.JSONDecodeError:
    return data_str  # 如果不是JSON，直接返回字符串
```

### 5.3 类型安全

使用枚举类型避免硬编码：
```python
# ❌ 错误写法
save_or_update(task_id, "step_planner", data)

# ✅ 正确写法
save_or_update(task_id, TaskDataType.STEP_PLANNER, data)
```

### 5.4 错误处理

所有API调用都有完整的异常处理：
```python
try:
    response = requests.post(url, json=payload, timeout=self.timeout)
    response.raise_for_status()  # 检查HTTP状态码
    result = response.json()
    logger.info(f"保存或更新成功: {result}")
    return result
except requests.RequestException as e:
    logger.error(f"保存或更新任务数据失败: {str(e)}", exc_info=True)
    raise
```

### 5.5 环境配置

API基础URL从环境变量读取：
```python
self.base_url = (
    base_url or 
    os.getenv("MANAGEMENT_API_BASE_URL") or 
    "http://ai24.daily.vdian.net/"
).rstrip("/")
```

**支持的环境：**
- `daily`: http://ai24.daily.vdian.net/
- `pre`: http://ai24.pre.vdian.net/
- `prod`: http://ai24.vdian.net/

## 六、多机共享机制

### 6.1 问题场景

```
机器A: 初始化任务 task_123，写入元数据
机器B: 接收任务 task_123 的查询请求
机器B需要：读取task_123的元数据（project_path、git_url、template_id等）
```

### 6.2 解决方案

**通过云存储实现数据共享：**

```
机器A                          腾讯云COS                    机器B
  │                                │                          │
  │ 1. 初始化任务                   │                          │
  ├─────────────────────────────>  │                          │
  │    saveOrUpdate(task_123)      │                          │
  │                                │                          │
  │                                │  2. 接收任务查询           │
  │                                │ <────────────────────────┤
  │                                │                          │
  │                                │  3. 读取任务元数据         │
  │                                │ ────────────────────────>│
  │                                │    get(task_123)         │
  │                                │                          │
  │                                │  4. 执行任务              │
  │                                │                       [执行]
  │                                │                          │
  │                                │  5. 更新任务状态          │
  │                                │ <────────────────────────┤
  │                                │    saveOrUpdate(...)     │
```

### 6.3 关键数据类型

**任务归属标识：**
```python
# 保存机器IP
save_or_update(
    task_id=task_id,
    data_type=TaskDataType.AGENT_IP,
    data=get_local_ip()
)
```

**任务版本号：**
```python
# 防止脏数据
save_or_update(
    task_id=task_id,
    data_type=TaskDataType.TASK_VERSION,
    data=str(int(time.time() * 1000))
)
```

## 八、对比本地存储

### 8.1 旧方案（本地文件）

```
项目根目录/
└── tmp/
    └── data/
        ├── task_metadata.json         # 所有任务的元数据
        ├── task_session_mapping.json  # 会话映射
        ├── interrupted_tasks.json     # 中断任务
        └── stopwatch/
            └── task_123.json          # 单个任务的计时
```

**问题：**
- ❌ 无法多机共享
- ❌ 进程崩溃可能丢失数据
- ❌ 磁盘故障导致数据丢失
- ❌ 难以备份和恢复

### 8.2 新方案（云存储）

```
每个数据类型独立存储到COS：
- task_id + data_type 作为唯一标识
- 自动版本控制（gmtCreate/gmtUpdate）
- RESTful API统一访问
- 支持批量查询（list_by_type）
```

**优点：**
- ✅ 多机共享数据
- ✅ 数据持久化可靠
- ✅ 支持灾难恢复
- ✅ 统一监控和管理
- ✅ 支持横向扩展

### 8.3 兼容模式

当前代码保持兼容性，优先使用旧路径（如果存在）：

```python
# PathManager的路径选择逻辑
if old_path.exists():
    return old_path  # 使用旧路径（本地文件）
else:
    return new_path  # 使用新路径（云存储）
```

## 九、最佳实践

### 9.1 使用模块级函数

```python
# ✅ 推荐：使用模块级便捷函数（自动使用单例）
from task_data_api import save_or_update, TaskDataType
save_or_update(task_id, TaskDataType.STEP_PLANNER, data)

# ❌ 不推荐：每次创建新客户端
client = TaskDataAPIClient()
client.save_or_update(task_id, TaskDataType.STEP_PLANNER, data)
```

### 9.2 使用枚举类型

```python
# ✅ 推荐：使用枚举，IDE有自动补全
from task_data_api import TaskDataType
save_or_update(task_id, TaskDataType.STEP_PLANNER, data)

# ❌ 不推荐：字符串硬编码，容易拼写错误
save_or_update(task_id, "step_planner", data)
```

### 9.3 异常处理

```python
try:
    data = get_data_content(task_id, TaskDataType.STEP_PLANNER)
    if data is None:
        logger.warning(f"任务 {task_id} 的数据不存在")
        return None
    # 处理数据...
except requests.RequestException as e:
    logger.error(f"获取任务数据失败: {str(e)}", exc_info=True)
    # 降级处理或重试...
```

### 9.4 自动JSON解析

```python
# ✅ 推荐：使用get_data_content()自动解析JSON
data = get_data_content(task_id, TaskDataType.STEP_PLANNER)
# data已经是dict类型，可以直接使用
steps = data.get('steps', [])

# ❌ 不推荐：手动解析JSON

data_str = result['data']['data']
data = json.loads(data_str)  # 多余的步骤
```

## 十、总结

### 核心要点

1. **双API架构**：
   - `claude_data_api.py` - 会话配置数据
   - `task_data_api.py` - 任务业务数据

2. **数据类型丰富**：
   - 10+种TaskDataType
   - 每种类型独立存储和查询
   - 支持批量操作

3. **多机共享**：
   - 通过COS实现数据共享
   - 机器IP和版本号管理
   - 支持任务迁移和负载均衡

4. **设计模式**：
   - 单例模式（客户端实例）
   - 工厂模式（get_default_client）
   - 策略模式（数据类型枚举）

5. **运维友好**：
   - 独立监控日志（monitor-rpc.log）
   - 详细的请求/响应日志
   - 环境变量配置

### 数据流总结

```
本地内存数据 ──save_or_update──> HTTP API ──> AI24 管理平台数据服务
                                                   │
                                                   │ 多机共享
                                                   ↓
本地内存数据 <──get_data_content─── HTTP API <── AI24 管理平台数据服务
```

结构化数据服务与 COS/OSS 文件备份共同构成 code-agent 多机部署的持久化基础设施。
