# 容错层详解

> 对应 [03-启动流程走读.md](./03-启动流程走读.md) 分层时序图里的 **容错层**。
> 容错层 = 注册信号处理器和退出回调，确保进程被 kill 或 Ctrl+C 时能优雅关闭。
> 入口：[main.py:3807-3811](../main.py#L3807-L3811) 信号处理器注册

---

## 一、容错层总览

```
环境层完成（环境变量就绪）
        │
        ▼
┌──────────────────────────────────────────┐
│  注册信号处理器 (main.py:3807-3811)       │
│                                          │
│  signal.signal(SIGTERM, handle_...)      │  ← kill 命令
│  signal.signal(SIGINT, handle_...)       │  ← Ctrl+C
│                                          │
│  当收到信号时 → handle_shutdown_signal() │
│    ├── 保存中断任务                       │
│    ├── 停止文件备份监听                   │
│    ├── 停止磁盘清理调度器                 │
│    ├── 清理 Figma MCP 进程                │
│    └── sys.exit(0)                       │
└──────────────────────────────────────────┘
        │
        ▼
    进入外设层（初始化 COS/Langfuse）
```

**一句话**：容错层不做业务，只干一件事——**捕获 SIGTERM/SIGINT 信号，保存中断任务，优雅退出**。

---

## 二、为什么需要容错层？

### 问题场景

```
场景1：服务部署时，运维执行 kill <pid>
  → 进程收到 SIGTERM 信号
  → 如果不处理，进程直接被杀
  → 正在执行的任务丢失，Claude 对话历史没保存

场景2：开发时按 Ctrl+C 停止服务
  → 进程收到 SIGINT 信号
  → 如果不处理，进程直接退出
  → 后台子进程（MCP Server）变成僵尸进程
```

### 解决方案

注册信号处理器，拦截 SIGTERM/SIGINT：
```python
signal.signal(signal.SIGTERM, handle_shutdown_signal)  # 拦截 kill
signal.signal(signal.SIGINT, handle_shutdown_signal)   # 拦截 Ctrl+C
```

当信号来临时，执行 `handle_shutdown_signal()` 做清理工作。

## 三、信号处理器注册

### 代码位置
[main.py:3807-3811](../main.py#L3807-L3811)

```python
# 注册信号处理器（必须在所有子进程启动前注册）
logger.info("正在注册信号处理器...")
signal.signal(signal.SIGTERM, handle_shutdown_signal)
signal.signal(signal.SIGINT, handle_shutdown_signal)
logger.info("信号处理器注册完成 (SIGTERM, SIGINT)")
```

### 两个信号的区别

| 信号 | 来源 | 场景 | 默认行为 |
|------|------|------|----------|
| **SIGTERM** | `kill <pid>` | 服务部署、优雅停机 | 终止进程 |
| **SIGINT** | `Ctrl+C` | 开发调试、手动停止 | 中断进程 |

**共同点**：都可以被捕获，都可以自定义处理逻辑。

**注意**：注释说"必须在所有子进程启动前注册"——因为子进程会继承父进程的信号处理器。如果先启动子进程，再注册信号处理器，子进程收不到信号处理。

## 四、信号处理逻辑 — handle_shutdown_signal()

### 代码位置
[main.py:80-121](../main.py#L80-L121)

### 完整代码走读

```python
def handle_shutdown_signal(signum, frame):
    """
    处理进程终止信号（SIGTERM, SIGINT）
    保存中断任务信息并清理子进程后退出
    """
    # 1. 获取信号名称（用于日志）
    signal_name = signal.Signals(signum).name
    logger.info(f"收到信号 {signal_name}，开始执行清理...")
    
    # 2. 保存中断任务（最重要！）
    try:
        TaskRecoveryManager.save_interrupted_tasks()
        logger.info("中断任务信息保存完成")
    except Exception as e:
        logger.error(f"保存中断任务信息失败: {str(e)}", exc_info=True)
    
    # 3. 停止所有文件备份监听
    try:
        logger.info("正在停止所有文件备份监听...")
        stop_all_backups()
        logger.info("所有文件备份监听已停止")
    except Exception as e:
        logger.error(f"停止文件备份监听失败: {str(e)}", exc_info=True)
    
    # 4. 停止磁盘清理调度器
    try:
        _disk_cleanup_scheduler.stop()
    except Exception as e:
        logger.error(f"停止磁盘清理调度器失败: {str(e)}", exc_info=True)
    
    # 5. 清理 Figma MCP HTTP 进程
    try:
        global _figma_mcp_proc
        if _figma_mcp_proc:
            logger.info("正在停止 Figma MCP HTTP 服务...")
            stop_figma_mcp_http(_figma_mcp_proc)
            logger.info("Figma MCP HTTP 服务已停止")
    except Exception as e:
        logger.error(f"停止 Figma MCP HTTP 服务失败: {str(e)}", exc_info=True)
    
    # 6. 退出进程
    logger.info("进程即将退出")
    sys.exit(0)
```

### 清理步骤详解

#### 步骤1：保存中断任务 ⭐️ 最关键

```python
TaskRecoveryManager.save_interrupted_tasks()
```

**作用**：
- 遍历 `ClaudeAgentSDKService` 中所有正在执行的任务
- 保存任务信息到 `tmp/data/interrupted_tasks.json`

**保存内容**：
```json
{
  "task_12345": {
    "task_id": "task_12345",
    "stage": "executing",           // 执行阶段：init/executing/waiting
    "task_type": "dev",              // 任务类型：dev/test/frontend
    "last_query": "实现用户登录功能",  // 最后一次查询内容
    "timestamp": "2026-07-07 10:30:00"
  }
}
```

**重启后恢复**：
- 服务重启时，`TaskRecoveryManager.recover_interrupted_tasks()` 读取这个文件
- 自动恢复被中断的任务，继续执行

#### 步骤2：停止文件备份监听

```python
stop_all_backups()
```

**作用**：
- 停止所有文件变更监听器（watchdog）
- 防止残留的文件监听占用资源

#### 步骤3：停止磁盘清理调度器

```python
_disk_cleanup_scheduler.stop()
```

**作用**：
- 停止定时任务调度器
- 防止后台线程继续运行

#### 步骤4：清理 Figma MCP 进程

```python
if _figma_mcp_proc:
    stop_figma_mcp_http(_figma_mcp_proc)
```

**作用**：
- 如果启动了 Figma MCP HTTP 服务，将其杀掉
- 防止子进程变成僵尸进程

#### 步骤5：退出进程

```python
sys.exit(0)
```

**作用**：
- 返回退出码 0（表示正常退出）
- 触发所有 `atexit` 注册的回调函数

## 五、atexit 回调 — 正常退出时的清理

除了信号处理器，还有 `atexit` 机制处理**正常退出**的清理。

### 代码位置
[main.py:3842](../main.py#L3842)

```python
# 注册服务关闭时的清理函数：将 /home/www/.claude 移动到 /home/www/logs/.claude
atexit.register(move_claude_project_on_shutdown)
```

### atexit vs 信号处理器

| 机制 | 触发时机 | 用途 |
|------|----------|------|
| **signal handler** | 收到 SIGTERM/SIGINT | 异常退出的清理 |
| **atexit** | `sys.exit()` 或程序正常结束 | 正常退出的清理 |

**调用链**：
```
收到 SIGTERM
  → handle_shutdown_signal()
    → TaskRecoveryManager.save_interrupted_tasks()
    → sys.exit(0)
      → atexit 回调
        → move_claude_project_on_shutdown()  # .claude 目录持久化
```

## 六、容错层的设计模式

### 1. 防御式编程

所有清理步骤都用 `try-except` 包裹：
```python
try:
    TaskRecoveryManager.save_interrupted_tasks()
except Exception as e:
    logger.error(f"保存中断任务信息失败: {str(e)}", exc_info=True)
```

**原因**：即使某个清理步骤失败，也不能阻塞其他清理步骤执行。

### 2. 优先级排序

清理步骤的顺序有讲究：
1. **最重要**：保存中断任务（业务数据）
2. **次要**：停止后台服务（防止资源泄漏）
3. **最后**：退出进程

### 3. 双重保障

```
异常退出：signal handler → 保存任务 → sys.exit(0) → atexit 回调
正常退出：直接 sys.exit(0) → atexit 回调
```

无论哪种退出方式，`atexit` 回调都会执行。

## 七、任务恢复机制 — TaskRecoveryManager

### 保存中断任务

**代码位置**：`TaskRecoveryManager.save_interrupted_tasks()`

**逻辑**：
```python
# 1. 获取所有正在执行的任务
service = ClaudeAgentSDKService.get_instance()
active_tasks = service.get_active_tasks()  # 返回 task_id 列表

# 2. 从 MetaContainer 获取任务详情
container = get_meta_container()
for task_id in active_tasks:
    metadata = container.get_task_metadata(task_id)
    # 保存到 interrupted_tasks.json

# 3. 持久化到磁盘
with open('tmp/data/interrupted_tasks.json', 'w') as f:
    json.dump(interrupted_tasks, f, indent=2)
```

### 恢复中断任务

**代码位置**：[main.py:3896-3901](../main.py#L3896-L3901)

**调用时机**：在服务启动的最后阶段（核心服务初始化完成后）

```python
# 恢复中断的任务
logger.info("正在检查是否有中断任务需要恢复...")
recovered_count = TaskRecoveryManager.recover_interrupted_tasks(run_query_task_in_thread)
if recovered_count > 0:
    logger.info(f"成功恢复 {recovered_count} 个中断任务")
else:
    logger.info("没有需要恢复的中断任务")
```

**逻辑**：
```python
# 1. 读取 interrupted_tasks.json
with open('tmp/data/interrupted_tasks.json') as f:
    tasks = json.load(f)

# 2. 为每个任务创建恢复线程
for task_id, task_info in tasks.items():
    run_query_task_in_thread(
        task_id=task_id,
        query=task_info['last_query'],  # 使用上次的查询
        resume=True                     # 标记为恢复任务
    )

# 3. 删除 interrupted_tasks.json（已恢复）
os.remove('tmp/data/interrupted_tasks.json')
```

## 九、小结：容错层做了什么

| 功能 | 输入 | 输出 | 作用 |
|------|------|------|------|
| 信号处理器注册 | SIGTERM/SIGINT | 自定义处理函数 | 拦截退出信号 |
| 保存中断任务 | 当前执行中的任务 | interrupted_tasks.json | 退出时保存状态 |
| 停止后台服务 | 运行中的子进程/线程 | 进程终止 | 防止资源泄漏 |
| atexit 回调 | 进程退出事件 | .claude 目录持久化 | 保存会话历史 |
| 任务恢复 | interrupted_tasks.json | 恢复执行 | 重启后继续任务 |

**容错层的本质**：它是服务可靠性的"安全网"——确保进程无论怎样退出，都能保存关键数据，清理后台资源，并在重启后恢复执行。
