# Code-Agent 项目启动流程详解

> 从 `python main.py` 到服务就绪的完整过程

**场景**：运维人员在服务器上首次启动 code-agent 服务  
**命令**：`python main.py`  
**状态**：此时没有任何任务，纯净启动

---

## 🚀 启动流程总览

```
python main.py
    ↓
阶段1: 环境设置与配置加载
    ↓
阶段2: 信号处理器注册
    ↓
阶段3: 云服务初始化（COS + Langfuse）
    ↓
阶段4: Claude 配置准备
    ↓
阶段5: 数据层初始化（单例创建）
    ↓
阶段6: Flask API 启动
    ↓
阶段7: 后台服务启动（心跳、调度器）
    ↓
✅ 服务就绪，监听端口，等待请求
```

**总耗时**：约 3-5 秒  
**阻塞点**：`app.run()` 会阻塞主线程

```python
def setup_runtime_environment():
    # 1. 加载 .env 文件
    load_dotenv()
    # 读取：
    # - LANGFUSE_PUBLIC_KEY
    # - LANGFUSE_SECRET_KEY
    # - COS_SECRET_ID
    # - COS_SECRET_KEY
    # - MANAGEMENT_API_BASE_URL
    # ... 等环境变量
    
    # 2. 解析命令行参数
    parser = argparse.ArgumentParser()
    parser.add_argument('--port', type=int, default=8080)
    parser.add_argument('--debug', action='store_true')
    args = parser.parse_args()
    
    # 3. 设置日志级别
    logging.basicConfig(
        level=logging.INFO,
        format='%(asctime)s [%(levelname)s] %(message)s'
    )
    
    # 4. 创建必要的目录
    os.makedirs('/tmp/.code-agent', exist_ok=True)
    os.makedirs('/tmp/projects', exist_ok=True)
    
    return args
```

#### 为什么必须第一个

- ✅ 后续所有步骤都依赖环境变量
- ✅ 日志配置影响所有日志输出
- ✅ 目录创建保证后续文件操作不出错

### 阶段2：信号处理器注册

**目的**：优雅处理 Ctrl+C 和 kill 信号

#### 做什么

```python
# 注册信号处理器（必须在所有子进程启动前注册）
def handle_shutdown_signal(signum, frame):
    logger.info(f"收到信号 {signum}，开始优雅关闭...")
    
    # 1. 停止 Flask 服务
    # 2. 保存正在执行的任务状态
    # 3. 停止文件监听器
    # 4. 清理临时文件
    # 5. 移动 .claude 目录到日志目录
    
    logger.info("服务已关闭")
    sys.exit(0)

# 注册
signal.signal(signal.SIGTERM, handle_shutdown_signal)  # kill 命令
signal.signal(signal.SIGINT, handle_shutdown_signal)   # Ctrl+C
```

#### 为什么重要

- ✅ 防止任务数据丢失
- ✅ 优雅清理资源
- ✅ 保存中断任务状态供后续恢复

### 阶段4：Claude 配置准备

#### 4.1 移动 claude_projects（历史遗留）

```python
def move_claude_project_on_startup():
    """
    将旧的 ~/.claude_projects/ 移动到 ~/.claude/projects/
    （历史版本遗留，新版本统一放在 ~/.claude/ 下）
    """
    old_path = os.path.expanduser('~/.claude_projects')
    new_path = os.path.expanduser('~/.claude/projects')
    
    if os.path.exists(old_path):
        shutil.move(old_path, new_path)
        logger.info(f"✅ 已移动 {old_path} → {new_path}")
```

#### 4.2 复制 Skills 到用户目录

```python
def copy_skills_to_user_claude_dir():
    """
    复制 .claude/skills/ → ~/.claude/skills/
    
    Skills 是 Claude 可以调用的技能（类似函数）
    """
    source = os.path.join(PROJECT_ROOT, '.claude', 'skills')
    target = os.path.expanduser('~/.claude/skills')
    
    # 清空目标目录
    if os.path.exists(target):
        shutil.rmtree(target)
    
    # 复制
    shutil.copytree(source, target)
    
    logger.info(f"✅ Skills 已同步到用户目录: {target}")
```

**Skills 示例**：
```
~/.claude/skills/
├── init-project/       ← 初始化项目技能
├── upload-document/    ← 文档上传技能
├── apply/              ← Apply 收尾流程
├── report-completion-metrics/ ← 完成量化指标 HTTP 上报
└── ...
```

`report-completion-metrics` 会随其他 Skill 一起从项目目录复制到 `~/.claude/skills`。当前 Skill 文档中的执行示例仍使用项目内相对路径，而任务通常在业务项目目录中运行，因此学习时要区分“源码目录中的脚本位置”和“部署后用户目录中的 Skill 位置”。

#### 7.1 恢复中断任务

```python
# 检查是否有中断任务需要恢复
logger.info("正在检查是否有中断任务需要恢复...")

    run_query_task_in_thread
```

**做什么**：
- 读取上次关闭前保存的任务状态
- 自动继续执行中断的任务

#### 7.2 启动机器状态心跳

```python
# 启动机器状态管理器心跳
try:
    machine_status_manager = get_machine_status_manager()
    machine_status_manager.start_heartbeat()
    logger.info("✅ 机器状态管理器心跳已启动")
    
    # 注册关闭时停止心跳
    atexit.register(machine_status_manager.stop_heartbeat)
except Exception as e:
    logger.error(f"启动机器状态管理器心跳失败: {str(e)}")
    logger.warning("服务将继续运行但无法上报机器状态")
```

**做什么**：
- 每隔 30 秒向 AI24 平台上报机器状态
- 上报内容：CPU、内存、磁盘、运行任务数

#### 7.3 启动磁盘清理调度器


## 🎯 启动流程总结

### 时间线

```
T0      : python main.py
T0 + 0.1s : 环境设置完成
T0 + 0.2s : 信号处理器注册完成
T0 + 0.5s : COS + Langfuse 初始化完成
T0 + 1.0s : Claude 配置同步完成
T0 + 1.5s : 中断任务检查完成
T0 + 2.0s : 心跳 + 调度器启动完成
T0 + 3.0s : Flask 启动完成
T0 + 3.0s+: 服务就绪，阻塞等待请求
```

**总耗时**：约 3 秒

### 依赖关系

```
setup_runtime_environment()  ← 必须第一个
    ↓
signal.signal() + init_coscmd_config() + init_langfuse()  ← 可并行
    ↓
copy_skills + copy_agents + copy_settings  ← 可并行
    ↓
recover_interrupted_tasks()  ← 依赖配置文件
    ↓
start_heartbeat() + start_scheduler()  ← 可并行
    ↓
app.run()  ← 必须最后
```

### 关键设计

1. **主动初始化**：核心单例在启动时创建，不是首次请求时懒加载
2. **信号处理**：优雅关闭，防止数据丢失
3. **配置同步**：Claude 配置复制到用户目录
4. **任务恢复**：自动恢复中断任务
5. **心跳上报**：让 AI24 平台知道机器状态
6. **磁盘清理**：防止磁盘空间耗尽
