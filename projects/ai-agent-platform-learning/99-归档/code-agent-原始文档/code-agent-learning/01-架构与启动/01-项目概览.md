# Code-Agent 项目概览

## 一、项目定位

**DevSecOps 多智能体平台** - 基于 Claude Agent SDK 构建的自动化代码生成和任务执行平台，提供 Flask API 服务。

### 核心价值
- 自动从 DEP 任务系统拉取需求并初始化项目
- 使用 OpenSpec 规范驱动开发工作流
- 支持前后端工作流
- 集成设计工具（Figma/MasterGo）用于前端界面还原
- 支持多机分布式任务调度（基于 Redis Pub/Sub）

## 三、核心模块详解

### 3.1 API 层 (main.py)

**主要 API 端点：**

| 端点 | 方法 | 功能 | 关键代码行 |
|------|------|------|-----------|
| `/task/perform` | POST | 初始化任务 | 222-279 |
| `/task/query` | POST | 执行查询任务 | 281-316 |
| `/task/stop` | POST | 中断任务 | 318-344 |
| `/test/task/perform/init` | POST | 初始化测试任务 | 395-446 |

**核心函数：**
- `fetch_task_metadata_from_dep_id()` (1047-1207) - 从 DEP 拉取任务元数据
- `init_task_project()` (733-771) - 初始化项目代码和 OpenSpec
- `execute_query_task()` (873-1043) - 执行查询任务
- `intercept_and_replace_prompt()` (395-622) - OpenSpec 命令拦截和提示词注入

### 3.2 Claude SDK 服务 (claude_agent_sdk_wrapper.py)

**ClaudeAgentSDKService** - 单例模式封装 Claude Agent SDK

**核心能力：**
- Session 生命周期管理
- 任务执行和中断
- Token 使用监控（超过 85% 自动 compact）
- MCP 工具集成

**关键方法：**
- `create_session()` - 创建新会话
- `execute_task()` - 执行任务
- `interrupt_task()` - 中断任务
- `_check_and_compact_if_needed()` - 自动压缩上下文

### 3.3 元数据管理 (meta_container.py)

**MetaContainer** - 任务元数据管理器（单例，持久化到磁盘）

**存储内容：**
```python
{
    "task_id": {
        "dep_id": "123",
        "git_url": "git@github.com:user/repo.git",
        "branch": "feature/xxx",
        "project_dir": "/path/to/project",
        "prd_content": "需求文档...",
        "flow_type": "backend|frontend_common|test",
        "figma_file_key": "xxx",  # 前端任务
        "mastergo_link": "xxx",   # 前端任务
        "template_id": "xxx"      # 自定义模板
    }
}
```

**持久化路径：** `tmp/data/task_metadata.json`

### 3.4 路径管理 (path_manager.py)

**PathManager** - 统一路径管理器

**核心路径结构：**
```
Project Root/
└── tmp/
    ├── projects/
    │   └── {task_id}/
    │       ├── prd.md                    # PRD 文档
    │       └── {project_name}/           # 克隆的项目代码
    │           └── openspec/             # OpenSpec 规范目录
    └── data/
        ├── task_metadata.json            # 任务元数据
        ├── task_session_mapping.json     # task_id↔session_id 映射
        └── stopwatch/                    # 任务执行时间记录
            └── {task_id}.json
```

**关键方法：**
- `get_task_project_dir()` - 获取任务项目目录
- `get_prd_path()` - 获取 PRD 文档路径
- `get_openspec_dir()` - 获取 OpenSpec 目录

### 3.5 OpenSpec 工作流

**三大核心命令：**

1. **`/openspec:proposal`** - 创建变更提案
   - 需求分析 → 技术设计 → 测试设计 → 任务列表

2. **`/openspec:apply`** - 实施变更提案
   - 编码 → 测试 → 提交 → 报告

3. **`/openspec:archive`** - 归档已部署变更

**三套模板：**
- `openspec/` - 通用后端工作流
- `openspec_frontend/` - 前端工作流（需要 UI 设计）
- `openspec_test/` - 测试工作流

### 3.6 消息渲染和报告

**双渲染器架构：**

1. **本地渲染** (`claude_message_renderer.py`)
   - 保存到本地日志文件
   - 三种格式：cli / openhands / event

2. **远程报告** (`message_reporter.py`)
   - 上报到管理平台 API
   - 支持富文本格式（Markdown）

### 3.7 多机任务分发 (redis_pubsub_service.py)

**基于 Redis Pub/Sub 的任务路由：**

```
机器A                机器B                机器C
   ↓                   ↓                   ↓
   └───────────────────┴───────────────────┘
                       │
              Redis Pub/Sub Channel
         (code_agent_global_tasks)
                       │
       ┌───────────────┼───────────────┐
       ↓               ↓               ↓
   检查任务归属    检查任务归属    检查任务归属
   (MetaContainer) (MetaContainer) (MetaContainer)
       │               │               │
   本机任务          其他机器          其他机器
   (执行)            (忽略)            (忽略)
```

## 四、关键流程图

### 4.1 任务初始化流程

```
HTTP POST /task/perform
        ↓
从 DEP 拉取元数据 (dep_id → git_url, branch, prd)
        ↓
克隆代码仓库
        ↓
复制 OpenSpec 模板到项目根目录
        ↓
保存任务元数据到 MetaContainer
        ↓
发布任务到 Redis (如果配置)
        ↓
返回 task_id
```

### 4.2 任务执行流程

```
HTTP POST /task/query
        ↓
检查任务归属 (本机/远程)
        ↓
[本机任务]
        ↓
预处理命令 (OpenSpec 命令、自定义命令、文件引用)
        ↓
调用 ClaudeAgentSDKService 执行
        ↓
双渲染器：本地日志 + 远程报告
        ↓
返回执行结果
```

### 4.3 OpenSpec Proposal 流程

```
用户输入需求
        ↓
/openspec:proposal 命令拦截
        ↓
注入 Prompt 模板 (openspec/prompts/proposal.md)
        ↓
Claude 生成变更提案
  ├── 需求分析 (PRD 解读)
  ├── 技术设计 (API 设计、数据结构)
  ├── 测试设计 (测试用例)
  └── 任务列表 (开发步骤)
        ↓
保存到 openspec/changes/xxx.md
```

### 4.4 OpenSpec Apply 流程

```
/openspec:apply 命令
        ↓
读取变更提案 (openspec/changes/xxx.md)
        ↓
注入 Prompt 模板 (openspec/prompts/apply.md)
        ↓
Claude 执行开发任务
  ├── 编写代码
  ├── 运行测试
  ├── Git 提交
  └── 生成报告
        ↓
上报到管理平台
```

## 六、核心设计模式

### 6.1 单例模式
以下服务使用单例模式（线程安全）：
- `ClaudeAgentSDKService`
- `MetaContainer`
- `RedisPubSubService`
- `RedisManager`

### 6.2 命令拦截模式
通过 `intercept_and_replace_prompt()` 实现：
- 拦截 OpenSpec 命令
- 注入对应的 Prompt 模板
- 支持文件引用 (`@filename`)

### 6.3 双渲染器模式
消息同时：
- 保存到本地日志文件
- 上报到远程管理平台

### 6.4 发布订阅模式
使用 Redis Pub/Sub 实现多机任务分发

## 七、关键技术点

### 7.1 Session 持久化
- `task_id ↔ session_id` 双向映射
- 支持多轮对话
- 持久化到磁盘

### 7.2 Token 管理
- 自动监控 Token 使用率
- 超过 85% 自动执行 `/compact`

### 7.3 任务恢复
- SIGTERM/SIGINT 信号捕获
- 保存中断任务信息
- 下次启动自动提示恢复

### 7.4 MCP 工具集成
- **内置 MCP (stdio)**：code-agent-report-tools, mastergo
- **外部 MCP (SSE/HTTP)**：ai24、confluence、context1、Zeus、Zeus-CI、UI/集成测试等
- **Skills**：`report-completion-metrics` 提供另一条直接 HTTP 上报量化指标的路径

> 当前完成指标上报处于迁移期：旧 `code-agent-report-tools` MCP 仍然注册，`apply` 相关 Skill 也仍调用旧 MCP；新增 Skill 尚未完全替代旧链路。

### 7.5 前端工作流
- 支持 Figma（官方远程 MCP Server）
- 支持 MasterGo（stdio MCP 工具）
- 自动注入前端特定提示词

## 十、常见问题

### Q1: 为什么有三套 OpenSpec 模板？
- `openspec/` - 后端开发（API、服务）
- `openspec_frontend/` - 前端开发（需要 UI 设计工具）
- `openspec_test/` - 测试用例生成（需要技术设计文档）

### Q2: 任务是如何分配到不同机器的？
- 每个任务在初始化时会被某台机器的 `MetaContainer` 记录
- 该任务的所有后续操作都由该机器处理
- 其他机器通过 Redis 收到任务消息后，检查 `MetaContainer`，发现不是自己的任务就忽略

### Q3: 为什么需要 PathManager？
- 统一路径管理，避免硬编码
- 支持路径兼容模式（旧路径优先，新路径兜底）
- 便于后续路径规则调整

### Q4: 消息为什么要双渲染？
- 本地日志：方便开发调试
- 远程报告：供管理平台展示给用户
