## 1. 架构设计类

### Q1.1: 为什么 ai24 用 Java，code-agent 用 Python？

**回答要点：**
- **ai24 (Java/Spring Boot)**：
  - 企业级后台，需要强类型、事务管理、权限控制
  - Spring 生态成熟：MyBatis Plus、Spring Security、@Transactional
  - 适合复杂业务逻辑（审批流、工作流配置）
  
- **code-agent (Python/Flask)**：
  - AI 交互侧，Python 生态丰富
  - Claude SDK、Langfuse、MCP 工具都是 Python 优先
  - 快速集成、动态语言灵活处理 JSON/Hook

**代码位置：**
- ai24: `ai24-core/src/main/java/com/vdian/ai24/core/service/TaskCreateOrchestrator.java:43`
- code-agent: `code-agent/main.py:3799`

---

### Q1.2: 两个服务如何通信？为什么不用 RPC？

**回答要点：**
- **HTTP POST 通信**：
  - ai24 → code-agent: `POST /task/perform`, `POST /task/query`
  - code-agent → ai24: `POST /api/task/notify/taskStatus`, `POST /api/task/notify/sessionComplete`

- **为什么不用 RPC (gRPC/Dubbo)？**
  - **跨语言**：Java ↔ Python，HTTP 最通用
  - **解耦**：code-agent 可能崩溃/重启，HTTP 容错更好
  - **异步**：ai24 发请求后立即返回 202，不阻塞

**代码位置：**
- ai24 发送: `ai24-core/src/main/java/com/vdian/ai24/core/service/impl/TaskPerformServiceImpl.java:88`
- code-agent 接收: `code-agent/main.py:230` (TaskPerformResource.post)

**追问：HTTP 性能不如 RPC，怎么优化？**
- **连接池复用**：RestTemplate 配置 HttpClient 连接池
- **异步处理**：接口立即返回 202，后台线程执行
- **流式推送**：通过 WebSocket 推送结果，不走轮询

---

### Q1.3: code-agent 如果挂了怎么办？

**回答要点：**

**1. 心跳机制**
- `machine_status_manager` 每 N 秒上报心跳到 ai24
- ai24 检测心跳超时，标记机器离线
- 路由层不再分配新任务到该机器

**代码位置：**
- code-agent: `code-agent/machine_status_manager.py:169` (_heartbeat_worker)
- 上报到: `POST /api/agentMachine/heartbeat`

**2. 任务恢复机制**
- **MetaContainer**：存储任务元数据（session_id、project_path）
- **COS 云存储**：任务目录定期备份到 COS
- **查询前恢复**：`BackupRestoreManager` 检查任务目录、PRD 和 Claude 会话文件，按资源类型从 COS、DEP/OSS 或 Git 恢复

**代码位置：**
- code-agent: `code-agent/main.py:3827` (启动时恢复)

**3. 任务迁移**
- ai24 检测到机器离线后，将任务状态改为 FAILED
- 用户可以手动重试，路由到健康机器

## 2. 并发与线程安全

### Q2.1: TaskCreateOrchestrator 是单例，会有并发问题吗？

**回答要点：**

**1. 是单例**
```java
@Component  // Spring 默认 singleton scope
public class TaskCreateOrchestrator {
    // 所有请求共享同一个实例
}
```

**2. 为什么线程安全？**
- **无状态设计**：所有参数通过方法传入，不依赖成员变量
- **依赖注入的 Bean 都是单例且线程安全**：
  - `TaskInfoManager`: MyBatis Plus，数据库连接从连接池获取
  - `TaskIdGenerator`: 雪花算法，内部有同步机制

**3. 如果不安全会怎样？**
假设有成员变量：
```java
private String currentTaskId;  // 错误！多线程会互相覆盖
```
线程 A 设置 `currentTaskId = "t-001"`，线程 B 可能读到这个值。

**代码位置：**
- `ai24-core/src/main/java/com/vdian/ai24/core/service/TaskCreateOrchestrator.java:43`

---

### Q2.2: 雪花算法如何保证 taskId 唯一？

**回答要点：**
- **雪花算法结构**：64 位 = 1位符号 + 41位时间戳 + 10位机器ID + 12位序列号
- **并发安全**：序列号在同一毫秒内递增，有 synchronized 锁
- **分布式唯一**：不同机器的 workerId 不同

**代码位置：**
- `ai24-core/src/main/java/com/vdian/ai24/core/service/TaskIdGenerator.java`

**追问：如果同一毫秒生成超过 4096 个 ID 怎么办？**
- 等待下一毫秒（自旋或阻塞）

---

### Q2.3: code-agent 的线程模型是什么？

**回答要点：**

**1. Flask 多线程处理请求**
```python
app.run(host='0.0.0.0', port=8080)
# 默认每个请求一个线程
```

**2. 任务执行用独立线程**
```python
thread = threading.Thread(target=run_init_task_via_claude, args=(task_id,))
thread.daemon = True
thread.start()
return {'success': True}, 202  # 立即返回
```

**3. 为什么用 daemon=True？**
- 守护线程：主线程退出时不等待它
- 避免任务执行失败时 Flask 线程被阻塞

**4. 会有并发问题吗？**
- **不同任务之间隔离**：每个任务有独立的 project_path、session_id
- **同一任务不会并发执行**：ai24 保证同一 taskId 不会同时发多个请求

**代码位置：**
- `code-agent/main.py:230` (TaskPerformResource.post)

## 3. 数据一致性

### Q3.1: 事务边界在哪里？如何保证一致性？

**回答要点：**

**1. 事务边界：Service 层**
```java
@Transactional(rollbackFor = Exception.class)
public String createTask(...) {
    return taskCreateOrchestrator.createTask(...);
}
```

**2. 事务范围：**
- INSERT task_info
- INSERT task_record (用户消息)
- INSERT approval_item (如果有审批)

**3. HTTP 调用在事务外**
```java
// 事务内：保存到数据库
taskInfoManager.save(taskInfoDO);
taskRecordService.createUserMessageRecord(...);

// 事务外：调用 code-agent
taskPerformService.performTask(...);  // HTTP 请求
```

**4. 为什么 HTTP 调用不在事务内？**
- **避免长事务**：HTTP 可能很慢，锁表时间长
- **容错**：code-agent 失败不回滚数据库，任务状态可以改为 FAILED

**代码位置：**
- `ai24-core/src/main/java/com/vdian/ai24/core/service/impl/TaskInfoServiceImpl.java:119`

**追问：如果 HTTP 调用失败，数据库怎么办？**
- **补偿机制**：捕获异常，更新 task_info.status = FAILED
- **用户可重试**：前端重新提交

---

### Q3.2: 分布式事务问题：ai24 和 code-agent 如何保证一致性？

**回答要点：**

**1. 不追求强一致性**
- ai24 保存任务后，异步通知 code-agent
- code-agent 执行失败，上报状态到 ai24

**2. 最终一致性**
- **状态机驱动**：INIT → IN_PROGRESS → SUCCESS / FAILED
- **上报机制**：code-agent 通过 `/api/task/notify/taskStatus` 上报

**3. 如果 code-agent 收到请求但崩溃了怎么办？**
- **心跳检测**：ai24 检测到机器离线
- **超时机制**：任务超过 N 分钟无心跳，标记为 TIMEOUT
- **用户重试**：重新路由到健康机器

**代码位置：**
- code-agent 上报: `code-agent/message_reporter.py`

## 4. 异常处理与容错

### Q4.1: code-agent 调用 Claude SDK 失败怎么处理？

**回答要点：**

**1. SDK 内部有重试机制**
- 网络错误、429 限流：自动重试
- 5xx 错误：指数退避重试

**2. code-agent 层的容错**
```python
try:
    await service.query(task_id, prompt, ...)
except Exception as e:
    logger.error(f"Task {task_id} failed: {e}")
    MessageReporter.report_session_status(FAILED, error_msg=str(e))
```

**3. ai24 看到 FAILED 状态后**
- 展示错误信息给用户
- 用户可以重试

**代码位置：**
- `code-agent/main.py:1819` (execute_query_task)

---

### Q4.2: Hook 拦截失败会怎样？

**回答要点：**

**1. Hook 返回 deny 时**
- SDK 不执行工具，返回拒绝理由给 Claude
- Claude 看到拒绝理由，调整行为或报告给用户

**2. Hook 执行异常时**
- 捕获异常，记录日志
- **默认通过**（fail-open），避免阻塞正常流程

**代码位置：**
- `code-agent/hooks/path_security_hook.py`

**追问：为什么是 fail-open 而不是 fail-close？**
- **可用性优先**：Hook bug 不应该导致所有任务失败
- **安全关键的 Hook 可以 fail-close**

---

### Q4.3: CompleteStageClient 的重试机制

**回答要点：**

**1. 指数退避重试**
```python
@retry_with_backoff(max_retries=3, base_delay=1.0, max_delay=30.0)
def complete_stage(self, task_id: str, command: str):
    response = requests.post(url, params=params, timeout=10)
```

**2. 重试策略**
- 第 1 次失败：等 1 秒重试
- 第 2 次失败：等 2 秒重试
- 第 3 次失败：等 4 秒重试
- 第 4 次失败：抛出异常

**3. 失败后怎么办？**
- 记录日志，**不阻塞主流程**
- ai24 会通过心跳检测任务超时

**代码位置：**
- `code-agent/hooks/stop_hook_complete_stage.py:86`

## 5. 性能优化

### Q5.1: 如何支持高并发？

**回答要点：**

**1. 无状态设计**
- ai24: 所有 Service 都是单例无状态，可水平扩展
- code-agent: Flask 多进程部署（Gunicorn）

**2. 数据库连接池**
- HikariCP 连接池（Spring Boot 默认）
- 最大连接数 = CPU 核心数 × 2

**3. 异步化**
- ai24 调用 code-agent 立即返回 202
- code-agent 用独立线程执行任务

**4. 缓存**
- 工作流配置缓存（spec_workflow）
- 用户权限缓存

**追问：如果任务量暴增怎么办？**
- **ai24**: 增加 Pod 副本数（K8s HPA）
- **code-agent**: 增加机器数，心跳上报可用机器
- **数据库**: 读写分离、分库分表

---

### Q5.2: 流式推送如何优化？

**回答要点：**

**1. 当前架构**
```
Claude 流式输出 → SDK 短连接 POST → code-agent → ai24 → WebSocket → 前端
```

**2. 为什么不直接 WebSocket？**
- **Claude SDK 不支持 WebSocket**
- **中间需要过 Hook 检查、内容过滤**

**3. 优化点**
- **批量推送**：积累 N 个 token 或 N 毫秒后再推送
- **压缩**：长文本 gzip 压缩
- **WebSocket 连接池复用**

**代码位置：**
- `code-agent/message_reporter.py`

---

### Q5.3: 数据库查询优化

**回答要点：**

**1. 索引优化**
- task_info: 索引 (taskId), (username, createTime)
- task_record: 索引 (taskId, recordId)

**2. 分页查询**
```java
Page<TaskInfoDO> page = taskInfoManager.page(
    new Page<>(pageNum, pageSize),
    queryWrapper
);
```

**3. 避免 N+1 查询**
- 一次查询 task_info，join 查询 task_record

**追问：如果单表数据量过亿怎么办？**
- **分库分表**：按 taskId hash 或按时间分表
- **冷热数据分离**：旧任务归档到 Hive

## 6. 安全性

### Q6.1: PathSecurityHook 如何防止目录穿越？

**回答要点：**

**1. 黑名单机制**
```python
PROTECTED_PATHS = ["/home/www/.claude/projects", "/etc", "/var", "/root"]

def check_permission(tool_name, params):
    path = extract_path_from_params(params)
    abs_path = os.path.abspath(path)  # 解析 .. 符号
    for protected in PROTECTED_PATHS:
        if abs_path.startswith(protected):
            return PermissionResultDeny(reason=f"禁止访问: {protected}")
```

**2. 为什么用 os.path.abspath？**
- 防止 `../../etc/passwd` 穿越

**3. 为什么黑名单而不是白名单？**
- **灵活性**：任务可能访问多个项目目录
- **白名单需要动态配置**：每个任务的 project_path 不同

**代码位置：**
- `code-agent/hooks/path_security_hook.py`

**追问：黑名单会不会被绕过？**
- 可能，建议**白名单 + 黑名单双重检查**

### Q6.2: GitCommitAuthorHook 为什么强制 --author？

**回答要点：**

**1. 审计需求**
- 所有代码提交必须标记为 Claude 提交
- 方便回溯：哪些代码是 AI 生成的

**2. 实现方式**
```python
def check_git_commit(tool_name, params):
    if "git commit" in command and "--author" not in command:
        return {"type": "deny", "reason": "请添加 --author 参数"}
```

**3. 为什么不直接配置 git config？**
- **任务隔离**：每个任务可能提交到不同仓库
- **灵活性**：不同任务可以用不同 author

**代码位置：**
- `code-agent/hooks/git_commit_author_hook.py`

if (!StringUtils.hasText(request.getInput())) {

## 7. 监控与运维

### Q7.1: 如何监控任务执行状态？

**回答要点：**

**1. 三条上报链路**
- **心跳**：机器健康度（CPU、内存、任务数）
- **状态**：任务状态（IN_PROGRESS、SUCCESS、FAILED）
- **内容**：Claude 输出流式内容

**2. 指标监控**
- 任务成功率、平均耗时
- Claude API 调用量、Token 消耗
- 机器负载（通过心跳上报）

**3. 日志**
- Langfuse: Claude 对话日志
- ELK: 应用日志（ai24 + code-agent）

**代码位置：**
- `code-agent/machine_status_manager.py` (心跳)
- `code-agent/message_reporter.py` (状态+内容)

---

### Q7.2: 如何定位任务执行失败的原因？

**回答要点：**

**1. 查看 task_record**
- 记录 Claude 的每次输入输出
- 记录工具调用记录

**2. 查看 Langfuse**
- 完整对话历史
- Token 消耗、延迟

**3. 查看应用日志**
- code-agent 日志：Hook 拦截、异常堆栈
- ai24 日志：审批流程、工作流状态

**追问：如何快速定位是哪个环节出问题？**
- **状态码**：通过 task_info.status 判断
- **关键字搜索**：在日志中搜索 taskId

---

### Q7.3: 如何灰度发布新版本？

**回答要点：**

**1. ai24 灰度**
- K8s 滚动更新：先发 1 个 Pod，观察 5 分钟
- 流量切换：通过 Ingress 控制流量比例

**2. code-agent 灰度**
- 机器分组：10% 机器先升级
- 任务路由：新任务优先路由到新版本机器
- 心跳检测：新版本机器异常立即下线

**3. 回滚策略**
- K8s Deployment 回滚
- 数据库表结构兼容：新字段允许 NULL

## 🎯 高频追问题

### 1. 如果让你优化这个系统，你会怎么做？

**回答思路：**
- **性能**：批量推送、缓存优化、数据库分库分表
- **可靠性**：任务重试机制、降级策略
- **安全**：白名单 + 黑名单、敏感信息脱敏

**回答思路：**
- **队列缓冲**：任务进入队列，逐个执行
- **限流器**：Guava RateLimiter
- **提示用户**：当前排队中，预计等待时间

### 3. 如果要支持多租户隔离怎么做？

**回答思路：**
- **数据隔离**：task_info 增加 tenantId 字段
- **资源隔离**：不同租户的任务路由到不同机器
- **权限隔离**：用户只能看到自己租户的任务
