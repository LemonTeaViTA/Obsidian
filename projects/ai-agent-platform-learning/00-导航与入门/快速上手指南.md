# 快速上手指南

> 5分钟了解 AI Agent 平台的核心概念和使用方式

---

## 🎯 这是什么？

这是一个完整的 **AI Agent 开发平台**，包含三个核心系统：

```
┌─────────┐  HTTP   ┌──────────┐  HTTP   ┌────────────┐
│  前端    │ ──────> │  ai24    │ ──────> │ code-agent │
│ (React) │ <────── │  (Java)  │ <────── │  (Python)  │
└─────────┘         │ 任务管理  │         │ AI 执行    │
                    └──────────┘         └────────────┘
```

**用一句话解释**：
- 用户在前端创建任务
- ai24 管理任务（存储、工作流、审批）
- code-agent 执行任务（调用 Claude AI）

---

## 🚀 核心流程（1分钟版）

### 创建任务

```
1. 用户在前端填写表单
   - 任务名：开发登录功能
   - 任务类型：backend
   - 工作流：后端TDD
   
2. 前端调用 ai24 API
   POST /api/taskInfo/create
   
3. ai24 存储任务信息
   - task_info 表 (status=0)
   
4. ai24 下发给 code-agent
   POST /task/perform
   
5. code-agent 执行
   - 初始化项目
   - 调用 Claude AI
   - 生成代码
   
6. 回调上报状态
   - status: 0 → 100 → 500
   
7. 前端实时更新
   - WebSocket 推送状态
```

## 🎓 5个核心概念

### 1. 任务（Task）

```java
// 任务就是一个数据库记录
{
  taskId: "T001",
  taskName: "开发登录功能",
  status: 0,  // 0=初始, 100=执行中, 500=完成
  input: "{...}" // JSON 格式的参数
}
```

### 2. 工作流（Workflow）

```
不同任务类型有不同的工作流：
- 后端开发：PRD审核 → 领域划分 → 应用拆分 → 开发 → 测试
- 前端开发：设计审核 → 组件拆分 → 开发 → UI测试
```

### 3. 审批（Approval）

```
每个阶段完成后需要审批：
- code-agent 上报产物
- 产品/测试审批
- 审批通过 → 进入下一阶段
- 审批拒绝 → 打回重做
```

### 4. 状态机（State Machine）

```
0 → 100 → 200 → 500
↓    ↓    ↓     ↓
初始  初始化 执行中 完成
      完成

任何阶段都可能 → -1 (失败)
```

### 5. MCP 工具（Model Context Protocol）

```
code-agent 通过 MCP 调用各种工具：
- Shell 工具：执行命令
- HTTP 工具：调用 API
- File 工具：读写文件
- Git 工具：管理代码
```

## ❓ 常见问题

### Q1: 为什么有三个系统？

**A**: 职责分离，各司其职
- 前端：用户交互
- ai24：任务管理、工作流、权限
- code-agent：AI 执行，可以独立扩展

### Q2: ai24 和 code-agent 如何通信？

**A**: HTTP + 回调
- ai24 → code-agent: POST /task/perform (下发任务)
- code-agent → ai24: POST /api/task/notify/* (上报状态)

### Q3: 前端如何实时看到进度？

**A**: WebSocket
- ai24 收到 code-agent 回调后
- 通过 WebSocket 推送给前端
- 前端更新进度条

### Q4: 工作流配置在哪里？

**A**: 数据库表
- spec_workflow: 工作流配置
- spec_stage: 阶段配置
- spec_convention: 约束规范

### Q5: 如何调试？

**A**: 三个入口
- 前端：浏览器 DevTools
- ai24: IDEA 断点调试
- code-agent: PyCharm 断点 + 日志
