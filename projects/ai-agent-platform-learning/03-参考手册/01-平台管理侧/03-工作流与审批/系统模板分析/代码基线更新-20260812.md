4. **产物协同机制**
   - 新增 `updateArtifactContent()` - 修改产物并评估下游影响
   - 新增 `updateArtifactContentOnly()` - 仅修改当前任务产物

## 三、Code Agent 主要功能变化

### 3.1 Web 视觉验证工具重构 ⭐️⭐️⭐️

**影响范围**：原调研报告第五节"前端模板调研结论"第 7-8 条关于视觉验证的问题

#### 核心变化

1. **Figma 官方 MCP 对接**
   - 新增 `ui_mcp_type='figma'` 路由至官方 MCP (`https://mcp.figma.com/mcp`)
   - 支持 OAuth 2.0 认证（替代 PAT）
   - 新增工具：`get_code`（设计转代码）、`get_screenshot`、`get_variable_defs`

2. **MCP 工具分离**
   - 原有 `figma_pat` 方案保留（向后兼容）
   - 新增独立的 Web Validation MCP Server
   - 新增 `web_validation_build_assets` 工具

3. **节点级验证流程 V3**
   - 新增 `/web-validation-node` 独立阶段
   - 强制使用 Figma 官方 MCP（不支持 MasterGo）
   - 引入 `assetRef` 机制（短引用 + 服务端存储）
   - 严格的 selector preflight 验证

#### 对原调研结论的影响

**原结论 7（第 87 段）**："视觉验证使用的 UI Test Automation 和 Figma 工具名与当前工厂声明存在差异"
- **部分解决**：Figma 官方 MCP 已上线，工具名已更新
- **仍需确认**：
  - UI Test Automation MCP 工具列表是否包含 `ui_task_batch_create`、`ui_task_execute`、`ui_task_detail`
  - 远程 MCP 的实际工具列表（需要线上确认）

**原结论 8（第 88-90 段）**："模板要求精确视觉差异率，但提交给 UI Test 平台的配置关闭了平台视觉对比"
- **新方案变化**：V3 节点验证流程引入独立的资产构建和提交机制
- **建议**：重新核对 `web_validation_submit_assets` 工具的视觉对比配置
