# 环境配置

## 概述

AI Agent Platform 前端项目使用 Vite 作为构建工具，支持通过环境变量配置不同的运行环境（开发、预发布、生产）。环境变量控制后端API地址、功能开关、第三方服务配置等关键参数。

## 核心文件

- **环境变量示例**: `/.env.sample`
- **Vite配置**: `/vite.config.ts`
- **TypeScript配置**: `/tsconfig.json`
- **API地址工具**: `/src/utils/api-base-url.ts`

## 环境变量配置

### 1. 环境变量文件

项目支持多个环境变量文件：

```
.env                 # 所有环境的默认配置
.env.local           # 本地开发配置（不提交到Git）
.env.development     # 开发环境配置
.env.production      # 生产环境配置
.env.sample          # 环境变量示例（提交到Git）
```

**加载优先级**（从高到低）:
1. `.env.{mode}.local` （如 `.env.development.local`）
2. `.env.{mode}` （如 `.env.development`）
3. `.env.local`
4. `.env`

### 2. 环境变量列表

#### 后端配置

```bash
# 后端URL（不含协议）
VITE_BACKEND_BASE_URL="localhost:3000"

# 后端主机地址（用于API连接）
VITE_BACKEND_HOST="127.0.0.1:3000"

# 是否使用TLS（HTTPS/WSS）
VITE_USE_TLS="false"

# 前端运行端口
VITE_FRONTEND_PORT="3001"

# 跳过TLS证书验证（开发环境）
VITE_INSECURE_SKIP_VERIFY="false"
```

#### 功能开关

```bash
# 启用API Mock（使用MSW模拟API）
VITE_MOCK_API="false"

# 模拟SaaS模式
VITE_MOCK_SAAS="false"
```

#### 新后端API配置

```bash
# ============================================
# 新后端API配置（渐进式迁移）
# ============================================

# 全局开关 - 启用所有新API
VITE_USE_NEW_API="false"

# 新后端服务器URL（带协议）

# 新API请求超时时间（毫秒）

# 模块级开关 - 独立控制每个模块
VITE_NEW_API_AUTH="false"           # 认证API
```

#### GMS WebSocket配置

```bash
# GMS (Global Message Service) WebSocket地址

```


### 3. 环境变量使用

在代码中通过 `import.meta.env` 访问环境变量：

```typescript
// 读取环境变量
const apiBaseUrl = import.meta.env.VITE_BACKEND_BASE_URL;
const useTLS = import.meta.env.VITE_USE_TLS === "true";
const frontendPort = import.meta.env.VITE_FRONTEND_PORT;

// 环境变量类型定义
interface ImportMetaEnv {
  readonly VITE_BACKEND_BASE_URL: string;
  readonly VITE_BACKEND_HOST: string;
  readonly VITE_USE_TLS: string;
  readonly VITE_FRONTEND_PORT: string;
  readonly VITE_MOCK_API: string;
  readonly VITE_MOCK_SAAS: string;
  readonly VITE_GMS_WS_URL: string;
  // ... 其他环境变量
}

interface ImportMeta {
  readonly env: ImportMetaEnv;
}
```

## 多环境配置

### 1. 开发环境 (.env.development)

```bash
# 开发环境配置
VITE_BACKEND_BASE_URL="localhost:3000"
VITE_BACKEND_HOST="127.0.0.1:3000"
VITE_USE_TLS="false"
VITE_FRONTEND_PORT="3001"
VITE_MOCK_API="false"
VITE_GMS_WS_URL="wss://link.daily.weidian.com/gms_ws"
```

**特点**:
- 使用本地后端服务
- 不使用TLS加密
- 可选启用API Mock进行前端独立开发

### 2. 预发布环境 (.env.staging)

```bash
# 预发布环境配置
VITE_BACKEND_BASE_URL="staging-api.example.com"
VITE_BACKEND_HOST="staging-api.example.com"
VITE_USE_TLS="true"
VITE_FRONTEND_PORT="3001"
VITE_MOCK_API="false"
VITE_GMS_WS_URL="wss://link-staging.weidian.com/gms_ws"
```

**特点**:
- 连接预发布后端
- 启用TLS加密
- 不使用Mock数据

### 3. 生产环境 (.env.production)

```bash
# 生产环境配置
VITE_BACKEND_BASE_URL="api.example.com"
VITE_BACKEND_HOST="api.example.com"
VITE_USE_TLS="true"
VITE_FRONTEND_PORT="80"
VITE_MOCK_API="false"
VITE_GMS_WS_URL="wss://link.weidian.com/gms_ws"
VITE_INSECURE_SKIP_VERIFY="false"
```

**特点**:
- 连接生产后端
- 启用TLS加密
- 严格的证书验证
- 不使用任何Mock功能

## Vite配置

### 1. 基础配置

```typescript
// vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import path from 'path';

export default defineConfig({
  // 插件配置
  plugins: [
    react(),
    // Tailwind CSS插件
    tailwindcss(),
  ],

  // 路径别名
  resolve: {
    alias: {
      '#': path.resolve(__dirname, './src'),
    },
  },

  // 开发服务器配置
  server: {
    port: parseInt(process.env.VITE_FRONTEND_PORT || '3001'),
    host: true,
    proxy: {
      // API代理配置
      '/api': {
        target: `http://${process.env.VITE_BACKEND_HOST || 'localhost:3000'}`,
        changeOrigin: true,
        secure: false,
      },
    },
  },

  // 构建配置
  build: {
    outDir: 'build',
    sourcemap: true,
    rollupOptions: {
      output: {
        manualChunks: {
          // 代码分割配置
          vendor: ['react', 'react-dom', 'react-router'],
          tanstack: ['@tanstack/react-query'],
          antd: ['antd'],
        },
      },
    },
  },

  // 环境变量配置
  envPrefix: 'VITE_',
});
```

### 2. 代理配置

开发环境下，Vite可以代理API请求到后端服务器：

```typescript
server: {
  proxy: {
    // 代理所有 /api 开头的请求
    '/api': {
      target: 'http://localhost:3000',
      changeOrigin: true,
      secure: false,
      rewrite: (path) => path, // 可选：重写路径
    },
    // 代理WebSocket连接
    '/ws': {
      target: 'ws://localhost:3000',
      ws: true,
      changeOrigin: true,
    },
  },
}
```

## API地址配置

### 1. API基础URL获取

```typescript
// src/utils/api-base-url.ts
/**
 * 获取API基础URL
 * 根据环境变量构建完整的API地址
 */
export function getApiBaseUrl(): string {
  const useTLS = import.meta.env.VITE_USE_TLS === "true";
  const protocol = useTLS ? "https" : "http";
  const host = import.meta.env.VITE_BACKEND_BASE_URL || window.location.host;
  
  return `${protocol}://${host}`;
}

/**
 * 获取WebSocket URL
 * 根据环境变量构建WebSocket连接地址
 */
export function getWebSocketUrl(): string {
  const useTLS = import.meta.env.VITE_USE_TLS === "true";
  const protocol = useTLS ? "wss" : "ws";
  const host = import.meta.env.VITE_BACKEND_HOST || window.location.host;
  
  return `${protocol}://${host}`;
}

/**
 * 获取GMS WebSocket URL
 */
export function getGmsWebSocketUrl(): string {
  return import.meta.env.VITE_GMS_WS_URL || "wss://link.daily.weidian.com/gms_ws";
}
```

```typescript
import axios from "axios";

export const openHands = axios.create({

  },

    return Promise.reject(error);
  }
```

### 2. 新API渐进式迁移

```typescript
// src/api-new/adapters/api-adapter.ts
export function shouldUseNewApi(module: string): boolean {
  // 检查全局开关
  if (import.meta.env.VITE_USE_NEW_API === 'true') {
    return true;
  }

  // 检查模块级开关
  const moduleKey = `VITE_NEW_API_${module.toUpperCase()}`;
  return import.meta.env[moduleKey] === 'true';
}

// 使用示例
export async function getTaskDetail(taskId: string) {
  if (shouldUseNewApi('task')) {
    return getTaskDetailFromNewApi(taskId);
  } else {
    return getTaskDetailFromOldApi(taskId);
  }
}
```

## 常见问题

### 1. 环境变量不生效？

**原因**: 
- 环境变量文件未创建或命名错误
- 忘记添加 `VITE_` 前缀
- 修改后未重启开发服务器

**解决方案**:
```bash
# 1. 检查文件名
ls -la | grep .env

# 2. 确保环境变量有VITE_前缀
VITE_BACKEND_BASE_URL="localhost:3000"  # ✅ 正确
BACKEND_BASE_URL="localhost:3000"        # ❌ 错误

# 3. 修改环境变量后重启服务器
# Ctrl+C 停止服务器
npm run dev  # 重新启动
```

### 2. API请求跨域错误？

**原因**: 开发环境未配置代理或CORS。

**解决方案**:
```typescript
// vite.config.ts
server: {
  proxy: {
    '/api': {
      target: 'http://localhost:3000',
      changeOrigin: true,  // 关键：改变请求源
      secure: false,        // 开发环境可以禁用SSL验证
    },
  },
}
```

### 3. 构建后环境变量丢失？

**原因**: Vite在构建时会将环境变量内联到代码中。

**解决方案**:
```typescript
// ❌ 错误：运行时修改环境变量无效
window.VITE_BACKEND_BASE_URL = "new-url";

// ✅ 正确：使用配置文件或运行时配置
const config = {
  apiBaseUrl: import.meta.env.VITE_BACKEND_BASE_URL || 'default-url',
};
```

### 4. 如何在不同环境使用不同配置？

**解决方案**:
```bash
# 创建环境特定的配置文件
.env.development      # 开发环境
.env.staging          # 预发布环境
.env.production       # 生产环境

# 使用--mode参数指定环境
npm run dev -- --mode development
npm run build -- --mode production
npm run build -- --mode staging
```

### 5. TypeScript提示环境变量不存在？

**解决方案**:
```typescript
// src/global.d.ts
/// <reference types="vite/client" />

interface ImportMetaEnv {
  readonly VITE_BACKEND_BASE_URL: string;
  readonly VITE_USE_TLS: string;
  // 添加所有使用的环境变量
}

interface ImportMeta {
  readonly env: ImportMetaEnv;
}
```

### 6. 生产环境如何动态切换后端地址？

**解决方案**:
```typescript
// 方案1: 使用window.location自动适配
export function getApiBaseUrl(): string {
  // 如果环境变量未设置，使用当前域名
  const host = import.meta.env.VITE_BACKEND_BASE_URL || window.location.host;
  return `${window.location.protocol}//${host}`;
}

// 方案2: 使用运行时配置文件
// public/config.js
window.APP_CONFIG = {
  apiBaseUrl: 'https://api.example.com',
};

// 在代码中读取
const apiBaseUrl = window.APP_CONFIG?.apiBaseUrl || import.meta.env.VITE_BACKEND_BASE_URL;
```

## 最佳实践

### 1. 环境变量管理

- ✅ 使用 `.env.sample` 作为模板提交到Git
- ✅ 将敏感信息放在 `.env.local`（不提交）
- ✅ 所有环境变量添加 `VITE_` 前缀
- ✅ 为环境变量添加注释说明
- ❌ 不要在代码中硬编码配置值
- ❌ 不要将 `.env.local` 提交到Git

### 2. 多环境配置

- ✅ 为每个环境创建独立的配置文件
- ✅ 使用构建命令的 `--mode` 参数切换环境
- ✅ 在CI/CD中使用环境变量或配置文件
- ❌ 不要在代码中使用 `if (process.env.NODE_ENV === 'production')`

### 3. API地址配置

- ✅ 使用工具函数封装API地址获取逻辑
- ✅ 支持自动适配（使用当前域名）
- ✅ 提供降级方案（默认值）
- ❌ 不要在多处重复构建API地址
