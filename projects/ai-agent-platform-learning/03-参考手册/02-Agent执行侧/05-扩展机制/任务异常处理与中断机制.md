# 任务异常处理与中断机制详解

> 本文档详细讲解 Code-Agent 如何处理任务执行中的异常、超时、卡住等情况，以及如何主动中断任务。

---

## 一、任务执行的三种异常情况

### 1.1 任务可能遇到的问题

```
正常执行：
  用户需求 → Claude 生成代码 → 测试通过 → 任务完成 ✅

异常情况1：任务执行失败
  用户需求 → Claude 生成代码 → 编译报错 → ❌ 怎么办？

异常情况2：任务卡住（超时）
  用户需求 → Claude 执行命令 → 命令一直运行不结束 → ❌ 怎么办？

异常情况3：用户主动中断
  用户需求 → Claude 正在执行 → 用户点击"停止" → ❌ 怎么办？
```

## 二、异常处理机制

### 2.1 代码层面的异常捕获

**代码位置**：[claude_agent_sdk_wrapper.py:1412-1437](../../code-agent/claude_agent_sdk_wrapper.py#L1412-L1437)

```python
try:
    # 执行任务
    async with client:
        async for message in client.query(prompt, session_id=session_id):
            # 处理消息...
            
except Exception as e:
    error_msg = str(e)
    logger.error(f"【task:{task_id}】ClaudeCode SDK 异常: {error_msg}", exc_info=True)
    
    # 分类异常类型
    if isinstance(e, InterruptedError) or "interrupted" in error_msg.lower():
        # 用户中断
        error_type = "user_interrupted"
        logger.info(f"[Task {task_id}] 任务被用户中断")
        
    elif "connection" in error_msg.lower() or "timeout" in error_msg.lower():
        # 连接/超时错误
        error_type = "network_error"
        logger.warning(f"[Task {task_id}] 网络或超时错误")
        
    else:
        # 其他错误
        error_type = "execution_error"
        logger.error(f"[Task {task_id}] 执行错误")
    
    # 清理中断标识
    self._clear_interrupt_flag(task_id)
    
    # 返回错误信息
    raise
```

### 2.2 异常分类

| 异常类型 | 触发条件 | 错误类型 | 处理方式 |
|----------|----------|----------|----------|
| **用户中断** | 收到中断请求 | `user_interrupted` | 清理资源，返回中断消息 |
| **网络/超时** | 连接失败、超时 | `network_error` | 记录日志，返回错误 |
| **执行错误** | 代码异常、SDK 错误 | `execution_error` | 记录详细日志，返回错误 |

### 2.3 错误信息的返回

**正常执行**：
```python
return {
    "success": True,
    "content": "任务完成...",
    "session_id": "session_abc"
}
```

**异常执行**：
```python
return {
    "success": False,
    "error": "执行失败：编译错误...",
    "error_type": "execution_error",
    "session_id": "session_abc"
}
```

## 三、任务中断机制 ⭐️

### 3.1 什么是任务中断？

**用户场景**：
```
用户发起任务：实现支付功能
    ↓
Claude 开始执行（预计 10 分钟）
    ↓
用户发现需求错了，想停止
    ↓
用户点击"停止任务"按钮
    ↓
Code-Agent 中断 Claude 执行
    ↓
任务停止 ✅
```

### 3.2 中断流程架构

```
┌─────────────────────────────────────────┐
│ AI24 / 用户界面                          │
│   点击"停止任务"按钮                     │
└─────────────────────────────────────────┘
            │
            ▼ POST /task/interrupt
┌─────────────────────────────────────────┐
│ TaskInterruptResource (Flask API)       │
│   接收中断请求                           │
└─────────────────────────────────────────┘
            │
            ▼ dispatch_task_query_message
┌─────────────────────────────────────────┐
│ ClaudeAgentSDKService.interrupt_task()  │
│                                         │
│ 1️⃣ 设置 was_interrupted 标识           │
│ 2️⃣ 检查任务锁状态                      │
│ 3️⃣ 设置 interrupt_flag                │
│ 4️⃣ 查找活跃的 client 实例              │
│ 5️⃣ 调用 client.interrupt()            │
└─────────────────────────────────────────┘
            │
            ▼
┌─────────────────────────────────────────┐
│ Claude SDK Client                       │
│   client.interrupt()                    │
│   中断当前执行                           │
└─────────────────────────────────────────┘
            │
            ▼
┌─────────────────────────────────────────┐
│ query() 循环检测到中断标识              │
│   抛出 InterruptedError                 │
└─────────────────────────────────────────┘
            │
            ▼
         任务中断成功 ✅
```

### 3.3 中断机制的关键设计

#### ① interrupt_flag（中断标识）

**代码位置**：[claude_agent_sdk_wrapper.py:558](../../code-agent/claude_agent_sdk_wrapper.py#L558)

```python
class ClaudeAgentSDKService:
    def __init__(self):
        # 中断标识：task_id → bool
        self._interrupt_flags: Dict[str, bool] = {}
        
        # 已中断标识：task_id → bool（持久化）
        self._was_interrupted: Dict[str, bool] = {}
```

**用途**：
- `interrupt_flag`：临时标识，告诉正在执行的任务"你被中断了"
- `was_interrupted`：持久标识，记录任务曾经被中断过

#### ② 检查中断标识的时机

**在消息处理循环中检查**：[claude_agent_sdk_wrapper.py:1764](../../code-agent/claude_agent_sdk_wrapper.py#L1764)

```python
async for message in client.query(prompt, session_id=session_id):
    # 每次收到消息时检查中断标识
    if task_id and self._get_interrupt_flag(task_id):
        logger.info(f"[Task {task_id}] 检测到中断标识，准备中断执行")
        # 清理并抛出异常
        self._clear_interrupt_flag(task_id)
        raise InterruptedError(f"任务 {task_id} 被用户中断")
    
    # 处理消息...
```

**在执行前检查**：[claude_agent_sdk_wrapper.py:1357](../../code-agent/claude_agent_sdk_wrapper.py#L1357)

```python
# 执行前检查是否已被中断
if task_id and self._get_interrupt_flag(task_id):
    logger.info(f"[Task {task_id}] 执行前检测到中断标识")
    self._clear_interrupt_flag(task_id)
    raise InterruptedError(f"任务 {task_id} 在执行前被中断")
```

#### ③ interrupt_task() 完整实现

**代码位置**：[claude_agent_sdk_wrapper.py:2146-2265](../../code-agent/claude_agent_sdk_wrapper.py#L2146-L2265)

```python
def interrupt_task(self, task_id: str) -> tuple[bool, str]:
    """中断指定任务的执行"""
    
    try:
        logger.info(f"[Task {task_id}] 开始中断任务")
        
        # 1. 立即设置 was_interrupted 标识
        with self._client_lock:
            self._was_interrupted[task_id] = True
        logger.info(f"[Task {task_id}] was_interrupted 标识已设置")
        
        # 2. 检查任务锁是否存在
        task_lock = None
        with self._client_lock:
            task_lock = self._task_locks.get(task_id)
        
        if not task_lock:
            message = f"任务 {task_id} 的锁不存在，任务可能尚未启动"
            return True, message
        
        # 3. 检查锁是否被占用（任务是否正在执行）
        if not task_lock.locked():
            message = f"任务 {task_id} 的锁未被占用，任务可能已完成"
            return True, message
        
        logger.info(f"[Task {task_id}] 任务锁被占用，开始执行中断流程")
        
        # 4. 设置打断标识
        self._set_interrupt_flag(task_id, True)
        logger.info(f"[Task {task_id}] 打断标识已设置")
        
        # 5. 查找所有相关的客户端实例
        clients_to_interrupt = {}
        
        with self._client_lock:
            # 查找主会话客户端
            if task_id in self._active_clients:
                clients_to_interrupt[task_id] = self._active_clients[task_id]
                logger.info(f"[Task {task_id}] 找到主会话客户端")
            
            # 查找辅助会话客户端（Token检查、步骤检查）
            for client_key in list(self._active_clients.keys()):
                if client_key.startswith(f"{task_id}:"):
                    clients_to_interrupt[client_key] = self._active_clients[client_key]
                    logger.info(f"[Task {task_id}] 找到辅助会话客户端: {client_key}")
        
        if not clients_to_interrupt:
            message = f"任务 {task_id} 当前没有活跃的客户端实例，但已设置打断标识"
            return True, message
        
        logger.info(f"[Task {task_id}] 找到 {len(clients_to_interrupt)} 个活跃的客户端实例")
        
        # 6. 调用 client.interrupt() 进行打断
        interrupt_results = []
        
        for client_key, client in clients_to_interrupt.items():
            try:
                # 获取该客户端对应的事件循环
                loop = None
                with self._client_lock:
                    loop = self._client_loops.get(client_key)
                
                if not loop:
                    logger.warning(f"[Task {task_id}] 客户端 {client_key} 没有找到对应的事件循环")
                    continue
                
                # 使用 run_coroutine_threadsafe 在原始事件循环中执行 interrupt
                logger.info(f"[Task {task_id}] 正在调用 {client_key} 的 interrupt() 方法")
                future = asyncio.run_coroutine_threadsafe(client.interrupt(), loop)
                
                # 等待中断完成（最多等待 2 秒）
                try:
                    future.result(timeout=2)
                    interrupt_results.append(f"{client_key}: 成功")
                    logger.info(f"[Task {task_id}] {client_key} 中断成功")
                except TimeoutError:
                    interrupt_results.append(f"{client_key}: 超时")
                    logger.warning(f"[Task {task_id}] {client_key} 中断超时")
                except Exception as e:
                    interrupt_results.append(f"{client_key}: 失败 ({str(e)})")
                    logger.error(f"[Task {task_id}] {client_key} 中断失败: {e}")
                    
            except Exception as e:
                logger.error(f"[Task {task_id}] 调用 {client_key} 的 interrupt() 时发生异常: {e}")
                interrupt_results.append(f"{client_key}: 异常 ({str(e)})")
        
        # 7. 返回中断结果
        result_message = f"任务 {task_id} 中断请求已发送: {', '.join(interrupt_results)}"
        logger.info(f"[Task {task_id}] {result_message}")
        return True, result_message
        
    except Exception as e:
        error_message = f"中断任务 {task_id} 时发生异常: {str(e)}"
        logger.error(f"[Task {task_id}] {error_message}", exc_info=True)
        return False, error_message
```

### 3.5 为什么需要两层中断机制？

#### ① interrupt_flag（立即中断）

```python
# 设置标识
self._interrupt_flags[task_id] = True

# 在执行循环中检查
if self._get_interrupt_flag(task_id):
    raise InterruptedError()  # 立即停止
```

**作用**：让 Python 代码层面立即检测到中断请求

#### ② client.interrupt()（SDK 中断）

```python
# 调用 Claude SDK 的中断方法
await client.interrupt()
```

**作用**：让 Claude SDK 内部停止执行（可能正在调用 API、等待响应）

**两者配合**：
- `interrupt_flag`：快速响应（Python 层）
- `client.interrupt()`：彻底中断（SDK 层）

## 四、任务卡住（超时）处理

### 4.1 超时的场景

```
场景1：命令执行超时
  Claude 执行：npm install
  → npm 卡住，一直不返回
  → ❌ 任务永远完不成

场景2：API 调用超时
  Claude 调用 API
  → API 响应慢，一直等待
  → ❌ 任务卡住
```

### 4.2 超时机制

#### ① Session 超时

**配置**：[claude_agent_sdk_wrapper.py:353](../../code-agent/claude_agent_sdk_wrapper.py#L353)

```python
session_timeout: int = 7200  # 默认 2 小时
```

**作用**：
- 如果一个 session 超过 2 小时没有活动
- Claude SDK 会自动关闭连接
- 防止资源长期占用

#### ② API 调用超时

**Figma Token API**：[claude_agent_sdk_wrapper.py:298](../../code-agent/claude_agent_sdk_wrapper.py#L298)

```python
resp = httpx.get(self._api_url, timeout=10.0)  # 10 秒超时
```

**AI24 API**：[claude_agent_sdk_wrapper.py:138](../../code-agent/claude_agent_sdk_wrapper.py#L138)

```python
response = requests.get(url, timeout=5)  # 5 秒超时
```

**作用**：防止 API 调用一直等待

### 4.3 任务卡住的检测

**目前没有主动检测机制**，依赖：
1. **Session 超时**：2 小时后自动断开
2. **用户手动中断**：用户点击停止按钮
3. **心跳监控**：AI24 通过心跳数据判断机器负载

**改进建议**：
```python
# 可以添加任务超时检测
if task_running_time > MAX_TASK_TIMEOUT:
    logger.warning(f"任务 {task_id} 执行超过最大时间，自动中断")
    service.interrupt_task(task_id)
```

## 五、Claude SDK 内部的错误处理

### 5.1 SDK 自身的容错

Claude Agent SDK 内部有以下容错机制：

#### ① 自动重试

```
API 调用失败
  ↓
SDK 自动重试（3次）
  ↓
如果还是失败，抛出异常
```

#### ② 连接池管理

```
维持 API 连接池
  ↓
连接失败时自动切换
  ↓
保证服务可用性
```

#### ③ 优雅降级

```
某个工具调用失败
  ↓
SDK 返回错误信息给 Claude
  ↓
Claude 尝试其他方式
```

### 5.2 Code-Agent 对 SDK 错误的包装

```python
try:
    # 调用 SDK
    result = await service.query(task_id, prompt)
    
except SDKError as e:
    # 包装成统一格式
    return {
        "success": False,
        "error": f"SDK 错误: {str(e)}",
        "error_type": "sdk_error"
    }
    
except Exception as e:
    # 未知错误
    return {
        "success": False,
        "error": f"未知错误: {str(e)}",
        "error_type": "unknown_error"
    }
```

## 六、完整的错误处理流程

```
任务执行
    │
    ├─ 情况1：正常完成
    │   └─ return {"success": True, "content": "..."}
    │
    ├─ 情况2：用户中断
    │   ├─ 用户点击"停止"
    │   ├─ interrupt_task() 设置标识
    │   ├─ query() 循环检测到
    │   ├─ 抛出 InterruptedError
    │   └─ return {"success": False, "error": "用户中断"}
    │
    ├─ 情况3：执行错误
    │   ├─ Claude 生成的代码有错
    │   ├─ 编译失败 / 测试失败
    │   ├─ 抛出 ExecutionError
    │   └─ return {"success": False, "error": "执行错误"}
    │
    ├─ 情况4：超时
    │   ├─ Session 超过 2 小时
    │   ├─ SDK 自动断开
    │   ├─ 抛出 TimeoutError
    │   └─ return {"success": False, "error": "超时"}
    │
    └─ 情况5：网络错误
        ├─ API 调用失败
        ├─ 连接断开
        ├─ 抛出 NetworkError
        └─ return {"success": False, "error": "网络错误"}
```

## 七、小结

### 任务异常处理

| 异常类型 | 检测方式 | 处理方式 | 用户感知 |
|----------|----------|----------|----------|
| **用户中断** | interrupt_flag | 抛出 InterruptedError | 任务停止，显示"已中断" |
| **执行错误** | try-except | 捕获异常，记录日志 | 显示错误信息 |
| **超时** | session_timeout | SDK 自动断开 | 显示"超时" |
| **网络错误** | API 调用失败 | 捕获异常，可重试 | 显示"网络错误" |

### 任务中断机制

| 机制 | 作用 | 实现方式 |
|------|------|----------|
| **interrupt_flag** | Python 层中断 | 设置标识，循环检测 |
| **client.interrupt()** | SDK 层中断 | 调用 SDK 方法 |
| **was_interrupted** | 持久化标识 | 记录任务被中断过 |
| **任务锁检查** | 判断是否执行中 | task_lock.locked() |

### 关键设计亮点

1. ⭐️ **双层中断**：Python 层 + SDK 层，确保彻底中断
2. ⭐️ **异步安全中断**：使用 `run_coroutine_threadsafe` 跨线程调用
3. ⭐️ **多客户端中断**：主会话 + 辅助会话（Token检查、步骤检查）
4. ⭐️ **异常分类**：user_interrupted、network_error、execution_error
5. ⭐️ **超时保护**：Session 超时 2 小时，API 调用超时 5-10 秒

### 与其他机制的关系

```
任务中断
  └─ 触发任务恢复机制
      └─ 保存到 interrupted_tasks.json
          └─ 服务重启后恢复

异常处理
  └─ 记录到日志
      └─ 上报到 AI24
          └─ 用户可查看错误信息
```
