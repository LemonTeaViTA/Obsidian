## 二、TaskRecoveryManager.recover_interrupted_tasks() - 任务恢复

### 2.1 什么是任务恢复？

**问题场景**：
```
Claude 正在执行任务
    ↓
服务被 kill -9 强制终止
    ↓
任务中断，Claude 对话丢失
    ↓
❌ 如果没有恢复机制，任务永远无法完成
```

**解决方案**：
```
服务关闭前：保存中断任务信息到 interrupted_tasks.json
服务重启后：读取 interrupted_tasks.json，恢复任务执行
```

### 2.2 中断任务保存机制

**触发时机**：收到 SIGTERM 或 SIGINT 信号

**代码位置**：[main.py:80-121](../main.py#L80-L121)

```python
def handle_shutdown_signal(signum, frame):
    """处理进程终止信号"""
    signal_name = signal.Signals(signum).name
    logger.info(f"收到信号 {signal_name}，开始执行清理...")
    
    try:
        # 保存中断任务（最重要！）
        TaskRecoveryManager.save_interrupted_tasks()
        logger.info("中断任务信息保存完成")
    except Exception as e:
        logger.error(f"保存中断任务信息失败: {str(e)}", exc_info=True)
    
    # ... 其他清理操作
    sys.exit(0)
```

**保存的内容**：

```json
// tmp/data/interrupted_tasks.json
{
  "task_123": {
    "task_id": "task_123",
    "stage": "executing",              // 执行阶段
    "task_type": "dev",                 // 任务类型
    "last_query": "实现用户登录功能",   // 最后一次查询
    "timestamp": "2026-07-07T10:30:00"
  },
  "task_456": {
    "task_id": "task_456",
    "stage": "waiting",
    "task_type": "frontend",
    "last_query": "实现登录页面",
    "timestamp": "2026-07-07T10:35:00"
  }
}
```

### 2.3 任务恢复流程

**代码位置**：[main.py:3896-3901](../main.py#L3896-L3901)

```python
# 恢复中断的任务
logger.info("正在检查是否有中断任务需要恢复...")
recovered_count = TaskRecoveryManager.recover_interrupted_tasks(run_query_task_in_thread)
if recovered_count > 0:
    logger.info(f"成功恢复 {recovered_count} 个中断任务")
else:
    logger.info("没有需要恢复的中断任务")
```

**恢复逻辑**：

```python
def recover_interrupted_tasks(run_query_func):
    # 1. 读取 interrupted_tasks.json
    if not os.path.exists('tmp/data/interrupted_tasks.json'):
        return 0  # 没有中断任务
    
    with open('tmp/data/interrupted_tasks.json') as f:
        tasks = json.load(f)
    
    # 2. 为每个中断任务创建恢复线程
    recovered_count = 0
    for task_id, task_info in tasks.items():
        try:
            # 使用最后一次的查询内容恢复任务
            run_query_func(
                task_id=task_id,
                query=task_info['last_query'],
                resume=True  # 标记为恢复任务
            )
            recovered_count += 1
        except Exception as e:
            logger.error(f"恢复任务 {task_id} 失败: {e}")
    
    # 3. 删除 interrupted_tasks.json（已恢复）
    os.remove('tmp/data/interrupted_tasks.json')
    
    return recovered_count
```

### 2.5 为什么需要任务恢复？

**场景1：服务升级部署**
```
运维：要升级 Code-Agent，需要重启服务
      但是有 10 个任务正在执行...

没有恢复机制：
  ├─ 10 个任务全部中断
  ├─ 用户需要手动重新发起
  └─ 之前的工作全部丢失 ❌

有了恢复机制：
  ├─ 服务重启后自动恢复 10 个任务
  ├─ Claude 继续之前的工作
  └─ 对用户透明，无需人工介入 ✅
```

**场景2：服务异常崩溃**
```
Code-Agent 因为某个 bug 崩溃
  ├─ 5 个任务正在执行
  ├─ 服务自动重启（守护进程）
  └─ 自动恢复 5 个任务 ✅
```

```python
def _heartbeat_loop(self):
    """心跳循环（在后台线程中运行）"""
    while self._heartbeat_running:
        try:
            # 上报机器状态
            self.report_machine_status()
        except Exception as e:
            logger.error(f"心跳上报失败: {e}")
        
        # 等待 30 秒

```

### 3.5 心跳机制的作用

#### ① 在线状态监控

```
AI24 管理平台
    │
    ├─ 机器列表
    │   ├─ 10.32.120.164 (在线) ✅ 最后心跳: 10秒前
    │   ├─ 10.32.120.165 (在线) ✅ 最后心跳: 5秒前
    │   └─ 10.32.120.166 (离线) ❌ 最后心跳: 5分钟前
    │
    └─ 如果超过 2 分钟没有心跳 → 标记为离线
```

#### ② 负载均衡

```
AI24 收到新任务
    ↓
查看所有在线机器的负载
    ├─ 10.32.120.164: CPU 45%, 3 个 Claude 进程
    ├─ 10.32.120.165: CPU 80%, 5 个 Claude 进程
    └─ 10.32.120.166: CPU 20%, 1 个 Claude 进程
    ↓
选择负载最低的机器（10.32.120.166）
    ↓
将任务分配给 10.32.120.166 ✅
```

#### ③ 故障转移

```
机器 A 正在执行 5 个任务
    ↓
机器 A 心跳停止（机器故障）
    ↓
AI24 检测到机器 A 离线
    ↓
将 5 个任务重新分配给其他机器
```

## 五、小结

### MetaContainer（任务元数据管理器）

| 维度 | 内容 |
|------|------|
| **作用** | 存储和管理所有任务的元信息 |
| **存储位置** | 云端（腾讯云 COS） |
| **数据内容** | git_url, branch, project_path, flow_type, template_id... |
| **使用场景** | 任务初始化、任务执行、任务查询 |
| **为什么需要** | 多机共享、持久化、数据一致性 |

### TaskRecoveryManager（任务恢复管理器）

| 维度 | 内容 |
|------|------|
| **作用** | 保存和恢复中断任务 |
| **触发时机** | 服务关闭时保存，启动时恢复 |
| **存储位置** | 本地（tmp/data/interrupted_tasks.json） |
| **数据内容** | task_id, stage, last_query |
| **为什么需要** | 服务升级、异常崩溃时不丢失任务 |

### MachineStatusManager（机器状态管理器）

| 维度 | 内容 |
|------|------|
| **作用** | 定期上报机器状态到 AI24 |
| **上报间隔** | 30 秒 |
| **上报内容** | IP, hostname, claude 进程数, CPU 使用率 |
| **使用场景** | 负载均衡、故障检测、容量规划 |
| **为什么需要** | 多机调度、故障转移 |

**三者关系**：
- MetaContainer：存储任务信息的"数据库"
- TaskRecoveryManager：保证任务执行的"保险"
- MachineStatusManager：多机协作的"信号灯"
