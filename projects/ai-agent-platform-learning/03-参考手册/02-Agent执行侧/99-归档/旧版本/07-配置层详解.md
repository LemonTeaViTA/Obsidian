# 配置层详解

> 对应 [07-启动流程走读.md](./07-启动流程走读.md) 分层时序图里的 **配置层**。
> 配置层负责把项目自带的最新配置(技能/子代理/全局设置/路由)同步覆盖到用户目录，保证服务用的是项目里这份而非机器上的旧配置。
> 三个复制函数 + 一个目录恢复，全部指向 `~/.claude/` 和 `~/.claude-code-router/`。

---

## 一、配置层总览

```
┌────────────────────────────────────────────┐
│  配置层启动时做的事（按顺序）                 │
│                                              │
│  move_claude_project_on_startup()            │
│    恢复上次停机备份的会话状态目录              │
│    /home/www/logs/.claude → /home/www/.claude│
│                                              │
│  copy_skills_to_user_claude_dir()            │
│    .claude/skills/* → ~/.claude/skills       │
│                                              │
│  copy_agents_to_user_claude_dir()            │
│    .claude/agents/* → ~/.claude/agents       │
│    ⚠️ 目录不存在，走 warning 静默跳过          │
│                                              │
│  copy_settings_to_user_claude_dir()          │
│    config/.claude/settings.json → ~/.claude/ │
│    config/.claude-code-router/* → ~/.claude-code-router/│
│    执行 ccr restart 重启路由服务              │
└────────────────────────────────────────────┘
```

**一句话**：配置层从"项目目录 → 用户 HOME 目录"单向同步，保证 Claude SDK 读到的是项目维护的最新配置。

## 二、会话状态恢复：`move_claude_project_on_startup()`

代码：[main.py:3685](../main.py#L3685)

与停机时的备份成对（[09-容错层详解.md](./09-容错层详解.md) 第五节）：

```python
# 启动：持久化目录 → 工作目录
/home/www/logs/.claude       → /home/www/.claude       (整个目录)
/home/www/logs/.claude.json  → /home/www/.claude.json  (单文件)
```

逻辑：如果源存在就 `copytree`/`copy2` 恢复，否则跳过。

**目的**：`~/.claude` 存 Claude 会话历史，停机时备份到 `~/logs`(持久卷)，启动时搬回来，**跨重启保住会话上下文**。这样任务恢复时能接着之前的对话进度走。

## 三、技能同步：`copy_skills_to_user_claude_dir()`

代码：[main.py:2635](../main.py#L2635)

```python
source_skills_dir = os.path.join(current_dir, '.claude', 'skills')
target_skills_dir = os.path.join(Path.home(), '.claude', 'skills')
# 遍历源目录文件，逐个 copy2 到目标（覆盖同名）
```

### Skills 是什么

Claude SDK 的"技能"系统，类似插件。每个技能是一个定义文件（通常 `.md` 格式），描述：
- 技能名称和触发词（如 `/openspec:proposal`）
- 技能要做什么
- 需要哪些参数

放在 `~/.claude/skills/` 后，用户在 prompt 里输入触发词，SDK 会调用对应技能。

### 本项目的 skills

```bash
ls .claude/skills/
# 输出会有 10 个文件，包含 OpenSpec 相关的技能定义
```

复制这些到 `~/.claude/skills` 后，Claude 就能识别 `/openspec:proposal` 等命令。

### 覆盖策略

同名文件会被覆盖，不同名的保留。这样项目更新 skill 定义时，下次启动自动同步到用户目录，开发者不用手动维护。

## 四、子代理同步：`copy_agents_to_user_claude_dir()`

代码：[main.py:2690](../main.py#L2690)

```python
source_agents_dir = os.path.join(current_dir, '.claude', 'agents')
if not os.path.exists(source_agents_dir):
    logger.warning(f"源 agents 目录不存在: {source_agents_dir}")
    return False
# 同 skills 的复制逻辑
```

### Agents 是什么

Claude SDK 的"子代理"配置，`.md` 文件定义不同类型的 subagent：
- 子代理的系统提示词
- 允许的工具
- 模型选择
- 推理等级

比如可以定义一个专门做代码审查的 subagent、一个专门写测试的 subagent。

### 当前状态

**`.claude/agents/` 目录不存在**（在 [07 文档](./07-启动流程走读.md) 第一节已确认）。每次启动走 warning 分支静默跳过。

这是**预留逻辑**——如果以后在 `.claude/agents/` 放配置文件，启动时会自动同步到 `~/.claude/agents`，SDK 就能用上。目前功能上无影响。

## 五、全局设置同步：`copy_settings_to_user_claude_dir()`

代码：[main.py:2744](../main.py#L2744)

这个函数最复杂，复制**三样**并重启路由服务：

### ① settings.json（Claude 全局设置）

```python
source: config/.claude/settings.json
target: ~/.claude/settings.json
```

`settings.json` 存 Claude SDK 的全局配置，如：
- 默认模型
- 输出格式
- 工具白名单
- MCP 服务器列表
- ...

### ② claude-code-router 配置

```python
source: config/.claude-code-router/config.json
target: ~/.claude-code-router/config.json
```

**CR (claude-code-router)** 是模型路由代理，能把请求转发到不同模型后端（如按任务类型路由到不同 API、或做 fallback）。

### ③ claude-code-router 插件目录

```python
source: config/.claude-code-router/plugins/
target: ~/.claude-code-router/plugins/
```

路由器的插件扩展（如自定义路由规则、负载均衡策略等）。

### ④ 重启路由服务

代码 [main.py:2824-2867](../main.py#L2824)：

```python
if config_updated:
    result = subprocess.run(
        ["ccr", "restart"],
        capture_output=True, text=True, timeout=30
    )
    if result.returncode == 0:
        logger.info("ccr restart 成功")
    else:
        logger.warning(f"ccr restart 失败: {result.stderr}")
```

配置更新后必须重启 `ccr` 才生效。注意这里失败只警告不抛异常——**配置同步失败不影响业务启动**，但可能导致路由不生效。

## 六、配置层的数据流向

```
项目维护的配置（版本管理）
    │
    ├─ .claude/skills/*              ─┐
    ├─ .claude/agents/*  (目前不存在)  │  复制
    ├─ config/.claude/settings.json   ├─────►  ~/.claude/*
    └─ config/.claude-code-router/*  ─┘         ~/.claude-code-router/*
                                                        │
                                               Claude SDK / ccr 读取
```

**设计意图**：配置跟代码一起走版本管理，部署时自动同步，避免：
- 手动维护每台机器的配置
- 配置漂移（不同机器配置不一致）
- 更新遗漏（改了配置忘了同步）

---

## 七、配置层失败的影响

| 函数 | 失败影响 | 健壮性 |
|------|---------|--------|
| `move_claude_project_on_startup` | 会话上下文丢失，任务恢复可能从头开始 | 源不存在跳过（首次启动正常） |
| `copy_skills_...` | `/openspec:*` 等命令不可用 | 失败记 error 不中断启动 |
| `copy_agents_...` | 目前无影响（预留功能） | 目录不存在走 warning |
| `copy_settings_...` | SDK 用旧配置，`ccr` 可能路由错误 | 失败记 error，`ccr restart` 失败只警告 |

**全部函数都不抛异常**——配置同步失败只记日志，让服务继续启动。宁可用旧配置跑起来，也不因配置问题彻底启动失败。

---

## 八、小结

配置层做的是"**配置同步**"：
- 从项目目录单向推到用户 HOME 目录
- 覆盖同名文件，保证最新
- 会话状态从持久卷恢复

与其他层的关系：
- **依赖容错层**：`move_claude_project_on_startup` 恢复的是容错层备份的会话
- **服务核心层**：同步的 settings/skills 被 `create_claude_service()` 和 SDK 使用
- **失败健壮**：全部失败只警告，不阻塞启动
