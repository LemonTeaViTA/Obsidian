# 核心层详解

> 对应 [03-启动流程走读.md](./03-启动流程走读.md) 分层时序图里的 **核心层**。
> 核心层是整个启动流程的**高潮**——前面所有层都是为它铺路，它之后的层都是收尾。
> 一行代码 `create_claude_service(enable_path_security=True)`，背后是几十个 MCP 服务器配置、单例建立、Hook 挂载、多任务隔离机制。

---

## 一、核心层在启动流程的位置

```
环境层 ──► 把配置搬进 os.environ
容错层 ──► 注册信号处理器，准备被杀时抢救
外设层 ──► 配好 COS 和 Langfuse 的"门票"
配置层 ──→ 同步 skills/settings 到 ~/.claude
        │
        ▼
   ┌────────────────────────────────┐
   │ 核心层  create_claude_service() │  ← 你在这里
   │   建 ClaudeAgentSDKService 单例 │
   │   挂载几十个 MCP 服务器          │
   │   注册 3 类 Hook                │
   │   初始化任务隔离机制            │
   └────────────────────────────────┘
        │
        ▼
get_meta_container() ──► 任务元数据管理器单例
恢复层/运维层 ──► 恢复中断任务、启心跳、启调度器
app.run() ──► Flask 开始接客
```

**核心层是"引擎点火"的那一步**——它之前的层都是"准备燃料和场地"，它之后才是真正的运转。

## 二、核心架构：单例 + 多任务隔离 ⭐️

> 🎯 **关键设计**：一个进程只有一个 ClaudeAgentSDKService 实例（单例），但支持多个任务并发执行，通过 session_id、task_lock、cwd 实现任务隔离。

### 2.1 单例模式

**代码位置**：[claude_agent_sdk_wrapper.py:310-340](../../code-agent/claude_agent_sdk_wrapper.py#L310-L340)

```python
class ClaudeAgentSDKService:
    _instance = None
    _lock = threading.Lock()
    
    def __new__(cls):
        """双重检查锁定，确保只创建一个实例"""
        if cls._instance is None:
            with cls._lock:
                if cls._instance is None:
                    cls._instance = super().__new__(cls)
        return cls._instance
    
    def __init__(self):
        """防止重复初始化"""
        if getattr(self, '_initialized', False):
            return
        # ... 初始化代码
        self._initialized = True
    
    @classmethod
    def get_instance(cls):
        """获取单例实例"""
        if cls._instance is None:
            cls._instance = cls()
        return cls._instance
```

**特点**：
- **全局唯一**：整个进程只有一个实例
- **线程安全**：双重检查锁定
- **防重复初始化**：`_initialized` 标志

### 2.2 为什么用单例？

| 方面 | 单例模式 | 多实例模式（每任务一个） |
|------|----------|-------------------------|
| **资源占用** | 1 个 SDK 连接 | N 个任务 = N 个连接 |
| **启动速度** | 启动时初始化一次 | 每个任务都要初始化（慢） |
| **MCP 服务** | 共享启动时动态组装的 MCP 连接 | 每个任务重复建立整套 MCP 连接 |
| **配置管理** | 全局统一配置 | 每个实例独立配置 |
| **内存占用** | 低 | 高（N 倍） |

**单例模式的优势**：节省资源、启动快、配置统一。

### 2.3 多任务隔离机制

虽然是单例，但通过以下机制实现任务隔离：

#### ① session_id 隔离（对话历史隔离）

**核心原理**：每个任务有独立的 `session_id`，SDK 通过 `session_id` 区分不同的对话上下文。

```python
# TaskSessionMapper 管理 task_id ↔ session_id 映射
task_123 → session_abc456
task_456 → session_def789
task_789 → session_ghi012

# 每次 query 时传入对应的 session_id
client.query(prompt, session_id="session_abc456")  # task_123 的对话
client.query(prompt, session_id="session_def789")  # task_456 的对话
```

**代码位置**：[claude_agent_sdk_wrapper.py:1272-1277](../../code-agent/claude_agent_sdk_wrapper.py#L1272-L1277)

```python
session_id = None
if task_id and keep_session:
    session_id = TaskSessionMapper.get_session_id(task_id)
    if session_id:
        logger.info(f"[Task {task_id}] 从映射关系中找到 session_id: {session_id}")
```

**对话历史存储**：
```
~/.claude/projects/
  ├── session_abc456/
  │   ├── conversation.jsonl  ← task_123 的对话历史
  │   └── artifacts/
  ├── session_def789/
  │   ├── conversation.jsonl  ← task_456 的对话历史
  │   └── artifacts/
  └── ...
```

#### ② task_lock 隔离（并发控制）

**核心原理**：每个任务有独立的锁，同一个任务同时只能有一个查询在执行。

**代码位置**：[claude_agent_sdk_wrapper.py:397-404](../../code-agent/claude_agent_sdk_wrapper.py#L397-L404)

```python
def _get_task_lock(self, task_id: str) -> threading.Lock:
    """获取任务锁（每个任务一个锁）"""
    if task_id not in self._task_locks:
        self._task_locks[task_id] = threading.Lock()
    return self._task_locks[task_id]
```

**使用场景**：[claude_agent_sdk_wrapper.py:1254-1257](../../code-agent/claude_agent_sdk_wrapper.py#L1254-L1257)

```python
if task_id:
    task_lock = self._get_task_lock(task_id)
    task_lock.acquire()  # 获取锁，阻塞直到上一个查询完成
    logger.info(f"[Task {task_id}] 已获取任务锁")
```

**作用**：
- 防止同一个任务的多个查询并发执行（会导致对话混乱）
- 不同任务之间可以并发执行

#### ③ cwd 隔离（文件系统隔离）

**核心原理**：每个任务有独立的工作目录。

```python
# 每个任务的工作目录
task_123 → /tmp/projects/task_123/order-service/
task_456 → /tmp/projects/task_456/payment-service/
task_789 → /tmp/projects/task_789/user-service/

# 传给 SDK
options = self._build_options(cwd=task_base_dir, ...)
```

**作用**：
- Claude 执行命令时在对应的项目目录
- 防止任务之间文件操作互相干扰

#### ④ interrupt_flag 隔离（打断标识）

**核心原理**：每个任务有独立的打断标识。

```python
self._interrupt_flags = {}  # task_id → bool

def interrupt_task(self, task_id: str):
    self._interrupt_flags[task_id] = True
```

## 三、多轮对话机制详解 ⭐️

> 🎯 **核心问题**：SDK 的 `query()` 可以支持多轮对话吗？  
> **答案**：可以！通过 `session_id` + `TaskSessionMapper` 实现。

### 3.1 多轮对话的完整流程

```
第1次查询（任务初始化）
├── AI24 调用：POST /task/perform/init
│   └── 创建任务：task_id = "task_123"
│
├── 第1次查询：POST /task/query
│   ├── task_id: "task_123"
│   ├── prompt: "实现用户登录功能"
│   ├── keep_session: True
│   │
│   ├── TaskSessionMapper.get_session_id("task_123")
│   │   └── 返回 None（第一次没有映射）
│   │
│   ├── 调用 SDK: client.query(prompt, session_id=None)
│   │   └── SDK 自动生成 session_id = "session_abc456"
│   │
│   └── 保存映射: TaskSessionMapper.set_mapping("task_123", "session_abc456")
│       ├── 保存到云端（双写）
│       ├── task_id → session_id
│       └── session_id → task_id
│
└── 返回结果：{"task_id": "task_123", "content": "已实现登录功能..."}


第2次查询（继续对话）
├── AI24 调用：POST /task/query
│   ├── task_id: "task_123"
│   ├── prompt: "添加验证码功能"
│   ├── keep_session: True
│   │
│   ├── TaskSessionMapper.get_session_id("task_123")
│   │   └── 返回 "session_abc456"（从云端读取）
│   │
│   ├── 调用 SDK: client.query(prompt, session_id="session_abc456")
│   │   └── SDK 加载 session_abc456 的对话历史 ✅
│   │   └── Claude 知道上次做了什么，继续添加验证码
│   │
│   └── 返回结果
│
└── ✅ 多轮对话成功！


第3次、第4次...
├── 同样使用 session_id="session_abc456"
└── 持续多轮对话（10轮、100轮都可以）
```

### 3.2 TaskSessionMapper 的作用

**文件位置**：[task_session_mapper.py](../../code-agent/task_session_mapper.py)

**核心功能**：

```python
# 1. 保存映射（双向）
TaskSessionMapper.set_mapping("task_123", "session_abc456")
  ├── task_id → session_id（保存到 task_data_api）
  └── session_id → task_id（保存到 claude_data_api）

# 2. 查询映射
session_id = TaskSessionMapper.get_session_id("task_123")
task_id = TaskSessionMapper.get_task_id("session_abc456")

# 3. 持久化到云端
  ├── 使用 COS 对象存储
  └── 机器重启后仍然保留映射关系
```

**数据结构**：

```python
# 云端存储（COS）
{
  "task_123": "session_abc456",
  "task_456": "session_def789",
  "task_789": "session_ghi012"
}

# 内存缓存（性能优化）
_session_to_task_cache = {
  "session_abc456": "task_123",
  "session_def789": "task_456",
  "session_ghi012": "task_789"
}
```

### 3.3 keep_session 参数

**代码位置**：[claude_agent_sdk_wrapper.py:1226-1241](../../code-agent/claude_agent_sdk_wrapper.py#L1226-L1241)

```python
def query(self, prompt: str, task_id: str = None, keep_session: bool = True):
    """
    keep_session: 是否保持会话连接（默认 True）
        - True: 会保存 task_id 和 session_id 的映射关系，支持多轮对话
        - False: 不保存映射关系，每次都是新的会话
    """
```

**使用场景**：

| keep_session | 场景 | 效果 |
|--------------|------|------|
| **True**（默认） | 正常任务执行 | 多轮对话，保留历史 |
| **False** | 临时评分、一次性查询 | 独立会话，不保留历史 |

**示例**：

```python
# 场景1：正常任务（多轮对话）
service.query("实现登录功能", task_id="task_123", keep_session=True)
service.query("添加验证码", task_id="task_123", keep_session=True)  # 继续上次对话

# 场景2：临时评分（独立会话）
service.query("评分这个设计：...", task_id="task_123", keep_session=False)  # 不影响主任务
```

## 四、启动时的调用

### 4.1 启动代码

**位置**：[main.py:3864](../../code-agent/main.py#L3864)

```python
# 初始化 ClaudeAgentSDKService 单例
logger.info("正在初始化 ClaudeAgentSDKService 单例...")
create_claude_service(enable_path_security=True)
logger.info("ClaudeAgentSDKService 单例初始化完成")
```

就一行，但这一行触发了：
1. 工厂函数组装 MCP 配置字典（几十个 stdio/sse/http 服务器）
2. 调用 `ClaudeAgentSDKService.get_instance(**kwargs)` 建单例
3. 单例的 `__init__` 执行（如果是首次）：
   - 从 AI24 拉 API Key
   - 设置模型/工具/权限默认值
   - 初始化三套渲染器（cli/openhands/event）
   - 挂载 Figma token provider
   - 初始化任务锁字典 `_task_locks = {}`
   - 初始化打断标识字典 `_interrupt_flags = {}`

### 4.2 启动时传的唯一参数：`enable_path_security=True`

启动时明确传了 `enable_path_security=True`，意味着**默认开启路径安全**。

**路径安全是什么？**

一个 Hook，拦截文件工具（Read/Write/Edit）的路径参数：
- 如果路径在 `working_dir`（任务基目录）内 → 放行
- 如果路径在外面 → **拒绝**并提示

**代码位置**：[hooks/path_security_hook.py](../../code-agent/hooks/path_security_hook.py)

**为什么启动时就开？**

防止 Claude 误操作系统文件（如改 `/etc/hosts`、删 `/usr/bin/mvn` 这种灾难）。虽然每次 `service.query()` 也能按需传 `enable_path_security`，但启动时开一遍是**全局兜底**——即使某个查询忘了传，也有这个默认保护。

## 六、启动时挂载的 Hook（强制的 + 条件的）

### ① Git Commit Author Hook — **无条件强制**

**代码位置**：[claude_agent_sdk_wrapper.py:1051-1062](../../code-agent/claude_agent_sdk_wrapper.py#L1051-L1062)

```python
# 始终注册 Git Commit Author Hook

注释明确说"**始终注册**"。它拦截缺 `--author` 的 git commit，强制 Claude 补作者信息（Co-Authored-By）。

### ② 路径安全 Hook — 启动时默认开，query 时动态建

前面第四节讲过，启动传 `enable_path_security=True` 是全局开关，每次 query 按 `task_base_dir` 重新建实例。

### ③ TDD Hook — 任务元数据控制

不在启动时挂，在 query 时判断 `meta_container` 的 `enable_tdd` 字段决定是否注册（[claude_agent_sdk_wrapper.py:766](../../code-agent/claude_agent_sdk_wrapper.py#L766) `_register_tdd_hooks`）。

                └── 对话历史: ~/.claude/projects/session_ghi012/
```

## 九、核心层与其他层的依赖

```
核心层读取的环境变量（来自环境层）:
  - MANAGEMENT_API_BASE_URL  → 拉 API Key
  - AI24_MCP_URL             → 挂 AI24 MCP
  - CONTEXT1_MCP_URL         → 挂 Context1 MCP
  - MASTERGO_TOKEN / _URL    → 挂 MasterGo MCP
  - UI_TEST_AUTOMATION_MCP_URL
  - LANGFUSE_* (三个)        → 追踪配置
  - ...

核心层使用的配置文件（来自配置层）:
  - ~/.claude/settings.json → SDK 读取
  - ~/.claude/skills/       → 技能定义
  - ~/.claude/agents/       → 子代理配置（预留）
```

**核心层是所有配置的"汇聚点"**——前面层准备的配置，都在这一步被 SDK 单例读取并生效。

## 十、小结

核心层是"引擎点火"：

| 维度 | 内容 |
|------|------|
| **启动代码** | 一行 `create_claude_service(enable_path_security=True)` |
| **单例模式** | 全局唯一实例，节省资源 |
| **多任务隔离** | session_id + task_lock + cwd + interrupt_flag |
| **多轮对话** | TaskSessionMapper 管理 task_id ↔ session_id 映射 |
| **MCP 服务** | 动态挂载文档/设计/CI/测试/云服务/媒体能力 |
| **Hook 挂载** | 强制 2 个（Git作者 + 路径安全），条件 1 个（TDD） |
| **配置汇聚** | 读取所有环境变量 + 配置文件，汇聚生效 |

之后所有 `service.query()` 调用，都站在这个单例的基础上按需调整参数。核心层失败 = 服务无法启动（没有 try-except 包裹）。

**关键设计亮点**：
1. ⭐️ **单例 + 多任务** - 一个实例服务所有任务，通过隔离机制避免冲突
2. ⭐️ **session_id 机制** - 支持多轮对话，对话历史持久化到云端
3. ⭐️ **任务锁机制** - 同一任务串行执行，不同任务并发执行
