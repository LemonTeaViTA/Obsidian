# 目录结构详解

## 概述

AI Agent Platform 前端项目采用模块化的目录组织方式，清晰分离业务逻辑、UI组件、工具函数、类型定义等。基于 React 19、TypeScript、Vite 构建，使用 React Router 7 进行路由管理，TanStack Query 处理数据状态。

## 核心目录详解

### 1. api/ - API接口层

按业务模块组织的API接口定义，每个模块包含独立的API函数和类型定义。

```
api/
├── task-service/
│   ├── task-service.api.ts     # 任务相关API函数
│   └── task-service.types.ts   # 任务类型定义
├── user-service/
│   ├── user-service.api.ts
│   └── user-service.types.ts
└── open-hands-axios.ts          # 全局Axios实例和拦截器
```

**命名规范**:
- API函数文件: `{module}-service.api.ts`
- 类型定义文件: `{module}-service.types.ts`
- API函数命名: 动词 + 名词（如 `getTaskDetail`, `createTask`）

**示例**:
```typescript
// task-service.api.ts
export async function getTaskDetail(taskId: string): Promise<TaskDetail> {
  const apiBaseUrl = getApiBaseUrl();
  const response = await axios.get(`${apiBaseUrl}/api/taskInfo/detail`, {
    params: { id: taskId }
  });
  return response.data.data;
}
```

分层组织的组件库，从基础UI到业务功能组件。

```
components/

│   │   ├── simple-task-form.tsx         # 任务创建表单
│   │   └── task-status-card.tsx         # 任务状态卡片
│   ├── chat/                # 聊天相关组件
│   │   ├── chat-interface.tsx           # 聊天界面
│   │   └── message-item.tsx             # 消息项
│   ├── settings/            # 设置相关组件
│   └── dashboard/           # 仪表盘组件
├── shared/                  # 共享通用组件
│   ├── buttons/             # 按钮组件
│   ├── modals/              # 模态框组件
│   └── layouts/             # 布局组件
├── ui/                      # UI基础组件
│   ├── button.tsx           # 基础按钮
│   ├── input.tsx            # 基础输入框
│   └── card.tsx             # 基础卡片

    ├── action-event.tsx     # Action事件渲染
    └── observation-event.tsx # Observation事件渲染
```

**组件分类原则**:
- **features/**: 与特定业务功能紧密相关，不可跨项目复用
- **shared/**: 可在项目内多处复用的组件
- **ui/**: 与业务无关的纯UI组件，可跨项目复用
- **v1/**: 特定协议版本的专用组件

### 3. hooks/ - 自定义Hooks

封装可复用的逻辑，特别是数据获取和状态管理。

```
hooks/
├── query/                   # TanStack Query查询Hooks
│   ├── use-task-detail.ts           # 获取任务详情
│   ├── use-tasks-with-summary.ts    # 获取任务列表（带统计）
│   ├── use-model-config.ts          # 获取模型配置
│   └── use-search-users.ts          # 搜索用户
├── mutation/                # TanStack Query变更Hooks
│   ├── use-delete-task.ts           # 删除任务
│   ├── use-create-task.ts           # 创建任务
│   └── use-update-task.ts           # 更新任务
├── chat/                    # 聊天相关Hooks
│   ├── use-send-message.ts          # 发送消息
│   └── use-message-history.ts       # 消息历史
├── use-debounce.ts          # 防抖Hook
├── use-throttle.ts          # 节流Hook
└── use-local-storage.ts     # 本地存储Hook
```

**命名规范**:
- Query Hooks: `use{Entity}{Action}.ts` (如 `useTaskDetail`)
- Mutation Hooks: `use{Action}{Entity}.ts` (如 `useDeleteTask`)
- 通用Hooks: `use{功能}.ts` (如 `useDebounce`)

### 4. stores/ - Zustand状态管理

全局和局部状态管理，使用Zustand实现。

```
stores/
├── use-event-store.ts           # 事件流状态（对话消息）
├── use-agent-store.ts           # Agent状态
├── task-status-store.ts         # 任务状态
├── session-status-store.ts      # 会话状态
├── preview-store.ts             # 前端预览状态
├── task-progress-store.ts       # 任务进度状态
├── error-message-store.ts       # 错误消息状态
└── optimistic-user-message-store.ts  # 乐观更新用户消息
```

**Store设计原则**:
- 每个Store职责单一，只管理相关联的状态
- 使用 `create` 创建Store，导出自定义Hook
- 包含状态和操作状态的方法

**示例**:
```typescript
// task-status-store.ts
import { create } from 'zustand';

interface TaskStatusState {
  taskStatus: number | null;
  setTaskStatus: (status: number) => void;
  clearTaskStatus: () => void;
}

export const useTaskStatusStore = create<TaskStatusState>((set) => ({
  taskStatus: null,
  setTaskStatus: (status) => set({ taskStatus: status }),
  clearTaskStatus: () => set({ taskStatus: null }),
}));
```

### 5. routes/ - 页面路由组件

每个路由对应一个页面组件。

```
routes/
├── _index.tsx               # 首页（/）
├── tasks.tsx                # 任务列表页（/tasks）
├── conversations.$id.tsx    # 对话详情页（/conversations/:id）
├── orchestration.$id.tsx    # 编排任务页（/orchestration/:id）
├── dashboard.tsx            # 仪表盘（/dashboard）
├── settings/                # 设置相关页面
│   ├── _layout.tsx          # 设置布局
│   ├── user.tsx             # 用户设置
│   └── model.tsx            # 模型设置
└── __tests__/               # 路由组件测试
```

**命名规范**（React Router 7 文件路由约定）:
- `_index.tsx`: 默认首页路由
- `{name}.tsx`: 静态路由，如 `tasks.tsx` → `/tasks`
- `{name}.$param.tsx`: 动态路由，如 `conversations.$id.tsx` → `/conversations/:id`
- `_layout.tsx`: 布局组件，不生成路由
- `_404.tsx`: 404错误页面

### 6. types/ - TypeScript类型定义

集中管理类型定义，避免重复。

```
types/
├── core/                    # 核心类型
│   ├── task.ts              # 任务相关类型
│   ├── user.ts              # 用户相关类型
│   └── model.ts             # 模型相关类型
├── v1/                      # V1协议类型
│   ├── event.ts             # 事件类型
│   ├── action.ts            # Action类型
│   └── observation.ts       # Observation类型
├── agent-state.ts           # Agent状态类型
└── index.ts                 # 类型导出入口
```

**类型命名规范**:
- Interface: 名词，PascalCase（如 `TaskDetail`）
- Type: 名词或形容词，PascalCase（如 `TaskStatus`）
- Enum: 名词，PascalCase（如 `TaskType`）

通用的工具函数和辅助方法。


- 充分的类型注解和JSDoc注释

### 9. contexts/ - React Context

跨组件共享的Context Provider。

```

├── custom-agent-websocket-context.tsx  # WebSocket Context
└── theme-context.tsx                   # 主题Context
```

## 文件命名规范

### 1. 组件文件

- **React组件**: `kebab-case.tsx`（如 `simple-task-form.tsx`）
- **组件测试**: `{component-name}.test.tsx`
- **组件样式**: `{component-name}.module.css`（如使用CSS Modules）

### 2. 非组件文件

- **工具函数**: `kebab-case.ts`（如 `api-base-url.ts`）
- **类型定义**: `kebab-case.ts` 或 `kebab-case.types.ts`
- **常量定义**: `kebab-case-constants.ts`
- **Hooks**: `use-kebab-case.ts`（如 `use-debounce.ts`）
- **Store**: `use-{name}-store.ts` 或 `{name}-store.ts`

### 3. 目录命名

- 全部使用 `kebab-case`（如 `task-service/`, `user-settings/`）
- 与业务模块对应，便于理解和查找

## 路径别名使用

项目配置了路径别名 `#/` 指向 `src/` 目录，避免相对路径的层级问题。

```typescript
// ❌ 不推荐：相对路径
import { getTaskDetail } from '../../../api/task-service/task-service.api';
import { useTaskDetail } from '../../hooks/query/use-task-detail';

// ✅ 推荐：路径别名
import { getTaskDetail } from '#/api/task-service/task-service.api';
import { useTaskDetail } from '#/hooks/query/use-task-detail';
```

## 常见问题

### 1. 如何添加新的API模块？

**步骤**:
1. 在 `src/api/` 下创建新目录（如 `notification-service/`）
2. 创建 `notification-service.api.ts` 和 `notification-service.types.ts`
3. 定义类型和API函数
4. 在需要的地方导入使用

```typescript
// src/api/notification-service/notification-service.api.ts
import axios from 'axios';
import { getApiBaseUrl } from '#/utils/api-base-url';

export async function getNotifications(): Promise<Notification[]> {
  const apiBaseUrl = getApiBaseUrl();
  const response = await axios.get(`${apiBaseUrl}/api/notifications`);
  return response.data.data;
}
```

### 2. 如何添加新的页面路由？

**步骤**:
1. 在 `src/routes/` 下创建路由文件
2. 按照React Router 7文件路由规范命名
3. 编写页面组件
4. 路由会自动生成，无需手动配置

```typescript
// src/routes/notifications.tsx
export default function NotificationsPage() {
  return (
    <div>
      <h1>通知列表</h1>
      {/* 页面内容 */}
    </div>
  );
}

// 自动生成路由: /notifications
```

### 3. 组件应该放在哪个目录？

**判断标准**:
- **与特定业务强相关**（如任务创建表单） → `components/features/`
- **项目内多处复用**（如自定义Modal） → `components/shared/`
- **纯UI，与业务无关**（如Button、Input） → `components/ui/`
- **特定协议版本专用** → `components/v1/`

### 4. Store和Context如何选择？

**选择标准**:
- **需要频繁更新**: 使用Zustand Store（性能更好）
- **需要订阅局部状态**: 使用Zustand Store（细粒度订阅）
- **需要依赖注入或提供器模式**: 使用React Context
- **需要与组件生命周期绑定**: 使用React Context

### 5. 类型定义应该放在哪里？

**判断标准**:
- **API响应类型**: 放在对应的 `{module}-service.types.ts`
- **组件Props类型**: 放在组件文件内部
- **跨模块共享类型**: 放在 `src/types/core/`
- **特定协议类型**: 放在 `src/types/v1/`
