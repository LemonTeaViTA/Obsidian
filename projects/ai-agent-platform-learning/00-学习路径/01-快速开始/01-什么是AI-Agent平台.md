# 什么是 AI Agent 平台

> 🎯 目标：10分钟理解 AI Agent 平台的核心概念  
> 📊 难度：⭐⭐  
> 🔗 前置：无

---

## 一句话总结

**AI Agent 平台是一个基于 Claude 的代码开发自动化平台，从 PRD 到上线全流程自动化，支持可配置的工作流和多任务并行开发。**

---

## 💡 它解决什么问题？

### 传统开发流程的痛点
```
产品写 PRD → 开发理解需求 → 架构设计 → 编码 → 测试 → CR → 上线
            ↑_____________________________________________↑
                     全靠人工，重复劳动，效率低
```

### AI Agent 平台的方案
```
产品写 PRD → AI 自动化全流程
              ├─ 自动审核 PRD
              ├─ 自动划分领域
              ├─ 自动拆分应用
              ├─ 自动编写代码
              ├─ 自动编写测试
              └─ 自动生成 CR 报告

人工只需：审批关键节点 + 最终 CR
```

---

## 🏗️ 三大核心系统

### 系统1：ai24（平台管理侧）
```
技术栈：Spring Boot + MyBatis + Redis + MQ
职责：
  - 任务管理（创建、状态管理、数据存储）
  - 工作流配置（spec_workflow 驱动）
  - 审批流程（approval_item）
  - WebSocket 实时推送
```

### 系统2：code-agent（Agent执行侧）
```
技术栈：Python + Flask + Claude SDK
职责：
  - 接收任务（Flask API）
  - 执行任务（调用 Claude）
  - 工具集成（MCP 工具）
  - 状态上报（回调 ai24）
```

### 系统3：ai-program-factory（前端展示侧）
```
技术栈：React + TypeScript + WebSocket
职责：
  - 任务创建表单
  - 实时展示进度
  - 审批交互
  - 产物查看
```

## 🔄 核心工作流程

### 完整八站链路

```
站点1：前端发起
  ↓ POST /api/taskInfo/create
站点2：ai24 Controller（参数校验）
  ↓ 调用 Service
站点3：ai24 Service（任务创建）
  ↓ 存库，生成 taskId
站点4：ai24 下发任务
  ↓ POST /task/perform → code-agent
站点5：code-agent 初始化
  ↓ 拉取 DEP、克隆代码
站点6：code-agent 执行
  ↓ Claude SDK 执行工作流
站点7：code-agent 上报
  ↓ POST /api/task/notify/* → ai24
站点8：ai24 更新状态
  ↓ WebSocket 推送前端
```

## 🎯 核心创新点

### 创新1：可配置的工作流引擎

**问题**：不同需求类型流程不同，硬编码无法扩展

**方案**：数据库配置驱动
```sql
spec_workflow（工作流配置）
  ↓
spec_stage（阶段配置）
  ↓
spec_convention（约束规范）
```

**效果**：
- ✅ 大需求：PRD审核 → 领域划分 → 应用拆分 → TDD开发
- ✅ 普通任务：Proposal → Apply → Build
- ✅ 灵活组合，无需改代码

---

### 创新2：编排任务（FAN_OUT）并行开发

**问题**：一个大需求拆分为多个应用，串行开发太慢

**方案**：编排任务 + MQ解耦
```
应用拆分审批通过
  ↓
投递 MQ 消息（4个应用）
  ├─ order-service
  ├─ payment-service
  ├─ inventory-service
  └─ user-service
  ↓
并行创建 4 个子任务
  ↓
4 个 code-agent 同时执行（工作目录隔离）
```

**效果**：
- ✅ 4个应用并行开发
- ✅ 开发时间 = 最慢的那个（不是总和）
- ✅ 单个失败不影响其他

---

### 创新3：TDD Hook 强制测试

**问题**：AI 可能跳过测试或先写实现

**方案**：Hook 机制强制执行
```
TddTestLockHook（测试文件锁）
  - 测试写完后锁定，禁止修改
  - 强制先写测试、再写实现

TddStopGateHook（停止门禁）
  - 检查 manifest.json
  - 所有测试通过才允许结束
  - 连续3次自检放行
```

**效果**：
- ✅ 保证测试覆盖
- ✅ 保证测试优先
- ✅ AI 无法"作弊"

---

### 创新4：MCP 工具生态

**问题**：AI 需要调用外部系统（DEP、GitLab、VOS等）

**方案**：MCP（Model Context Protocol）统一集成
```
code-agent 
  ↓ JSON-RPC
MCP Server（多个）
  ├─ ai24-mcp（查询任务）
  ├─ dep-mcp（查询需求）
  ├─ ui-test-mcp（UI测试）
  └─ backstage-mcp（后端服务）
```

**效果**：
- ✅ 统一的工具接口
- ✅ 可扩展的工具生态
- ✅ AI 能调用企业内部系统

## 🌟 实际应用场景

### 场景1：大需求开发
```
输入：一个复杂的订单系统 PRD
过程：
  1. PRD审核（10分钟）
  2. 领域划分（30分钟）- AI划分为订单域、支付域、库存域
  3. 应用拆分（30分钟）- 每个域拆分为几个服务
  4. 并行开发（2小时）- 8个服务同时开发
  5. CR审查（人工）
输出：8个应用的完整代码 + 测试
```

### 场景2：普通功能开发
```
输入：一个简单的用户注册功能 PRD
过程：
  1. Proposal（设计测试，20分钟）
  2. Apply（TDD开发，40分钟）
  3. Build（编译验证，10分钟）
输出：完整代码 + 测试 + CR报告
```

## 💎 面试可讲的点

1. **可配置的工作流引擎**
   - 数据库驱动，不是硬编码
   - 支持不同需求类型的灵活流程

2. **编排任务并行开发**
   - MQ解耦 + 多线程并发
   - 工作目录隔离避免冲突

3. **TDD Hook 强制执行**
   - 保证代码质量
   - 测试文件锁 + 停止门禁

4. **跨系统协作**
   - 三个系统（前端+ai24+code-agent）
   - HTTP + WebSocket + MQ
