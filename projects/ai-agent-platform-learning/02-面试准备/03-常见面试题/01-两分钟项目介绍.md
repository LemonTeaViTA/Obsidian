# 两分钟项目介绍模板

> 🎯 目标：准备好开场的项目介绍  
> ⏱️ 时长：2分钟

---

## 📝 标准版本（2分钟）

### 开场（30秒）- 是什么

```
"我负责开发的是一个 AI Agent 平台，核心功能是基于 Claude 实现代码自动化开发。

用户只需要提交 PRD 需求文档，系统就能自动完成从需求审核、架构设计、
代码开发、测试编写到代码审查的全流程，最后交付可运行的代码和测试。

这个平台解决了传统开发流程中重复劳动多、效率低的问题。"
```

---

### 技术栈（30秒）- 用什么

```
"技术架构上，我们采用了三个系统协作：

前端是 React + TypeScript，负责任务创建和进度展示；

后端是 Spring Boot + MyBatis + Redis + MQ，负责任务管理、
工作流配置和审批流程；

Agent 执行侧是 Python + Flask + Claude SDK，负责真正调用 AI 执行任务。

三个系统通过 HTTP 和 WebSocket 通信，实现实时状态同步。"
```

---

### 个人贡献（60秒）- 做了什么

```
"我主要负责以下几个核心模块：

第一，工作流引擎的设计。通过数据库配置驱动流程，支持灵活的工作流定义。
不同需求类型可以走不同流程，新增流程不需要改代码，只需要配置数据库。

第二，编排任务的 FAN_OUT 并行机制。一个大需求会拆分为多个应用，
通过 MQ 解耦实现并行开发。我解决了多 Agent 并发时的资源冲突问题，
通过工作目录隔离技术，让4个应用可以同时开发，效率提升了4倍。

第三，审批拒绝后的重试机制。当产品经理拒绝审批时，系统会将拒绝原因
反馈给 AI，让 AI 重新分析调整。我设计了重试次数限制和补偿机制，
避免无限循环，最多重试3次后转人工处理。

遇到的最大挑战是多 Agent 并发冲突，通过工作目录隔离和动态资源分配解决了。"
```

## 🎯 精简版本（1分钟）

```
"我负责的是一个 AI Agent 平台，基于 Claude 实现代码自动化开发。
用户提交 PRD，系统自动完成需求审核、架构设计、代码开发、测试的全流程。

技术栈是 React + Spring Boot + Python，三个系统协作。

我主要做了三个模块：
一是可配置的工作流引擎，数据库驱动，支持灵活流程定义；
二是编排任务的 FAN_OUT 并行机制，通过 MQ 解耦实现多应用并行开发，效率提升4倍；
三是审批重试机制，AI 根据反馈调整方案，最多重试3次。

最大挑战是多 Agent 并发冲突，通过工作目录隔离解决了。"
```

## 💡 扩展版本（3分钟）

在标准版基础上，可以加入：

### 核心创新点（+30秒）
```
"这个项目的核心创新点有三个：

一是可配置工作流引擎，通过 spec_workflow 三层表结构，
实现了流程的灵活定义和版本管理；

二是 TDD Hook 强制测试机制，通过文件锁定和停止门禁，
保证 AI 先写测试、再写实现，提高代码质量；

三是 MCP 工具集成生态，通过统一的协议接入企业内部系统，
让 AI 能调用 DEP、GitLab、VOS 等工具。"
```

### 项目规模（+15秒）
```
"项目目前代码量约 5万+ 行，支撑公司内部 100+ 个开发需求的自动化。
平均一个中等复杂度的需求，从提交到代码产出大约 40分钟，
相比人工开发节省了 70% 的时间。"
```

### 技术挑战（+15秒）
```
"除了并发冲突，还解决了几个技术难点：
一是 WebSocket 多实例同步，通过 Redis Pub/Sub 实现；
二是测试文件锁定后的问题处理，依赖 CR 阶段人工审查；
三是 MQ 消息丢失的补偿机制，定时扫描重试。"
```

## 🎭 不同场景的调整

### 场景1：技术面试
重点：架构设计、技术难点、解决方案
```
多讲：工作流引擎设计、并发冲突解决、策略模式
少讲：业务价值、项目规模
```

### 场景2：项目面试/交叉面
重点：业务价值、项目管理、团队协作
```
多讲：效率提升4倍、节省70%时间、支撑100+需求
少讲：具体技术实现细节
```

### 场景3：HR面/总监面
重点：项目意义、个人成长、影响力
```
多讲：解决了什么问题、有什么价值、学到了什么
少讲：技术细节
```

```
项目规模：

- 支撑需求：100+ 个

性能提升：
- 并行开发：效率提升 4倍
- 时间节省：70%
- 开发时长：40分钟（中等复杂度）

- 重试次数：最多 3次

```

## 🎤 练习技巧

### 技巧1：对着镜子练
- 看着自己的表情和手势
- 注意语速和停顿
- 确保2分钟内说完

### 技巧2：录音练习
- 听自己的语气是否自然
- 检查有无口头禅（"然后"、"就是"）
- 调整节奏

### 技巧3：找朋友模拟
- 让朋友提问
- 练习随机应变
- 获得反馈

### 技巧4：准备变体
- 1分钟精简版
- 2分钟标准版
- 3分钟扩展版
- 根据面试官反应调整

---

## ⚠️ 注意事项

### ❌ 避免
1. 不要背书式朗读（要自然）
2. 不要用太多技术黑话（要解释清楚）
3. 不要说得太快（要给面试官消化时间）
4. 不要夸大（数据要真实）

### ✅ 要做
1. 开头说清楚"是什么"
2. 技术栈简明扼要
3. 个人贡献要突出
4. 准备好数据支撑
5. 提前想好追问

---

## 🔗 后续追问准备

面试官可能的追问：

**Q1：你负责了哪部分？**
→ 准备：清晰的模块划分，哪些是你独立完成

**Q2：遇到最大的挑战是什么？**
→ 准备：多 Agent 并发冲突的详细回答

**Q3：如果重新做会怎么优化？**
→ 准备：测试解锁接口、自动冲突检测、智能重试

**Q4：这个项目的业务价值是什么？**
→ 准备：效率提升、成本节约、开发体验

**Q5：项目还有什么不足？**
→ 准备：诚实面对（测试锁定、补偿机制、监控告警）
