## 🎯 核心认知

### 什么是多人审批？

**单人审批** (旧版本):
```
任务提交审批 → 指定审批人A → A 通过/驳回
```

**多人审批** (新版本):
```
任务提交审批 → 指定候选人列表 [A, B, C] → 其中任意一人通过/驳回 → 回写实际审批人
```

**核心变化**:
- ✅ 支持多个候选审批人
- ✅ 任意一人审批即生效 (OR 逻辑)
- ✅ 记录实际审批人 (回写机制)
- ✅ 查询当前用户审批权限状态

**典型场景**:
- 需求评审：任意一位产品经理可以审批
- 代码评审：团队内任意一位技术负责人可以审批
- 测试审批：任意一位测试工程师可以审批

## 一、数据模型设计

### 1.1 核心字段变更

**审批项表 (spec_approval_item)**:

| 字段名 | 类型 | 说明 | 变更 |
|-------|------|------|------|
| `confirmer` | VARCHAR(500) | 候选审批人列表 (逗号分隔) | 🆕 支持多人 |
| `actual_confirmer` | VARCHAR(100) | 实际审批人 | 🆕 新增字段 |
| `approval_status` | INT | 审批状态 (0=待审批, 1=通过, 2=驳回) | - |

**示例数据**:
```sql
INSERT INTO spec_approval_item VALUES (
    id = 12345,
    confirmer = 'zhangsan,lisi,wangwu',  -- 候选人列表
    actual_confirmer = 'lisi',            -- 实际审批人
    approval_status = 1,                  -- 已通过
    ...
);
```

## 二、核心服务实现

### 2.1 ApprovalItemService 多人审批逻辑

**文件路径**: `ai24-core/service/impl/ApprovalItemServiceImpl.java`

**关键方法1: 创建审批项**

```java
public Long createApprovalItem(CreateApprovalItemRequest request) {
    // 1. 解析候选审批人列表
    String confirmer = request.getConfirmer(); // 可能是 "zhangsan,lisi,wangwu"
    
    // 2. 创建审批项
    SpecApprovalItemDO item = new SpecApprovalItemDO();
    item.setConfirmer(confirmer);  // 存储候选人列表
    item.setActualConfirmer(null);  // 实际审批人初始为空
    item.setApprovalStatus(ApprovalStatus.PENDING.getCode());
    
    // 3. 保存到数据库
    specApprovalItemManager.insert(item);
    
    // 4. 为每个候选人创建跟进记录
    List<String> confirmerList = UsernameCsvUtils.splitUsernames(confirmer);
    for (String username : confirmerList) {
        createFollowerRecord(item.getId(), username, FollowerRole.APPROVER);
    }
    
    return item.getId();
}
```

**关键方法2: 更新审批人**

```java
public void updateConfirmer(UpdateConfirmerRequest request) {
    Long approvalItemId = request.getApprovalItemId();
    String newConfirmer = request.getConfirmer();
    
    // 1. 查询现有审批项
    SpecApprovalItemDO item = specApprovalItemManager.getById(approvalItemId);
    
    // 2. 检查是否已审批
    if (item.getApprovalStatus() != ApprovalStatus.PENDING.getCode()) {
        throw new BizException("审批项已完成，无法修改审批人");
    }
    
    // 3. 更新候选人列表
    item.setConfirmer(newConfirmer);
    specApprovalItemManager.updateById(item);
    
    // 4. 同步更新跟进人记录
    syncFollowerRecords(approvalItemId, newConfirmer);
}
```

**关键方法3: 执行审批操作**

```java
public void approveOrReject(Long approvalItemId, String operator, boolean approve) {
    // 1. 查询审批项
    SpecApprovalItemDO item = specApprovalItemManager.getById(approvalItemId);
    
    // 2. 权限校验：operator 必须在候选人列表中
    List<String> confirmerList = UsernameCsvUtils.splitUsernames(item.getConfirmer());
    if (!confirmerList.contains(operator)) {
        throw new BizException("您不在审批人列表中，无权审批");
    }
    
    // 3. 状态校验：必须是待审批状态
    if (item.getApprovalStatus() != ApprovalStatus.PENDING.getCode()) {
        throw new BizException("审批项已完成，无法重复审批");
    }
    
    // 4. 回写实际审批人
    item.setActualConfirmer(operator);
    item.setApprovalStatus(approve ? ApprovalStatus.APPROVED.getCode() : ApprovalStatus.REJECTED.getCode());
    item.setApprovalTime(new Date());
    specApprovalItemManager.updateById(item);
    
    // 5. 触发后续流程
    if (approve) {
        triggerNextStage(item.getTaskId());
    } else {
        notifyRejection(item.getTaskId(), operator);
    }
}
```

### 2.2 UsernameCsvUtils 工具类 (新增)

**文件路径**: `ai24-core/utils/UsernameCsvUtils.java`

**核心功能**: 处理逗号分隔的用户名列表

```java
public class UsernameCsvUtils {
    
    /**
     * 分割逗号分隔的用户名字符串
     * @param csv 逗号分隔的用户名，如 "zhangsan,lisi,wangwu"
     * @return 用户名列表
     */
    public static List<String> splitUsernames(String csv) {
        if (StringUtils.isBlank(csv)) {
            return Collections.emptyList();
        }
        
        return Arrays.stream(csv.split(","))
                .map(String::trim)
                .filter(StringUtils::isNotBlank)
                .collect(Collectors.toList());
    }
    
    /**
     * 合并用户名列表为逗号分隔字符串
     * @param usernames 用户名列表
     * @return 逗号分隔的字符串
     */
    public static String joinUsernames(List<String> usernames) {
        if (CollectionUtils.isEmpty(usernames)) {
            return "";
        }
        
        return usernames.stream()
                .filter(StringUtils::isNotBlank)
                .map(String::trim)
                .collect(Collectors.joining(","));
    }
    
    /**
     * 检查用户是否在候选人列表中
     * @param csv 候选人CSV字符串
     * @param username 要检查的用户名
     * @return true 如果用户在列表中
     */
    public static boolean contains(String csv, String username) {
        List<String> list = splitUsernames(csv);
        return list.contains(username);
    }
}
```

**使用示例**:
```java
String confirmer = "zhangsan,lisi,wangwu";

// 分割
List<String> list = UsernameCsvUtils.splitUsernames(confirmer);
// ["zhangsan", "lisi", "wangwu"]

// 检查
boolean canApprove = UsernameCsvUtils.contains(confirmer, "lisi");
// true

// 合并
String newConfirmer = UsernameCsvUtils.joinUsernames(Arrays.asList("alice", "bob"));
// "alice,bob"
```

## 三、当前用户审批状态查询

### 3.1 ApprovalCurrentUserStateResolver

**文件路径**: `ai24-core/service/approval/ApprovalCurrentUserStateResolver.java`

**功能**: 解析当前用户在某个审批项中的状态和权限

```java
public class ApprovalCurrentUserStateResolver {
    
    /**
     * 解析当前用户的审批状态
     * @param approvalItemId 审批项ID
     * @param currentUsername 当前登录用户
     * @return 审批状态信息
     */
    public ApprovalUserState resolveState(Long approvalItemId, String currentUsername) {
        // 1. 查询审批项
        SpecApprovalItemDO item = specApprovalItemManager.getById(approvalItemId);
        
        // 2. 解析候选人列表
        List<String> confirmerList = UsernameCsvUtils.splitUsernames(item.getConfirmer());
        
        // 3. 判断当前用户是否在候选人中
        boolean isCandidate = confirmerList.contains(currentUsername);
        
        // 4. 判断当前用户是否有审批权限
        boolean canApprove = isCandidate && item.getApprovalStatus() == ApprovalStatus.PENDING.getCode();
        
        // 5. 判断是否已被其他人审批
        boolean approvedByOthers = item.getActualConfirmer() != null 
                                    && !item.getActualConfirmer().equals(currentUsername);
        
        // 6. 构造返回结果
        return ApprovalUserState.builder()
                .isCandidate(isCandidate)
                .canApprove(canApprove)
                .approvalStatus(item.getApprovalStatus())
                .actualConfirmer(item.getActualConfirmer())
                .approvedByOthers(approvedByOthers)
                .candidateList(confirmerList)
                .build();
    }
}
```

### 3.2 ApprovalUserState 数据结构

```java
@Data
@Builder
public class ApprovalUserState {
    /** 当前用户是否在候选人列表中 */
    private Boolean isCandidate;
    
    /** 当前用户是否可以审批 (候选人 && 待审批状态) */
    private Boolean canApprove;
    
    /** 审批状态 (0=待审批, 1=通过, 2=驳回) */
    private Integer approvalStatus;
    
    /** 实际审批人 (谁最终完成了审批) */
    private String actualConfirmer;
    
    /** 是否被其他人审批 */
    private Boolean approvedByOthers;
    
    /** 候选人列表 */
    private List<String> candidateList;
}
```

### 3.3 前端展示逻辑

```javascript
// 查询当前用户审批状态
const response = await api.getApprovalUserState(approvalItemId);

if (response.canApprove) {
    // 显示"通过"和"驳回"按钮
    showApprovalButtons(true);
} else if (response.approvedByOthers) {
    // 显示"已被 xxx 审批"
    showMessage(`已被 ${response.actualConfirmer} 审批`);
} else if (!response.isCandidate) {
    // 显示"您不在审批人列表中"
    showMessage('您不在审批人列表中');
}
```

### 5.1 跟进人表设计

**表名**: `spec_task_follower`

| `username` | VARCHAR(100) | 跟进人用户名 |
| `follower_role` | INT | 角色 (1=创建者, 2=审批人, 3=观察者) |

### 5.2 同步逻辑

```java
private void syncFollowerRecords(Long approvalItemId, String newConfirmer) {
    // 1. 删除旧的跟进人记录
    specTaskFollowerManager.deleteBySourceId(approvalItemId);
    
    // 2. 解析新的审批人列表
    List<String> confirmerList = UsernameCsvUtils.splitUsernames(newConfirmer);
    
    // 3. 为每个审批人创建跟进记录
    for (String username : confirmerList) {
        SpecTaskFollowerDO follower = new SpecTaskFollowerDO();
        follower.setTaskId(getTaskId(approvalItemId));
        follower.setUsername(username);
        follower.setFollowerRole(FollowerRole.APPROVER.getCode());
        follower.setSourceId(approvalItemId);
        specTaskFollowerManager.insert(follower);
    }
}
```

**作用**:
- 审批人可以在"我的待办"中看到需要审批的任务
- 支持按审批人筛选任务
- 记录审批历史和责任人

## 七、常见问题

### Q1: 多人审批是 OR 逻辑还是 AND 逻辑？

**A**: 当前实现是 **OR 逻辑** (任意一人审批即生效)。

如果需要 AND 逻辑 (所有人都审批才通过)，需要修改：
1. 增加 `approval_count` 字段记录已审批人数
2. 每次审批时累加计数
3. 当计数等于候选人数量时才更新状态

### Q2: 如果审批人列表中包含重复用户名会怎样？

**A**: `UsernameCsvUtils.splitUsernames()` 不会自动去重，建议在创建时校验：

```java
List<String> confirmerList = UsernameCsvUtils.splitUsernames(confirmer);
Set<String> uniqueSet = new HashSet<>(confirmerList);
if (uniqueSet.size() != confirmerList.size()) {
    throw new BizException("审批人列表中存在重复用户");
}
```

### Q3: 能否支持审批人分组 (如 "产品组" vs "技术组")？

**A**: 当前版本不支持。如需实现：
1. 增加 `confirmer_group` 字段
2. 在查询时动态展开组成员
3. 权限校验时检查用户所属组

### Q4: 实际审批人字段的长度够用吗？

**A**: `actual_confirmer VARCHAR(100)` 只存储单个用户名，长度足够。如果用户名特别长或需要存储额外信息 (如审批时间)，建议改为 JSON 格式。

## 八、最佳实践

### 8.1 审批人数量建议

- ✅ 推荐: 2-5 人 (保证有人审批，不至于全员通知)
- ⚠️ 谨慎: 6-10 人 (可能导致责任分散)
- ❌ 不推荐: 10+ 人 (建议改为分组审批)

### 8.2 审批人选择策略

```java
// 好的示例: 明确的职责范围
confirmer = "pm_lead,pm_senior";  // 资深产品经理

// 不好的示例: 过于宽泛
confirmer = "all_pms";  // 所有产品经理 (责任不明确)
```

### 8.3 审批超时处理

建议增加超时机制：
```java
// 审批项创建24小时后仍未审批，自动提醒
if (item.getCreateTime().before(24.hours.ago()) && item.getApprovalStatus() == PENDING) {
    sendReminderToAllCandidates(item);
}
```
