# 会话持久化与快照

**是什么**：两套机制：JSONL 持久化（恢复对话历史）+ Git Side-History 快照（回滚文件状态）。

**为什么**：恢复对话和回滚文件是两个不同的需求，一套机制无法同时满足。

**怎么做**：
- JSONL 持久化：每条消息追加写入，不覆盖，`--continue` 启动时读取恢复完整对话历史
- Git Side-History 快照：在项目目录外维护一个 shadow git repo，每次工具执行后自动 commit 一次文件快照
- `/restore` 命令：列出快照历史，选择后用 shadow git 的内容覆盖当前工作区
- 两套机制相互独立：JSONL 记录"说了什么"，shadow git 记录"做了什么（文件变化）"

**关键权衡**：shadow git 在项目目录外，不污染用户自己的 git 历史，代价是需要额外维护一个隐藏的 git repo。

## 面试 Q&A

**Q：为什么不直接用用户项目的 git 来做快照？**
会污染用户的 git 历史（每次工具调用都产生一个 commit），影响 git log 可读性，也可能和用户自己的提交产生冲突。shadow git 隔离了这些问题。

**Q：JSONL 为什么追加写而不是每次覆盖？**
追加写不会因进程崩溃丢失之前的数据；覆盖写如果在写入中途崩溃会损坏整个历史文件。JSONL 每行独立，损坏最多影响最后一条记录。

**Q：对话历史和文件快照为什么要分开存？**
恢复对话只需要消息序列，不需要文件状态；回滚文件不需要重放对话。合在一起反而增加复杂度，分开让每套机制职责单一。
