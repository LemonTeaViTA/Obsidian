# 安全纵深防御

**是什么**：多层安全机制，防止 Agent 执行有破坏性的操作。

**为什么**：自主 Agent 有权执行 shell 命令和修改文件，一旦出错可能不可逆，必须有防护。

**怎么做**：
- HITL 三级：只读操作自动允许；写文件/执行命令显示 diff 等用户确认（y/n）；危险命令黑名单直接阻断
- 路径围栏：文件操作限制在项目目录内，防止 `../../` 路径逃逸访问系统文件
- 命令黑名单：预定义的高危命令列表，Agent 无法执行
- 审计日志：每次工具调用记录时间戳、工具名、参数、结果，可事后追溯

**关键权衡**：HITL 确认步骤打断了自动化流程，但对破坏性操作宁可多一次确认。纯自动化场景可以降低确认级别，默认偏保守。

---

## 面试 Q&A

**Q：路径围栏怎么实现？**
对文件工具传入的路径做规范化（resolve 绝对路径），然后检查是否在项目根目录的子树内。`../` 跳出后规范化路径不再以项目目录开头，直接拒绝。

**Q：HITL 三级的划分标准是什么？**
按操作可逆性：只读操作天然可逆；写操作有快照可回滚；危险命令可能造成不可回滚的破坏，必须阻断。

**Q：命令黑名单 vs 白名单哪个更安全？**
白名单更安全（只允许已知安全的命令），但会严重限制 Agent 能力。项目选择黑名单 + HITL 兜底——黑名单拦不住的，HITL 确认步骤还有机会介入。
