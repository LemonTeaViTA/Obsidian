# 可观测性与用户钩子系统

**是什么**：成本追踪（CostLedger）+ 用户可自定义的钩子系统（PreToolUse / PostToolUse / Stop）。

**为什么**：Agent 消耗 token 要可见；钩子让用户扩展 Agent 行为而不需要修改 CLI 源码。

**怎么做**：
- CostLedger：按模型分桶记录 token 用量和费用，`/cost` 命令展示分模型明细
- 三类钩子：PreToolUse（工具调用前）、PostToolUse（工具调用后）、Stop（会话结束）
- 钩子实现为用户自定义的 shell 脚本，通过环境变量接收上下文（工具名、参数、结果）
- 钩子脚本返回非零退出码可中断当前工具执行

**关键权衡**：钩子用 shell 脚本实现，灵活性极高（任意语言、任意操作），但 shell 脚本有注入风险，需要在受信任的环境中使用。

## 面试 Q&A

**Q：为什么选 shell 脚本而不是 Java SPI 插件？**
shell 脚本零门槛（用户不需要了解项目内部结构），任意语言编写，启动即可用。Java SPI 需要打包、实现接口，门槛高。CLI 工具的扩展点优先考虑运维友好性。

**Q：PreToolUse 钩子可以做什么？**
典型用途：记录审计日志、二次确认危险操作、注入额外环境变量。返回非零退出码可以在钩子层拦截工具执行，作为 HITL 机制的补充。

**Q：CostLedger 按模型分桶有什么好处？**
多模型场景下（主模型 + Reviewer 用不同模型 + fallback 切换），分桶可以精确看到每个模型各自花了多少钱，便于优化模型选择策略。
