# 记忆系统

**是什么**：三层记忆架构，让 Agent 在单次上下文之外也能访问相关知识。

**为什么**：相关信息可能来自本轮对话（短期）、上次会话（长期）、或项目文档（项目级），单一存储无法覆盖。

**怎么做**：
- 短期记忆：会话内 LinkedHashMap，O(1) 查找
- 长期记忆：跨会话持久化文件，write-behind 异步写入（daemon 线程每秒检查 dirty flag，不阻塞主流程）
- 项目级记忆：PAI.md 文件随代码库存在，支持 `@path` 行内导入（三重防护：深度限制/环检/子树限制）
- 混合检索：精确包含匹配优先 → jieba 分词 + 时间衰减评分 → 长期记忆 ×1.2 加权

**关键权衡**：长期记忆 1.2× 加权确保跨会话积累的知识优先级高于本轮临时记忆，但如果长期记忆内容过时，这个加权会产生反效果。

---

## 面试 Q&A

**Q：为什么长期持久化用 write-behind 而不是同步写？**
Agent 每轮可能频繁触发记忆更新，同步写磁盘会阻塞响应。write-behind 把写操作异步化，用 dirty flag 合并多次更新为一次写入，只在极端崩溃情况下丢失最近几秒的记忆。

**Q：PAI.md 的 @path 导入为什么要三重防护？**
没有深度限制 → 栈溢出；没有环检 → 无限递归；没有子树限制 → 可以导入 `/etc/passwd` 等系统文件。这是对用户开放的功能，必须做边界防御。

**Q：混合检索为什么不只用语义搜索？**
记忆条目通常很短（一两句话），语义 embedding 在短文本上效果不稳定；jieba 分词 + 关键词匹配对中文短文本更可靠。精确匹配优先保证"用户刚说的东西"一定能找到。
