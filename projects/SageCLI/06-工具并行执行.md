# 工具并行执行

**是什么**：LLM 单次响应可返回多个 tool_call，并行执行后有序回收结果。

**为什么**：串行执行多工具浪费时间，LLM 返回多个独立工具调用时完全可以并行，减少 wall-clock time。

**怎么做**：
- 固定线程池（大小 4，daemon 线程），对 LLM 返回的 tool_call 列表批量提交
- 按提交下标有序 `Future.get()`，不是按完成顺序收结果
- 单工具抛异常不影响其他工具继续执行，异常结果以错误消息形式返回给 LLM

**关键权衡**：有序回收（按提交顺序）而非按完成顺序——保证 LLM 收到的 observation 序列与 tool_call 序列一致，否则 LLM 会混淆哪个结果对应哪个调用。

---

## 面试 Q&A

**Q：线程池大小为什么是 4？**
工具调用主要是 I/O 密集（文件读写、命令执行），4 个线程足以覆盖大部分并发场景，同时不会创建过多线程。这是经验值，不是精确计算。

**Q：有序回收为什么重要？**
LLM 上下文里 tool_call 和 tool result 是按 id 配对的。如果按完成顺序收结果，result 顺序可能与 tool_call 不一致，LLM 可能把 result A 当成 tool_call B 的结果处理，导致逻辑错误。
