# SageCLI 面试速记卡

> 1小时速览版。从上往下读，加粗部分是高频追问。

---

## ⚡ 开场 30 秒

> SageCLI 是对标 Claude Code 的本地 Java Agent CLI，用自然语言驱动代码开发、调试和自动化。核心是三条执行路径——简单任务走 ReAct，多步依赖走 Plan-and-Execute（DAG 并行），需要质量审查走 Multi-Agent，三条共享同一套工具和记忆。底下支撑有数据驱动多模型适配 + 故障转移、长上下文动态压缩、MCP 工具生态、安全纵深防御。**比较得意的是：多模型注册表（加平台只改配置，不写代码）和绝对预留的压缩策略（不用比率，跨窗口行为一致）。**

---

## 🔴 最高频问题（必须流利）

### Q1：三条路径的区别是什么？各适合什么场景？

| 路径 | 适合场景 | 核心机制 |
|------|----------|----------|
| ReAct | 简单探索，灵活 | while循环，LLM停止调工具即结束 |
| Plan-Execute | 多步骤有依赖，可并行 | LLM生成DAG → 拓扑排序 → 分批并行 |
| Multi-Agent | 需要质量门控，有审查 | Planner/Worker/Reviewer三角色 |

**一句话收口：这是"规划-执行耦合度 vs 可控性/可并行"的谱系，不是越复杂越好。**

---

### Q2：ReAct 怎么防止死循环？

三道保险阀（优先级从高到低）：
1. **停滞检测**：对每轮工具调用集合取签名，连续3轮相同 → 判停滞
2. Token 上限（默认不限，可配）
3. 硬轮数上限（50轮）

**追问：停滞检测的局限？**
只能抓"完全相同的重复动作"。A/B 两工具交替横跳、参数含时间戳——这些只靠硬轮数兜底。这是有意的工程近似，简单够用。

---

### Q3：Plan-and-Execute 怎么处理循环依赖？并行怎么实现？

- **环检**：DFS 拓扑排序 + visiting/visited 双集合，visiting 中再次命中 = 有环 → 抛异常
- **并行**：拓扑排序后分层，同层节点无依赖关系 → 固定线程池（最多4）并行执行
- **计划解析两遍扫描**：第一遍建节点，第二遍连依赖边（解决前向引用 + 统一重编号）
- **重规划**：任务失败且进度 < 50% 时重新规划，最多2次

---

### Q4：Multi-Agent 并发时怎么保证线程安全？

- **Worker 池化**（BlockingQueue take/offer）：防同一实例被并发复用，Worker 有可变对话历史
- **Reviewer 按步 new 独立实例**：无状态，无竞争
- 状态更新加 synchronized，per-step 独立缓冲区，按顺序 flush 输出

**追问：Reviewer 审查失败默认不通过，但 Reviewer LLM 调用失败反而放行，矛盾吗？**
不矛盾。前者是"内容不可信"（fail-closed 拒绝）；后者是"服务不可用"（审查器故障不应阻塞已产出的 Worker 结果，fail-open 放行）。两种情况，方向相反都合理。

---

### Q5：多模型适配怎么做的？为什么不用类继承？

- `LlmClient` 接口 → `AbstractOpenAiCompatibleClient` 通用基类 → **`SeriesQuirks` 数据驱动注册表**
- 每个模型系列的差异（endpoint/窗口/reasoning字段名/图片格式/是否支持工具）全写进一个 record，查表即用
- **加一个新平台：往注册表加一条记录，不写新类**

类继承 = 差异是代码，加平台必须写子类；数据驱动 = 差异是配置，加平台只改注册表。这是 LiteLLM 的核心思路。

---

### Q6：长上下文压缩策略？为什么用绝对值不用比率？

**触发线 = 窗口大小 - summaryReserve - buffer**（绝对值）

- 比率（如80%）：128k窗口触发点102k，8k窗口触发点6.4k → 相差悬殊，行为不稳定
- 绝对值：固定"留多少余量"的语义，跨模型行为一致

**分割点必须落在 user turn 边界**：assistant 的 tool_call 和 tool result 是强配对，切断会破坏格式。

---

### Q7：安全机制有哪些？

**四层**：
1. **命令黑名单**：HITL 之前先拦截（sudo/rm -rf/mkfs/curl|sh 等）
2. **HITL 三级审批**：只读自动允许；写文件/执行命令展示确认；危险命令阻断
3. **路径围栏**：文件操作必须在项目目录内，防 `../../` 逃逸
4. **审计日志**：危险操作按天写 JSONL，脱敏凭证

## 🟡 次高频问题（说清楚要点）

### Q：工具并行执行怎么保证结果顺序？

固定线程池并行执行，按**提交下标有序 Future.get()**（不是按完成顺序）。LLM 上下文里 tool_call 和 tool result 是按 id 配对的，乱序会导致 LLM 混淆。

### Q：记忆系统三层是什么？

- 短期：会话内，O(1)查找
- 长期：跨会话持久化，write-behind 异步（不阻塞响应）
- 项目级：PAI.md 随代码库，`@path` 行内导入（三重防护：深度/环检/子树）

### Q：MCP 怎么集成？SchemaSanitizer 做什么？

两种 transport：stdio（本地子进程）和 HTTP SSE（远端）。SchemaSanitizer 清洗第三方 MCP server 返回的不规范 JSON Schema，防止目标模型拒绝工具注册。

### Q：代码库检索怎么实现？

- 通路A：ripgrep 优先（快），不可用降级 Java 遍历；三态可用性缓存（启动时探测一次）
- 通路B：`/index` 触发，JavaParser AST 分块 → embedding → SQLite 向量索引
- 混合评分：语义分 + 关键词基础分(0.3) + 分级加分 + 类型加分
