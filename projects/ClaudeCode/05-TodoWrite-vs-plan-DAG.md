# CC 怎么管任务清单（TodoWrite）

> **一句话定位**：CC 的 todo 不是"执行引擎"，而是**一块模型给自己管的草稿板**——它在上面记"要做哪几件事、现在做到哪了"，主要是**给自己看**（保持思路）、顺便给用户看到进度。

---

## 一、先说清楚它不是什么

很容易把 todo 理解成某种"任务编排引擎"——列出一堆任务、有依赖关系、自动调度执行。**CC 的 todo 不是这个。** 它没有依赖、没有拓扑排序、不管执行。

它是什么？**一块模型自己管的草稿板**——就像你做一件复杂事时，在纸上列"第一步做 A、第二步做 B、第三步做 C"，做完一项划掉一项。它不会"自动执行 B"，只是让你记得"我现在该做 B 了"。

---

## 二、它的构造极简

一个 todo 列表，就是这么几个字段的数组：

| 字段 | 干什么 |
|---|---|
| `content` | 祈使态描述，"Run tests"（给自己看，记住要做啥） |
| `activeForm` | 进行态描述，"Running tests"（给进度条看，显示正在做啥） |
| `status` | 三态：待办 / 进行中 / 完成 |

工具每次调用时**传整个列表的新状态**，全表替换（不是增量更新）。

**强制规则：任意时刻恰好一个"进行中"**——不能同时标两件事在做，也不能没有一个在做（那说明没在推进）。

**UI 上几乎隐形**：todo 工具不像其他工具那样在终端里显眼地亮出来，它几乎藏起来——主要是**喂给模型自己看、以及驱动右侧进度条**，不是给用户看的交互工具。

---

## 三、prompt 教模型何时用、何时不用

todo 工具的价值全在 prompt 教的"纪律"上。

**何时该用**：
- **3 步以上的任务**（简单的两三步直接做就行，不值得记）。
- 用户给了一个多任务列表（那你就先列个 todo 对应它）。
- **复杂到你自己都容易忘下一步该干啥的事**——记下来保持思路。
- 收到新指令立即记、开工前标"进行中"、完成立即标"完成"。

**何时别用**：
- 单步、琐碎任务、纯对话——"只有一个琐碎任务时，直接做比记 todo 强"。

**完成纪律**（这条很重要）：
- **完成了立即标，不要攒着批量标**（否则进度条不动、用户以为卡了）。
- 测试没过、实现不全、有未解决的错误、找不到文件——**这些情况绝不能标"完成"**，得继续修。

---

## 四、一个精妙的"软提醒"：验证助推

有个有意思的细节：当模型**关掉一个有 3 项以上的 todo 列表、且没有一项是"验证"**时，工具返回的结果里会**追加一句系统提醒**，大意是"你刚做完几件事，考虑派一个验证 agent 去检查下，而不是直接在回复里列 caveats 自封 PARTIAL"。

**为什么是"提醒"不是"硬拦"？** 因为不是所有任务都需要验证。硬拦太死板，软提醒让模型自己判断。

**为什么在"最后一个任务关闭"这一刻提醒？** 因为这正是**最容易忘记验证就结束的那一刻**——刚做完最后一步、循环马上要退出了，这时候轻推一下"要不要验证"，效果最好。

这是 CC 反复用的一招：**在最容易犯错的时刻，用系统提醒轻推正确方向**——不是硬控制流，是软引导。（读文件遇到空文件、编辑失效检测，都是同一招。）

---

## 四点五、todo 之外：CC 的"目标驱动"是 /goal，不是 plan 引擎

容易有个疑问：todo 只是"草稿板"，那 CC 有没有"给个目标、让它自己干到完成"的能力？

**有，但不是传统的 plan 引擎（任务分解 + 依赖图 + 分步执行），而是一个极简的 `/goal` 命令**（v2.1.139+）：你设一个**完成条件**，Claude 自己一轮轮干下去、不还控制权给你，每轮后由一个**独立小模型**验收条件达成没，达成自动停。

- **todo**：模型给自己记的清单，提醒别漏步——**辅助记忆**。
- **/goal**：给一个"什么算完成"，模型自主反复推进 + 独立裁判验收——**目标驱动 + 客观收尾**。

关键认知：CC 走的是"**轻量目标驱动**"而非"重型规划"——不替模型拆解步骤，只给它明确终点 + 客观验收。这正好印证「模型越强，越不需要僵硬的 plan 引擎」。详见 [[CC-goal目标驱动自主工作]]。

> 补正：本篇标题里的「/plan DAG」是早期对照视角的遗留——CC 本身**没有** plan/DAG 引擎。它的"目标驱动"方案是上面说的 `/goal`（轻量、靠独立评估器验收），不是 DAG 编排。

---

## 五、核心 takeaway

1. **todo 不是执行引擎**，是模型给自己管的草稿板——记"要做啥、做到哪了"，主要给自己看。
2. **极简构造**：content（祈使态）+ activeForm（进行态）+ status（三态），全表替换更新，任何时刻恰好一个"进行中"。
3. **prompt 定纪律**：3 步以上才值得记、完成立即标不要攒、测试没过绝不标完成。
4. **"验证助推"是个精妙的软提醒**：在最后一个任务关闭（最容易忘验证）的时刻，轻推"要不要验证"——不硬拦，让模型判断。
5. **目标驱动看 /goal 不看 plan**：CC 没有 plan/DAG 引擎；要"自主干到完成"用轻量的 `/goal`（完成条件 + 独立小模型验收）。
