# CC 怎么执行命令（Bash）

> **一句话定位**：执行 shell 命令看着简单，CC 的 Bash 工具却写了一千多行。重头不在"把命令跑起来"，而在**长命令不能卡死对话、命令输出别撑爆上下文、危险命令要拦、还要把模型往专用工具上引**。

---

## 零、参数与输出（Schema）

**输入参数**：

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `command` | string | ✅ | 要执行的 shell 命令，走 `bash -c` 运行 |
| `timeout` | number(ms) | 可选 | 超时限制，单位毫秒；超时不杀进程，转后台继续运行（见后台执行机制） |
| `description` | string | 可选 | 主动语态的一句话描述（如 "List files in src/"），给终端 UI 显示用，**不影响命令执行**，不是给模型看的 |
| `run_in_background` | boolean | 可选 | 设为 true 则立即返回 task_id，命令在后台异步运行；设为 false（默认）则同步等待结束 |

> **description 参数的工程设计**：这个参数要求「主动语态、5-10 词、不用"复杂"/"风险"等模糊词、给出类似 `ls → "List files in directory"` 的格式示例」。它的目的是让终端能显示有意义的操作摘要，同时它本身就是在训练模型写出清晰描述——描述的质量直接影响用户体验。

> **隐藏的内部字段**：Schema 里还有一个 `_simulatedSedEdit` 字段，**永远不出现在模型可见的参数表里**，纯内部用途。一旦暴露，模型可以用它把任意内容直接写盘、绕过所有权限检查——这是一条安全边界，靠「从模型视角的 schema 里彻底删掉」来保证。

**输出字段**（模型看到的工具结果）：

| 字段 | 含义 |
|---|---|
| `stdout` | 命令标准输出（stderr 已合并进来） |
| `stderr` | 额外错误或 shell 重置提示 |
| `interrupted` | 是否被用户中断 |
| `backgroundTaskId` | 后台任务 ID（run_in_background 时返回） |
| `returnCodeInterpretation` | 对非零退出码的语义解释（如 grep 无匹配 exit 1 不是错） |
| `noOutputExpected` | 是否是「成功但无输出」的命令（如 mv/cp） |
| `persistedOutputPath` | 超大输出落盘后的文件路径（模型可用 read_file 读） |

---



| 操心的事 | 为什么 | 怎么做 |
|---|---|---|
| **① 长命令别卡死对话** | build/测试/下载要跑几分钟，同步等会把整个对话冻住 | 后台执行——立即返回、跑完再通知 |
| **② 输出别撑爆上下文** | 命令输出可能极大，还会逐轮重发 | 保尾截断 + 超大输出落盘 |
| **③ 退出码要会读** | 非 0 不一定是错（有些命令拿退出码表状态） | 语义解释退出码 |
| **④ 危险命令要拦** | 命令能改文件、删东西、联网 | 拆解命令 + 权限规则 + 沙箱 |
| **⑤ 把模型往专用工具引** | 用 `cat`/`grep`/`sed` 跑命令，不如用专门的读/搜/改工具 | prompt 明确"这些事别用 Bash" |

下面逐件讲。

---

## 二、① 后台执行：长命令不卡死对话（Bash 工具的灵魂）

**问题**：模型要跑一个 `npm build` 或测试套件，可能几分钟。如果同步死等，整个对话就**冻在这一条命令上**，啥也干不了。

**CC 的核心能力是把命令转入后台**——有三条路进后台：

1. **模型主动要求后台**：模型明确说"这条放后台跑"，工具**立即返回一个任务 ID**（不等结果），命令的输出**写到一个磁盘文件**里，跑完之后给对话**发一条完成通知**。
2. **超时自动转后台**：命令跑到设定的超时点还没完，CC **不杀它**，而是把它转进后台继续跑（个别命令例外，比如纯 `sleep` 就不该转后台）。
3. **助手模式下的"阻塞预算"**：在某些模式下，一条命令阻塞主对话超过约 15 秒，就自动转后台——**目的就是让主对话保持响应**，不被一条命令劫持。

CC 维护一张**后台任务表**管这些跑着的命令。还有个细节：如果一条前台命令要转后台，是**原地把它改造成后台任务**，而不是重新起一个——重起会造成重复通知、清理逻辑泄漏等一堆乱子。

> **记住这句话**：后台执行**不是为了快，是为了"主对话不被一条命令劫持"**。这是它的设计动机，CC 的注释说得很直白。

---

## 三、② 输出处理：保尾截断 + 超大落盘

命令输出也会进对话、逐轮重发，所以同样要管体积。但这里有个**和读文件相反的细节**：

- **读文件是"保头"**——文件的结构、开头往往最重要。
- **命令输出是"保尾"**——命令的**报错信息、退出码、最终结论几乎都在输出的最后**。所以截断时 CC **保留尾部、砍掉头部**。

> 这是一个很值得记的原则：**截断方向要跟着"信息密度在哪一头"走**，不是无脑砍尾巴。读文件砍尾、命令输出砍头，因为各自的"精华"在不同的一头。

**超大输出怎么办**：如果输出大到离谱，CC 把它**落到一个磁盘文件**，然后给模型一个"预览 + 文件路径 + 还有更多"的包装——模型想看全的，自己用读文件工具去读那个文件。这和读文件"太大就抛错让你精确取"、搜索"超限就分页"是**完全同一套 token 经济学**：别让一大坨东西卡进昂贵的上下文反复重发。

---

## 四、③ 退出码语义：非 0 不一定是错

直觉上"退出码非 0 = 命令失败"。但现实里**很多命令拿退出码表达状态而非错误**——最典型的，搜索类命令"没找到匹配"也会返回非 0，但那根本不是错。

所以 CC 不傻乎乎地"非 0 就当报错"，而是**对命令的退出码做语义解释**：判断这个非 0 到底是真失败、还是这条命令的正常状态表达。只有判定为真错误时，才在结果里追加"退出码 N"的提示。

---

## 五、④ 安全：拆命令 + 权限规则 + 沙箱

这是 Bash 工具最重的一块，因为命令能改文件、删东西、联网，权限必须把得严。几层：

**拆解复合命令再匹配权限**：像 `ls && git push` 这种用 `&&` 串起来的复合命令，CC 会**把它解析成一个个子命令**，**每个子命令都拿去匹配权限规则**。为什么必须拆？因为如果只看整条命令，`ls && git push` 可能就绕过了"`git push` 需要批准"这条规则——把危险命令藏在一串无害命令后面。拆开后，只要**任何一个**子命令命中需批准的规则，就触发批准。

**沙箱**：默认情况下命令在**沙箱里跑**，限制它能碰的目录和网络。模型可以请求"这条不走沙箱"，但这需要额外的权限确认。prompt 里还教模型：怎么从报错信息里识别"这是沙箱限制导致的失败"，从而决定要不要请求跳出沙箱。

**只读命令才允许并发**：CC 会判断一条命令是否为"只读"——只读命令（不改任何东西）可以和别的命令并行跑；会改东西的命令必须串行，避免互相踩。

**把"原地改文件的命令"识别成文件编辑**：像 `sed -i`（直接改文件内容）这种命令，CC **不真的去跑 sed**，而是把它识别成"一次文件编辑"，走专门的文件编辑路径处理（这样能享受撤销支持、新鲜度台账等一整套文件操作的保护）。

**拦截裸睡眠**：模型有时会想用 `sleep N` 来"等一下"，但裸睡眠是浪费——CC 会拦截这种长睡眠，引导模型改用"后台执行 + 完成通知"或专门的监控工具，而不是干等。

**一个安全边界的精妙处**：工具有一些**纯内部字段，永远不会出现在模型能看到的参数表里**。因为一旦暴露给模型，模型就可能用它把一条无害命令"拼装"成绕过权限和沙箱的危险操作。**不该让模型看见的，就根本不放进它的工具描述里**——这是一条干净的安全边界。

---

## 六、⑤ prompt：把模型往专用工具引

CC 的 Bash 工具 prompt 花了大力气**劝模型别拿 Bash 干那些有专门工具的事**：

- 找文件用专门的 Glob 工具，**别用 `find`/`ls`**。
- 搜内容用专门的 Grep 工具，**别用命令行 `grep`/`rg`**。
- 读文件用专门的读文件工具，**别用 `cat`/`head`/`tail`**。
- 改文件用专门的编辑工具，**别用 `sed`/`awk`**。
- 写文件用专门的写文件工具。
- **想跟用户说话，就直接输出文本，别用 `echo`/`printf`**。

为什么这么执着？因为专用工具有 Bash 给不了的东西：权限审批看得清、token 经济学（分页/去重/落盘）、新鲜度台账……拿 Bash 绕过这些，等于把前面所有精心设计都丢了。

其他 prompt 纪律：多条独立命令可以并行发多个 Bash 调用、有依赖的用 `&&` 串成一条；一整套 git 安全协议（不擅自改配置、不擅自跑破坏性命令、不跳过 hook 等）；少用 `cd`、多用绝对路径保持工作目录稳定。

---

## 七、核心 takeaway

1. **后台执行是灵魂，动机是"主对话不被一条命令劫持"**——不是为了快。
2. **截断方向跟着信息密度走**：读文件保头、命令输出保尾，因为精华在不同的一头。
3. **超大输出落盘 + 预览**，和读文件、搜索是同一套 token 经济学。
4. **复合命令必须拆开逐个匹配权限**，否则危险命令能藏在无害命令后面绕过。
5. **不该给模型看的字段就别放进工具描述**——这是最干净的一条安全边界。
6. **prompt 把模型从 Bash 往专用工具引**，因为专用工具有 Bash 给不了的权限可见性和 token 经济学。
